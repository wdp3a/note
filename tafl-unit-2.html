Q1 State recursive definition of regular expression and construct regular expression corresponding to a transition diagram. 7 Marks ▼
1. Definition of Regular Expression
Definition

A Regular Expression (RE) is a compact pattern that describes a Regular Language. Think of it like a recipe — you start with single symbols and combine them using three operations (union, concatenation, Kleene star) to describe all strings you want to match.

2. Recursive (Inductive) Definition

Build REs from scratch. Start with atoms (base cases), then combine them (inductive cases). Each RE describes a language — the set of strings it matches.

Base Cases — The Atoms
  • ø — the empty language: matches nothing at all. No string passes.
  • ε — matches only the empty string "". L(ε) = {ε}
  • a (any symbol in Σ) — matches just that one character. L(a) = {a}
Inductive Cases — Combining Rules

If r and s are already valid REs, you can form new ones:

  • (r + s) — Union: r OR s. Example: a+b matches "a" or "b".
  • (r · s) or (rs) — Concatenation: r then s. Example: ab matches only "ab".
  • (r*) — Kleene Star: 0 or more copies of r. Example: a* matches "", "a", "aa", "aaa"…
  • (r+) — Positive Closure: 1 or more copies of r. Same as r·r*.
  • (r) — Grouping only — doesn't change the language.
3. Operator Precedence

Just like BODMAS for arithmetic — operators have an order. Memorize: Star → Concat → Union (highest to lowest).

PriorityOperatorSymbolExample
1 (Highest)Kleene Star*ab* = a followed by zero-or-more b's
2Concatenation·ab+c = (ab) OR c
3 (Lowest)Union+a+bc = a OR (bc)
4. Constructing RE from Transition Diagram

We use the State Elimination Method: write one equation per state, then solve the system step by step. The start state's equation includes ε. The accepting state's solution is our final RE.

Fig 1.1 — Example DFA: q₀ = start, q₂ = accept state
5. State Elimination Method — Step by Step

The idea: write each state as an equation using incoming transitions. Then solve from the last state backward to get the RE. Self-loops are handled by Arden's Theorem: R = Q + R·P → R = Q·P*

  • 1Identify: States = {q₀, q₁, q₂}, Start = q₀, Accept = {q₂}, Σ = {0,1}
  • 2Write equations (each state = where it can come from):
    q₀ = 1·q₀ + 0·q₁   (start: self-loop on 1, goes to q₁ on 0)
    q₁ = 0·q₁ + 1·q₂   (self-loop on 0, goes to q₂ on 1)
    q₂ = (0+1)·q₂ + ε   (accept state: self-loop on anything, or stop here)
  • 3Solve q₂ — has self-loop (0+1): apply Arden → q₂ = (0+1)*
  • 4Substitute q₂ → q₁: q₁ = 0·q₁ + 1·(0+1)* → apply Arden → q₁ = 0*·1·(0+1)*
  • 5Substitute q₁ → q₀: q₀ = 1·q₀ + 0·(0*·1·(0+1)*) → apply Arden → q₀ = 1*·0·0*·1·(0+1)*
RE = 1*·0·0*·1·(0+1)* = 1*00*1(0+1)*
What does this RE mean?

RE = 1*00*1(0+1)*
Read it left to right: any number of 1s → then at least one 0 → then at least one 1 → then anything. In plain English: strings that have the pattern "01" somewhere, with optional 1s at the start and anything at the end.

Key Takeaway: Every FA has a corresponding RE, and every RE has a corresponding FA — they describe the same class of languages. Use State Elimination + Arden's Theorem to go from FA → RE systematically.

1. Three Methods to Convert FA → RE
  • State Elimination — Remove states one by one; fold their paths into edge labels. Best for small DFAs.
  • Arden's Theorem — Write one equation per state, solve algebraically. Works for any size.
  • Kleene's Algorithm — Table-based, computes all path expressions bottom-up. Systematic but tedious.

3. Arden's Theorem — The Core Tool
Arden's Theorem

If you have an equation of the form R = Q + R·P (where P doesn't contain ε), the solution is: R = Q·P*

Intuition: R keeps expanding as R·P, so it's really Q, followed by any number of P's — which is exactly Q·P*.

Write one equation per state. Each equation says: "how do I reach this state?" Include ε for the start state. Then solve from last to first.

-- Transition equations based on incoming transitions -- q₀ = ε + q₀·b + q₁·b -- start state (ε) + self-loop on b + from q₁ on b q₁ = q₀·a + q₂·b -- from q₀ on a, from q₂ on b q₂ = q₁·a + q₂·(a+b) -- from q₁ on a + self-loop on a,b
  • 1Solve q₂ first (has a self-loop):
    q₂ = q₁·a + q₂·(a+b)
    → Apply Arden (P = a+b, Q = q₁·a): q₂ = q₁·a·(a+b)*
  • 2Substitute q₂ into q₁:
    q₁ = q₀·a + [q₁·a·(a+b)*]·b = q₀·a + q₁·[a(a+b)*b]
    → Apply Arden: q₁ = q₀·a·[a(a+b)*b]*
  • 3Substitute q₁ into q₀:
    q₀ = ε + q₀·b + q₀·a·[a(a+b)*b]*·b
    = ε + q₀·[b + a·(a(a+b)*b)*·b]
    → Apply Arden: q₀ = [b + a(a(a+b)*b)*b]*
  • 4Final RE = the accepting state (q₁):
    Plug q₀ into q₁: RE = [b + a(a(a+b)*b)*b]* · a · [a(a+b)*b]*
RE = (b + a(a(a+b)*b)*b)* · a · (a(a+b)*b)*

Remember the steps: (1) Write equations for every state. (2) Include ε in the start state's equation. (3) Solve from the deepest state backward. (4) Wherever you see R = X + R·Y, replace with R = X·Y*. (5) The accepting state's final expression is your answer.

Q3 State Pumping Lemma for regular sets and prove L = {aᵖ | p is prime} is not regular. 7 Marks ▼
1. What is a Regular Language? (Background)
Regular Language

A language L is regular if a Finite Automaton (DFA/NFA) can recognize it. Since a DFA has a fixed, finite number of states, it has no way to "count" or remember unbounded amounts of information. This limitation is what the Pumping Lemma exploits.

2. Pumping Lemma — Statement
Pumping Lemma for Regular Languages

If L is regular, then ∃ a number p ≥ 1 (called the pumping length — equal to the number of DFA states) such that any string w ∈ L with |w| ≥ p can be split into w = xyz where:

  • |y| ≥ 1 — y is non-empty (we must be pumping something)
  • |xy| ≤ p — the pump part y is within the first p characters
  • ∀ i ≥ 0: xy^i z ∈ L — repeating y any number of times stays in L
3. How to Use It — Proof Template

The Pumping Lemma gives a necessary condition for regularity. If it fails for even ONE choice of i, the language is NOT regular. Use contradiction:

  • 1Assume L is regular → pumping length p exists
  • 2Choose a clever string w ∈ L with |w| ≥ p (pick one that will break)
  • 3Consider all splits w = xyz with |xy| ≤ p and |y| ≥ 1
  • 4Find i such that xy^i z ∉ L (this is your contradiction)
  • 5Conclude: Our assumption was wrong → L is NOT regular □
4. Proof: L = {aᵖ | p is prime} is NOT Regular
Given L = {aᵖ | p is prime} = {a², a³, a⁵, a⁷, a¹¹, ...} — only strings whose length is a prime number.
Assume Suppose L is regular. Then Pumping Lemma gives us some pumping length p.
Choose w Pick a prime q ≥ p + 2 (always possible). Take w = aᵍ ∈ L. Since q ≥ p, the lemma applies.
Split Lemma gives w = xyz where:
x = aˢ,   y = aᵏ (k ≥ 1),   z = aᵍ⁻ˢ⁻ᵏ   with s + k ≤ p
Pump with i = q+1 xy^(q+1)z has length = s + k(q+1) + (q−s−k) = q + qk = q(1+k)

Since q ≥ 2 and k ≥ 1, both factors are ≥ 2. So q(1+k) is composite (not prime).
∴ xy^(q+1)z ∉ L
Contradiction The lemma says xy^i z ∈ L for ALL i ≥ 0. But we just showed i = q+1 breaks this. ✗
Conclude ∴ L = {aᵖ | p is prime} is NOT regular. □
Concrete Example (memorize this!)

Let p = 5. Pick q = 7 (prime ≥ 5+2). So w = a⁷ ∈ L.
Split: x = aa, y = aaa (k=3), z = aa → w = a²·a³·a² = a⁷ ✓

Pump i = q+1 = 8: length = 7×(1+3) = 7×4 = 28. But 28 = 4×7 is composite ✗
So a²⁸ ∉ L. Contradiction!

Why can't a DFA check primality? A DFA has a fixed number of states — it must loop for long strings. That loop lets us repeat (pump) part of the string, which multiplies the length. Multiplied lengths are composite, not prime. So no DFA can ever correctly say "yes" only to prime lengths.

Q4 Discuss closure properties of regular languages. 7 Marks ▼
1. What Is a Closure Property?
Closure Property

A class is closed under an operation if applying that operation always stays within the class. For regular languages: if you combine two regular languages using union, concatenation, etc., the result is always still regular. Think of it like integers under addition — add two integers, get an integer.

2. Summary Table — All Closure Properties
OperationNotationClosed?Proof Method
UnionL₁ ∪ L₂✓ YesNFA construction / RE: r₁+r₂
ConcatenationL₁ · L₂✓ YesNFA ε-transition / RE: r₁r₂
Kleene StarL*✓ YesNFA ε-loop / RE: r*
ComplementL̄ = Σ* − L✓ YesSwap accept/non-accept in DFA
IntersectionL₁ ∩ L₂✓ YesProduct construction / De Morgan
DifferenceL₁ − L₂✓ YesL₁ ∩ L̄₂
ReversalL^R✓ YesReverse all transitions in DFA
Homomorphismh(L)✓ YesApply h to each symbol in RE
Inverse Homomorphismh⁻¹(L)✓ YesDFA construction with h-labeling
3. Proof: Closure under Union

Given DFAs M₁ and M₂ for L₁ and L₂, build a product DFA that runs both simultaneously:

Product Construction for Union

New DFA M has states Q₁×Q₂ (pairs of states, one from each DFA).
δ((p,q), a) = (δ₁(p,a), δ₂(q,a)) — transition both DFAs together
F = {(p,q) | p ∈ F₁ OR q ∈ F₂} — accept if either DFA would accept

Plain English: "Run both machines at once. Accept if at least one accepts."

4. Proof: Closure under Complement
  • 1Take DFA M for L. Make it complete — every (state, symbol) must have a transition. Add a dead/trap state if needed.
  • 2Swap accepting and non-accepting states: M' = (Q, Σ, δ, q₀, Q−F)
  • 3Now M' accepts exactly the strings M would reject — that's L̄.
  • 4M' is a valid DFA → L̄ is regular. □
  • 5Warning: You MUST use a complete DFA first. If δ is partial, swapping gives wrong results.
Fig 4.1 — Complement Construction: Swap accepting and non-accepting states
5. Proof: Closure under Intersection
De Morgan's Approach

L₁ ∩ L₂ = (L̄₁ ∪ L̄₂)̄
Since regular languages are closed under complement and union, and intersection = complement of union of complements, regular languages are also closed under intersection.

6. Reversal

Given DFA M for L, build M^R (the reversed machine) by:

  • Flip all arrows (reverse every transition)
  • The old start state becomes the new accept state
  • Add a new start state with ε-transitions to all old accept states
  • Convert to DFA if needed → L^R is regular

Quick Summary: Regular languages are closed under everything useful — all Boolean operations (union, intersection, complement, difference) and all string operations (concatenation, Kleene star, reversal, homomorphism). This is what makes them so powerful and practical.

Q5 Prove that the language L = {aⁿbⁿ | n ≥ 1} is not regular. 7 Marks ▼
1. Understanding the Language
Language

L = {aⁿbⁿ | n ≥ 1} = {ab, aabb, aaabbb, aaaabbbb, ...}
Every string has equal numbers of a's and b's, all a's before all b's. To accept this, you'd need to count a's and check against b's — but a DFA has no counter. This hints it's not regular.

2. Recall: Pumping Lemma
Pumping Lemma

If L is regular, ∃ p ≥ 1 s.t. every w ∈ L with |w| ≥ p can be written as w = xyz with:
(i) |y| ≥ 1, (ii) |xy| ≤ p, (iii) ∀ i ≥ 0: xy^i z ∈ L

3. Proof by Contradiction
Assume Suppose L = {aⁿbⁿ} is regular. Let p be the pumping length.
Choose w Pick w = aᵖbᵖ ∈ L. Length = 2p ≥ p. ✓
Split Write w = xyz with |xy| ≤ p and |y| ≥ 1.

Since |xy| ≤ p and the first p characters are ALL a's:
x = aˢ, y = aᵏ (k ≥ 1), z = aᵖ⁻ˢ⁻ᵏ bᵖ
Key Insight y is made entirely of a's (it lies within the first p characters). So pumping y just adds more a's — the b's stay fixed at p.
Pump i=2 xy²z = aˢ·aᵏ·aᵏ·aᵖ⁻ˢ⁻ᵏ·bᵖ = aᵖ⁺ᵏ bᵖ
We have (p+k) a's but only p b's. Since k ≥ 1, counts are unequal → xy²z ∉ L
Contradiction Pumping Lemma requires xy^i z ∈ L for all i. But i=2 breaks it. ✗
Conclude ∴ L = {aⁿbⁿ} is NOT regular. □
Fig 5.1 — The split w = xyz: since |xy| ≤ p, y consists ONLY of a's

Why intuitively? L = {aⁿbⁿ} requires a machine to remember how many a's it saw and match them with b's. That's counting — which needs unbounded memory. A DFA has finite memory (fixed states), so it can never do this. L is Context-Free, not Regular.

Q6 Explain Pumping Lemma and applications of pumping lemma for regular languages. 7 Marks ▼
1. The Intuition — Why Does Pumping Happen?

A DFA with n states processes strings like a loop. If you feed it a string of length ≥ n, by the Pigeonhole Principle, some state must repeat. The part of the string that caused that repeated visit (y) can be looped any number of times — the machine will still accept, because it just keeps going around the same loop.

Fig 6.1 — Pumping Lemma Intuition: y is the portion causing a cycle
2. Formal Statement of Pumping Lemma
Pumping Lemma (Formal)

Let L be a regular language. Then ∃ p ≥ 1 (the pumping length) such that ∀ w ∈ L with |w| ≥ p, ∃ strings x, y, z with w = xyz satisfying:
(1) |y| ≥ 1    (2) |xy| ≤ p    (3) ∀ i ≥ 0: xy^i z ∈ L

3. Classic Applications — Languages NOT Regular
  • L = {aⁿbⁿ} — equal a's and b's. Requires counting.
  • L = {aⁿ | n is prime} — primality can't be tracked by finite states.
  • L = {ww | w ∈ Σ*} — string repeated twice. Requires remembering the whole first half.
  • L = {a^(2ⁿ)} — exponential growth. No finite loop can simulate doubling.
  • L = {aⁿbᵐ | n > m} — comparing two counts requires memory.
4. Application Example: L = {ww | w ∈ {a,b}*}
AssumeL is regular with pumping length p
Choose ww = aᵖbaᵖb ∈ L — it's of the form ss where s = aᵖb
SplitSince |xy| ≤ p, y = aᵏ for some k ≥ 1 (y lies in the first p a's of the first half)
Pump i=2xy²z = aᵖ⁺ᵏ·b·aᵖ·b — first half is longer than second half → NOT of the form ww
ConcludeContradiction! ∴ L = {ww} is NOT regular □
5. Important Rules When Applying Pumping Lemma
  • It's a necessary condition only. Passing the lemma doesn't prove regularity — it just doesn't disprove it.
  • p is unknown — assume it exists and derive a contradiction. Your argument must work for ANY valid p.
  • Your string w must be in L and have length ≥ p.
  • The contradiction must hold for ALL possible splits xyz (not just one convenient split).
  • For an if-and-only-if test, use the Myhill-Nerode Theorem instead.

One-line summary: The Pumping Lemma says "if your language is regular, long strings must have a pumpable middle section." If you can find even one string that breaks this, the language isn't regular. It works because DFAs must loop for long inputs — and loops can be repeated.

Q7 Prove complement, homomorphism, inverse homomorphism, and closure of regular language are regular. 7 Marks ▼
1. Complement of a Regular Language
Complement

If L is regular over Σ, then L̄ = Σ* − L (all strings NOT in L) is also regular. In other words: "flip what's accepted."

Proof: Complement
  • 1Let L be accepted by DFA M = (Q, Σ, δ, q₀, F). Assume M is complete (δ is total — defined for every (state, symbol) pair)
  • 2Construct DFA M' = (Q, Σ, δ, q₀, Q − F)
  • 3For any w ∈ Σ*: w ∈ L(M') ⟺ δ*(q₀,w) ∈ Q−F ⟺ δ*(q₀,w) ∉ F ⟺ w ∉ L
  • 4∴ L(M') = L̄, and M' is a DFA → L̄ is regular. □
2. Homomorphism
Homomorphism

A homomorphism h: Σ → Δ* replaces each symbol with a string. Applied character-by-character: h(abc) = h(a)·h(b)·h(c). Think of it as a simple substitution cipher — but mapping symbols to strings.

Theorem

If L is a regular language and h is a homomorphism, then h(L) = {h(w) | w ∈ L} is also regular.

Proof: Homomorphism
  • 1Take the RE r for L. Apply h to every symbol in r.
  • 2If r = a (single symbol): h(r) = h(a), a fixed string — still a valid RE.
  • 3If r = r₁+r₂: h(r) = h(r₁) + h(r₂) — union is preserved.
  • 4If r = r₁r₂: h(r) = h(r₁)·h(r₂) — concatenation is preserved.
  • 5If r = r₁*: h(r) = h(r₁)* — star is preserved.
  • 6Result h(r) is a valid RE → h(L) is regular. □
Example

Let Σ = {0,1}, L = (0+1)*, h(0) = ab, h(1) = ba
Then h(L) = (ab + ba)* — still regular!

3. Inverse Homomorphism
Inverse Homomorphism

h⁻¹(L) = {w ∈ Σ* | h(w) ∈ L} — the set of strings that, after applying h, land in L. Think of it as "pre-image under h." If L is regular and h is a homomorphism, then h⁻¹(L) is also regular.

Proof: Inverse Homomorphism
  • 1Let M = (Q, Δ, δ, q₀, F) be the DFA for L over Δ.
  • 2Build new DFA M' over Σ: when reading symbol a ∈ Σ, simulate M reading h(a).
  • 3Formally: δ'(q, a) = δ*(q, h(a)) — run M on the substituted string h(a).
  • 4w ∈ L(M') iff h(w) ∈ L iff w ∈ h⁻¹(L). So M' accepts exactly h⁻¹(L).
  • 5M' is a valid DFA → h⁻¹(L) is regular. □
4. Kleene Closure (L*)

If L is regular, then L* is regular.

Proof: Kleene Closure
  • 1Start with NFA N for L. Add a new start state q_new.
  • 2Add ε-transition: q_new → q₀ (to enter the original machine).
  • 3Add ε-transitions from every accepting state back to q₀ (allow another repetition).
  • 4Make q_new accepting (to accept ε — zero repetitions).
  • 5New NFA N' accepts exactly L* → L* is regular. □
Fig 7.1 — NFA for L*: ε-back-loop from accepting states to start state

All four preserve regularity: Complement (swap states), Homomorphism (substitute symbols in RE), Inverse Homomorphism (simulate substitution in DFA), Kleene Closure (add ε back-loop). Together with union and concatenation, regular languages are closed under virtually everything you can do to them.

Q8 Explain closure properties and decision properties of regular languages. 7 Marks ▼
1. Closure Properties (Quick Reference)

2. Decision Properties — What Can Be Checked Automatically?
Decision Property

A decision property is a yes/no question about a language that can always be answered by an algorithm. For regular languages, all the important questions are decidable — there's always an algorithm to answer them. (This is NOT true for more complex language classes.)

ProblemQuestionAlgorithmComplexity
MembershipIs w ∈ L?Simulate DFA on wO(|w|)
EmptinessIs L = ∅?Is any accept state reachable from start?O(|Q|²)

3. Emptiness Test — Algorithm
  • 1Given DFA M, do a BFS/DFS from the start state q₀.
  • 2If you reach any accepting state: L ≠ ∅ (not empty).
  • 3If no accepting state is reachable: L = ∅ (empty — DFA accepts nothing).
4. Equivalence Test — Algorithm
  • 1Minimize both DFAs → M₁_min and M₂_min.
  • 2Check if M₁_min and M₂_min are isomorphic (identical structure, up to renaming states).
  • 3Alternatively: check if the symmetric difference L₁ △ L₂ = (L₁−L₂) ∪ (L₂−L₁) is empty.
Why Regular Languages Are Special

For context-free languages: equivalence and universality are undecidable — no algorithm can always answer them.
For Turing machines / RE languages: even membership (the Halting Problem) is undecidable.
Regular languages are the gold standard — every interesting property is decidable efficiently.

Practical value: Closure properties let you combine regular languages and stay regular. Decision properties let you verify, compare, and test languages algorithmically. Together, they make regular languages the backbone of lexical analysis, search tools, and protocol verification.

Q9 Compute regular expression using Arden's Theorem for the given DFA. 7 Marks ▼
1. Arden's Theorem — Statement
Arden's Theorem

If P and Q are regular expressions, and ε ∉ L(P), then:
R = Q + R·P has the unique solution: R = Q·P*

Memory trick: It's like solving a linear equation. "R appears on both sides? Factor it out: R(1−P) = Q, so R = Q·P*." (P* = the 'inverse' of the self-loop.)

2. Verification (Why It Works)
Check Substitute R = QP* into R = Q + RP:
RHS = Q + QP*·P = Q(ε + P*·P) = Q·P* = R = LHS ✓
(Because ε + P*·P = P* by definition of Kleene star)
3. How to Apply — Step-by-Step Method
  • 1For each state qᵢ, write Rᵢ = sum of (all Rⱼ·symbol for each incoming edge from state j on that symbol).
  • 2Add ε to the start state's equation (the machine starts there for free).
  • 3Solve the "deepest" state first (the one with no outgoing edges, or last in flow).
  • 4Whenever you see Rᵢ = X + Rᵢ·Y, replace with Rᵢ = X·Y*.
  • 5Substitute backward until you get the accepting state's expression = your RE.
4. Example: 3-State DFA
Fig 9.1 — DFA for Arden's Theorem application. Accept state: q₂
5. Setting Up Equations
-- Arden's equations: each Rᵢ = sum of (source · symbol) for incoming edges R₀ = ε + R₀·1 + R₂·1 -- start (ε), self on 1, back from q₂ on 1 R₁ = R₀·0 + R₁·0 -- from q₀ on 0, self on 0 R₂ = R₁·1 -- from q₁ on 1
  • 1Solve R₁ (has self-loop on 0):
    R₁ = R₀·0 + R₁·0 → Apply Arden: R₁ = R₀·0·0* = R₀·0⁺
  • 2Get R₂: R₂ = R₁·1 = R₀·0⁺·1
  • 3Substitute R₂ → R₀:
    R₀ = ε + R₀·1 + (R₀·0⁺·1)·1 = ε + R₀·(1 + 0⁺11)
    Apply Arden: R₀ = (1 + 0⁺11)*
  • 4Final RE = R₂ (accepting state):
    R₂ = R₀·0⁺·1 = (1 + 0⁺11)*·0⁺·1
RE = (1 + 0+11)* · 0+ · 1

Arden's Theorem in one sentence: Write one equation per state, solve from last to first, and whenever a state equation has itself on the right side (a self-loop), apply R = Q + R·P → R = Q·P* to eliminate it. The accepting state's final expression is your RE.

Q10 Determine FA accepted by regular expression: (0+1)*0(0+1)*00(0+1)* 7 Marks ▼
1. Breaking Down the Regular Expression
Given RE

RE = (0+1)*0(0+1)*00(0+1)*

Read it in plain English: "any string, then a 0, then any string, then two consecutive 0s, then any string."
In short: strings containing at least one 0 followed (eventually) by "00". The minimum is "000" — just three zeros together.

2. Strategy: Thompson's Construction (RE → NFA)

Thompson's Construction builds an NFA piece by piece from the RE's structure. Each sub-expression gets its own mini-NFA, and they're connected with ε-transitions.

3. NFA States — What Each Means
  • 1q₀ (start): NFA for (0+1)* — self-loop on 0 and 1. Stays here while reading any prefix.
  • 2q₀ → q₁ on 0: Guesses "this 0 is the first required 0." Non-deterministically moves to q₁.
  • 3q₁ → q₂ on 0 or 1: Middle (0+1)* section — reads anything between the first 0 and the "00".
  • 4q₂ → q₃ on 0: Sees the first 0 of the "00" pair.
  • 5q₃ → q₄ on 0: Sees the second 0 of the pair. Now we've confirmed the pattern.

5. What Language Does This Accept?

Strings over {0,1} that contain at least 3 zeros, with the last two being consecutive (the "00" part). The simplest accepted string is "000". One's before, between, or after the zeros are fine.

Quick Test

Accepted: 000 ✓ | 0001 ✓ | 1000 ✓ | 10001 ✓ | 01100 ✓
Rejected: 01 ✗ | 001 ✗ | 11 ✗ | 010 ✗ | 0110 ✗
(Need a separate 0 AND then a "00" — that's at least 3 zeros total)

Key idea: When converting RE → NFA using Thompson's Construction, build mini-NFAs for each piece of the RE, then join them with ε-transitions in order. The NFA's non-determinism lets it "guess" where the pattern begins.

1. Three Methods — Pick Your Tool
  • State Elimination — Physically remove states and fold edge labels. Visual and intuitive for small DFAs.
  • Arden's Theorem — Write and solve equations. Most systematic; works for any DFA.
  • Kleene's Algorithm — Table-based path computation. Thorough but tedious.
2. Example 1: Simple 2-State DFA (over {a})
Fig 11.1 — DFA: q₀ = start AND accept, q₁ = non-accepting

Setting up equations (q₀ is both start and accept):

q₀ = ε + q₀·a + q₁·a -- start here (ε), self-loop on a, reach here from q₁ on a q₁ = q₀·a -- only way to reach q₁ is from q₀ on a
  • 1Substitute q₁ into q₀: q₀ = ε + q₀·a + (q₀·a)·a = ε + q₀·(a + aa)
  • 2Apply Arden: q₀ = (a + aa)* — which simplifies to (aa)* since the machine alternates between q₀ and q₁.
RE₁ = (aa)*    [strings with even number of a's]
3. Example 2: DFA for strings ending in 01
Fig 11.2 — DFA for strings ending in 01

Setting up equations (C is the accepting state — strings ending in 01):

A = ε + A·1 + B·0 + C·0 + C·1 B = A·0 C = B·1
  • 1From B: B = A·0 (reach B only from A on 0)
  • 2From C: C = B·1 = A·0·1 = A·01
  • 3Substitute B and C into A: A = ε + A·1 + A·0·0 + A·01·0 + A·01·1 = ε + A·(1+00+010+011)
  • 4Apply Arden: A = (1 + 00 + 010 + 011)*
  • 5RE = C = A·01 = (1 + 00 + 010 + 011)* · 01
RE₂ = (1 + 00 + 010 + 011)* · 01

Pattern to remember: Write equations bottom-up (C first, then B, then A). Each equation = "how do I get here?" Substitute backwards. Self-loops → apply Arden's R = Q + R·P → R = Q·P*. The accepting state's final expression is your RE.

Q12 State pumping lemma for regular language and prove L = {aⁿ | n is prime} is not regular. 7 Marks ▼
1. Pumping Lemma — Restatement
Pumping Lemma

If L is regular, then ∃ p ≥ 1 (pumping length, determined by number of states in the DFA for L) such that ∀ w ∈ L with |w| ≥ p, ∃ x,y,z with w = xyz satisfying:
(1) |y| ≥ 1,  (2) |xy| ≤ p,  (3) ∀ i ≥ 0: xy^i z ∈ L

The pumping length p equals the number of states in the minimal DFA for L.

2. Language: L = {aⁿ | n is prime}
Language

L = {aa, aaa, aaaaa, aaaaaaa, ...} = {a², a³, a⁵, a⁷, a¹¹, ...}
The length of every string in L must be a prime number.

3. Proof: L is NOT Regular
Step 1 Assume L is regular. Let p be the pumping length.
Step 2 Choose string w: Let q be the smallest prime ≥ p + 2. (Such a prime always exists by Bertrand's Postulate). Take w = aᵍ ∈ L with |w| = q ≥ p.
Step 3 Split: By Pumping Lemma, w = xyz where:
• y = aᵏ for some k with 1 ≤ k ≤ p (since |xy| ≤ p and only a's exist)
• x = aˢ (some s ≥ 0, s + k ≤ p)
• z = aᵍ⁻ˢ⁻ᵏ
Step 4 Pump with i = q + 1:
xy^(q+1)z = aˢ⁺ᵏ⁽ᵍ⁺¹⁾⁺ᵍ⁻ˢ⁻ᵏ = aᵍ⁺ᵍᵏ = aᵍ⁽¹⁺ᵏ⁾

The length is q(1+k). Since q ≥ 2 and k ≥ 1:
• q ≥ 2 (prime) and (1+k) ≥ 2
• ∴ q(1+k) is a product of two integers each ≥ 2 → q(1+k) is COMPOSITE
Step 5 Contradiction: xy^(q+1)z has composite length → xy^(q+1)z ∉ L.
But Pumping Lemma requires xy^i z ∈ L for ALL i ≥ 0. Contradiction!
Step 6 Conclusion: ∴ L = {aⁿ | n is prime} is NOT a regular language. □
4. Numerical Verification
Example with p = 5

Choose q = 7 (prime, ≥ 5+2=7). w = a⁷ ∈ L
Suppose k = 2 (any valid split). Then pump i = 8:
Length = 7 + (8−1)×2 = 7 + 14 = 21 = 3 × 7 (composite, not prime)
∴ a²¹ ∉ L. Contradiction!

Or use i = q+1 = 8: length = 7×(1+2) = 21 — composite ✓

5. Key Insight
  • Primality testing cannot be done with finite memory
  • A finite automaton has a fixed number of states p; for strings longer than p, it must loop — and this looping changes the length by a regular (non-prime) amount
  • No DFA can track whether a count is prime because prime distribution is irregular

Conclusion: Languages whose membership depends on arithmetic properties of string length (like primality) are generally not regular. The pumping lemma provides the formal tool to prove this rigorously.

Q13 Discuss closure properties including union, concatenation, complement, intersection, and difference. 7 Marks ▼
1. Introduction
Closure Property

The class of regular languages is closed under an operation O if, for any regular language(s) L (and L₁, L₂), the result O(L) (or O(L₁,L₂)) is also regular. We prove each operation preserves regularity.

2. Closure under Union
Theorem

If L₁ and L₂ are regular languages, then L₁ ∪ L₂ is also regular.

Proof (using Regular Expressions):

  • 1Let r₁ and r₂ be RE for L₁ and L₂ respectively
  • 2Then r₁ + r₂ is a RE for L₁ ∪ L₂ (union is a RE operator)
  • 3∴ L₁ ∪ L₂ is regular □

Proof (using NFA): Create new start state with ε-transitions to start states of NFA₁ and NFA₂.

Fig 13.1 — NFA for Union: new start state with ε-transitions to both NFAs
3. Closure under Concatenation
Theorem

If L₁ and L₂ are regular, then L₁·L₂ = {xy | x ∈ L₁, y ∈ L₂} is regular.

  • 1Let r₁ and r₂ be RE for L₁ and L₂. Then r₁·r₂ is a RE for L₁·L₂
  • 2NFA construction: Add ε-transitions from every accepting state of NFA₁ to the start state of NFA₂
  • 3New accepting states = accepting states of NFA₂ only
  • 4∴ L₁·L₂ is accepted by this NFA → it is regular □
4. Closure under Complement
Theorem

If L is regular, then L̄ = Σ* − L is regular.

Construction: Start with a complete DFA M for L. Swap final and non-final states to get DFA M' for L̄.

Important: Complete DFA Required

The DFA must be complete (every (state,symbol) pair has a defined transition, possibly to a dead/trap state). Incomplete DFAs give wrong results when swapping accepting states.

5. Closure under Intersection
Theorem

If L₁ and L₂ are regular, then L₁ ∩ L₂ is regular.

Method 1 — De Morgan's Law:

L₁ ∩ L₂ = (L̄₁ ∪ L̄₂)̄

Since regular languages are closed under complement and union, they are also closed under intersection.

Method 2 — Product (Cross-Product) Construction:

  • 1Given DFAs M₁ = (Q₁,Σ,δ₁,s₁,F₁) and M₂ = (Q₂,Σ,δ₂,s₂,F₂)
  • 2Construct product DFA M = (Q₁×Q₂, Σ, δ, (s₁,s₂), F₁×F₂)
  • 3δ((q₁,q₂), a) = (δ₁(q₁,a), δ₂(q₂,a)) — run both DFAs simultaneously
  • 4For intersection: F = F₁ × F₂ = {(q₁,q₂) | q₁ ∈ F₁ AND q₂ ∈ F₂}
  • 5This DFA accepts w iff BOTH M₁ and M₂ accept w → L(M) = L₁ ∩ L₂ □
6. Closure under Difference
Theorem

If L₁ and L₂ are regular, then L₁ − L₂ = L₁ ∩ L̄₂ is regular.

  • 1Compute L̄₂ (complement of L₂) — regular (closure under complement)
  • 2Compute L₁ ∩ L̄₂ — regular (closure under intersection)
  • 3∴ L₁ − L₂ is regular □

These properties make regular languages an algebraically rich and computationally tractable class, fundamental to compiler design (lexical analysis) and formal verification.
