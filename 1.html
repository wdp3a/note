2MQ1(a) — Describe JVM and Byte Code in Java Architecture.

JVM — Java Virtual Machine

JVM is an abstract computing machine that provides a runtime environment to execute Java byte code. It is platform-specific (different JVM binaries for Windows, Linux, macOS) but makes Java programs platform-independent. Responsibilities: class loading → byte code verification → interpretation / JIT compilation → garbage collection.

Byte Code

Byte code is the intermediate, platform-neutral code generated by the Java compiler (javac) from .java source files, stored in .class files. It is NOT native machine code; the JVM converts it to native instructions at runtime.

.java ──javac──► .class (Byte Code) ──JVM──► Machine Code (Source) (Platform Neutral) (Platform Specific)
💡 Concept Booster
Byte code is a universal recipe. The Java compiler writes the recipe once; each platform's JVM "cooks" it according to local kitchen rules — hence "Write Once, Run Anywhere."
2MQ1(b) — Define the concept of Classes and Objects in Java with a suitable example.

Class

A class is a blueprint/template that defines attributes (fields) and behaviour (methods) for its objects. It is a logical entity with no memory allocated until an object is created.

Object

An object is a real-world instance of a class, created using the new keyword. Each object has its own state (field values) and identity.

class Car {
    String brand;   // field
    int speed;
    void display() {
        System.out.println(brand + " at " + speed + " km/h");
    }
}
public class Main {
    public static void main(String[] args) {
        Car c = new Car();   // object
        c.brand = "Toyota"; c.speed = 120;
        c.display();         // Toyota at 120 km/h
    }
}
💡 Concept Booster
A class is like an architectural blueprint; objects are the actual houses built from it. Many houses (objects) can be built from one blueprint (class), each with its own colour and size.
2MQ1(c) — Explain Interfaces in Java with suitable example.

Interface

An interface is a 100% abstract type (before Java 8) that defines a contract — what a class must do, not how. It contains abstract methods (and from Java 8, default and static methods). A class implements an interface. Java supports multiple interface implementation.

interface Drawable {
    void draw();   // abstract method
}
class Circle implements Drawable {
    public void draw() { System.out.println("Drawing Circle"); }
}
public class Main {
    public static void main(String[] args) {
        Drawable d = new Circle();
        d.draw();   // Drawing Circle
    }
}
💡 Concept Booster
An interface is like a job description: it specifies requirements without detailing how to do the job. Any class that "implements" it promises to fulfil those capabilities.

2MQ1(e) — Describe various states achieved by the thread in its life cycle.

A Java thread passes through 5 states:

  1. New — Thread object created; start() not yet called.
  2. Runnable — start() called; eligible for CPU scheduling.
  3. Running — Scheduler picks it; run() is executing.
  4. Blocked / Waiting / Timed-Waiting — Thread paused due to sleep(), wait(), I/O, or lock wait.
  5. Terminated (Dead) — run() has completed normally or due to exception.
New ──start()──► Runnable ◄──────────────────────────┐ │ │ (CPU schedules) (re-scheduled) │ │ Running ──(sleep/wait/lock/I-O)──► Blocked/Waiting │ (run() completes) ▼ Terminated
💡 Concept Booster
Thread life cycle is like an employee: Hired (New) → Ready at desk (Runnable) → Working (Running) → On break (Blocked) → Retired (Terminated).

2MQ1(g) — Explain the concept of Sealed Classes in Java with suitable example.

Sealed Classes (Java 17+)

A sealed class restricts which other classes can extend or implement it, using the sealed keyword and a permits clause. Permitted subclasses must be declared final, sealed, or non-sealed.

sealed class Shape permits Circle, Rectangle, Triangle { }

final class Circle    extends Shape { double radius; }
final class Rectangle extends Shape { double length, width; }
final class Triangle  extends Shape { double base, height; }
// Any class NOT listed in permits → COMPILE ERROR if it tries to extend Shape
💡 Concept Booster
Sealed classes are a VIP club with a strict guest list. Only classes named in permits may join — no uninvited subclasses. Useful for fixed domain hierarchies (shapes, result types, AST nodes).

7MQ2(a) — Explain Abstraction and Abstract Classes in Java. Describe abstract method. Demonstrate with a suitable example.

1. Abstraction

Abstraction is an OOP principle that hides implementation details and exposes only the essential features. It reduces complexity and increases reusability. In Java achieved via Abstract Classes (partial abstraction) and Interfaces (full abstraction).

2. Abstract Class

Declared with the abstract keyword. Cannot be instantiated directly. May have abstract methods (no body) and concrete methods (with body). Can have constructors, static methods, fields.

3. Abstract Method

A method with no body. Subclasses must override it. Syntax: abstract returnType methodName();

4. Abstract Class vs Interface

FeatureAbstract ClassInterface
InstantiationNoNo
MethodsAbstract + ConcreteAbstract (+ default/static Java 8+)
ConstructorYesNo
Multiple inheritanceNo (single extends)Yes (multiple implements)
FieldsAny typeOnly public static final

5. Example

abstract class Animal {
    String name;
    Animal(String name) { this.name = name; }   // constructor allowed

    abstract void sound();       // abstract — no body, must override

    void breathe() {             // concrete method
        System.out.println(name + " breathes oxygen.");
    }
}

class Dog extends Animal {
    Dog(String n) { super(n); }
    @Override
    void sound() { System.out.println(name + " says: Woof!"); }
}

class Cat extends Animal {
    Cat(String n) { super(n); }
    @Override
    void sound() { System.out.println(name + " says: Meow!"); }
}

public class Main {
    public static void main(String[] args) {
        Animal a1 = new Dog("Rex");
        Animal a2 = new Cat("Whiskers");
        a1.sound();    // Rex says: Woof!
        a2.sound();    // Whiskers says: Meow!
        a1.breathe();  // Rex breathes oxygen.
    }
}

6. Key Rules

  • A class with even one abstract method must be declared abstract.
  • Subclass must implement ALL abstract methods, else it too must be abstract.
  • Abstract classes can have constructors, static, and final methods.
💡 Concept Booster
An abstract class is a generic job role: "Vehicle" says every vehicle must move(), but doesn't specify how a Car vs Boat moves. Each subclass fills in the actual logic, while sharing common functionality (e.g., fuelUp()).
7MQ2(b) — Describe the ways to create threads in Java. Also explain which method is more suitable.

Method 1: Extending Thread Class

Create a class extending java.lang.Thread and override run().

class MyThread extends Thread {
    public void run() {
        System.out.println("Thread: " + Thread.currentThread().getName());
    }
}
public class Main {
    public static void main(String[] args) {
        MyThread t1 = new MyThread();
        MyThread t2 = new MyThread();
        t1.start();  t2.start();
    }
}

Method 2: Implementing Runnable Interface ✅ (Preferred)

Implement java.lang.Runnable and pass instance to Thread constructor.

class MyRunnable implements Runnable {
    public void run() {
        System.out.println("Runnable: " + Thread.currentThread().getName());
    }
}
public class Main {
    public static void main(String[] args) {
        Thread t1 = new Thread(new MyRunnable());
        Thread t2 = new Thread(new MyRunnable());
        t1.start();  t2.start();
    }
}

Method 3: Lambda Expression (Java 8+)

public class Main {
    public static void main(String[] args) {
        Thread t = new Thread(() ->
            System.out.println("Lambda thread: " + Thread.currentThread().getName())
        );
        t.start();
    }
}

Method 4: Callable + ExecutorService (returns result)

import java.util.concurrent.*;
public class Main {
    public static void main(String[] args) throws Exception {
        Callable<String> task = () -> "Result from Callable thread";
        ExecutorService es = Executors.newSingleThreadExecutor();
        Future<String> f = es.submit(task);
        System.out.println(f.get());  // Result from Callable thread
        es.shutdown();
    }
}

Implementing Runnable is preferred because Java doesn't support multiple class inheritance — extending Thread blocks further inheritance. Also separates the task from the thread management.

Runnable is the task description; Thread is the worker. You can hand the same task to different workers. When you extend Thread, worker and task are one inseparable entity — inflexible and tightly coupled.
7MQ2(c) — Explain Functional Interfaces in Java. Describe Lambda Expressions with the help of Functional Interfaces.

1. Functional Interface

An interface with exactly one abstract method. Annotated with @FunctionalInterface (optional but recommended). Java 8 introduced them to enable lambda expressions.

Built-in examples: Runnable, Comparable, and from java.util.function: Predicate<T>, Function<T,R>, Consumer<T>, Supplier<T>.

2. Lambda Expression

A concise way to represent an anonymous function (implementation of a functional interface).

Syntax: (parameters) -> { body }

3. Custom Functional Interface + Lambda

@FunctionalInterface
interface MathOperation {
    int operate(int a, int b);  // single abstract method
}
public class Main {
    public static void main(String[] args) {
        MathOperation add      = (a, b) -> a + b;
        MathOperation multiply = (a, b) -> a * b;
        System.out.println("Add:      " + add.operate(5, 3));       // 8
        System.out.println("Multiply: " + multiply.operate(5, 3));  // 15
    }
}

4. Built-in Functional Interfaces

import java.util.function.*;
public class Demo {
    public static void main(String[] args) {
        Predicate<Integer> isEven  = n -> n % 2 == 0;
        Function<String,Integer> len = s -> s.length();
        Consumer<String> greet     = s -> System.out.println("Hello, " + s);
        Supplier<Double> rand      = () -> Math.random();

        System.out.println(isEven.test(4));    // true
        System.out.println(len.apply("Java")); // 4
        greet.accept("World");                 // Hello, World
        System.out.println(rand.get());        // random number
    }
}

5. Anonymous Class vs Lambda

ApproachCode
Anonymous classnew Runnable() { public void run() { ... } }
Lambda() -> { ... }
💡 Concept Booster
Lambda is syntactic sugar for implementing a functional interface. Instead of a verbose anonymous class, you write a clean one-liner. Tell Java: "Here is exactly what to do — skip the class boilerplate."
7MQ2(d) — Describe Collections Framework in Java with hierarchy diagram. Explain List, Set and Queue interfaces.

1. Collections Framework

The Java Collections Framework (JCF) provides a unified architecture for storing, retrieving, and manipulating groups of objects. Located in java.util.

2. Hierarchy Diagram

Iterable (Interface) │ Collection (Interface) ┌───────────┼────────────┐ List Set Queue │ │ │ ┌──────┴──┐ ┌─────┴────┐ LinkedList ArrayList LinkedList HashSet TreeSet PriorityQueue Vector Stack LinkedHashSet (SortedSet) Stack ─ ─ ─ ─ Map (separate — does NOT extend Collection) ─ ─ ─ ─ HashMap TreeMap LinkedHashMap Hashtable

3. List Interface

Ordered collection that allows duplicates. Elements accessed by index.

  • ArrayList — Dynamic array; fast random access O(1); slow mid-insert O(n).
  • LinkedList — Doubly linked; fast insert/delete O(1); slow access O(n).
  • Vector — Thread-safe ArrayList (legacy).
List<String> list = new ArrayList<>();
list.add("A"); list.add("B"); list.add("A");
System.out.println(list);  // [A, B, A]  ← duplicates allowed, ordered

4. Set Interface

Collection that does NOT allow duplicates. No guaranteed order (except sorted/linked variants).

  • HashSet — No order; O(1) avg operations.
  • LinkedHashSet — Insertion order maintained.
  • TreeSet — Sorted natural order; O(log n).
Set<Integer> set = new HashSet<>();
set.add(3); set.add(1); set.add(2); set.add(1);  // 2nd 1 ignored
System.out.println(set);  // [1, 2, 3]

5. Queue Interface

Follows FIFO (First In, First Out). Used for task scheduling.

  • LinkedList — General-purpose Queue.
  • PriorityQueue — Dequeued by natural / custom priority.
Queue<String> q = new LinkedList<>();
q.offer("First"); q.offer("Second"); q.offer("Third");
System.out.println(q.poll()); // First  ← FIFO
💡 Concept Booster
List = notebook (ordered, allows repeats). Set = passport stamps (no duplicates). Queue = bank counter line (FIFO). Pick the right structure based on your data's access needs!
7MQ2(e) — Explain the difference between Dependency Injection (DI) and Inversion of Control (IoC) in Spring.

1. Inversion of Control (IoC)

IoC is a design principle where control of object creation and lifecycle is transferred from the programmer to a framework (Spring container). Instead of your code creating objects, the framework creates and manages them.

Traditional: UserService s = new UserService(); — programmer controls creation.
IoC: Spring creates UserService; you just declare it.

2. Dependency Injection (DI)

DI is the implementation mechanism of IoC. Spring automatically injects required dependencies into a bean, rather than the bean creating them.

3. Types of DI

TypeHowAnnotation
Constructor InjectionVia constructor parameter@Autowired on constructor
Setter InjectionVia setter method@Autowired on setter
Field InjectionDirectly into field@Autowired on field

4. Code Example

// Tightly coupled (WITHOUT DI)
class OrderService {
    PaymentService ps = new PaymentService(); // hardcoded dependency
}

// Loosely coupled (WITH Spring DI — Constructor Injection)
@Component
class PaymentService {
    public void pay() { System.out.println("Payment processed"); }
}

@Component
class OrderService {
    private final PaymentService paymentService;

    @Autowired    // Spring injects PaymentService automatically
    public OrderService(PaymentService paymentService) {
        this.paymentService = paymentService;
    }
    public void placeOrder() { paymentService.pay(); }
}

5. Key Differences

IoC = "Don't call us, we'll call you" — the framework runs the show. DI = how it does it: when your class needs a service, Spring delivers it automatically — like pizza delivery vs driving to the store yourself.

7MQ3(a) — Illustrate Polymorphism and its types. Differentiate run-time vs compile-time polymorphism. Demonstrate method overriding with Shape and Rectangle.

1. Polymorphism

Polymorphism (Greek: "many forms") allows a single interface or method name to behave differently based on the object or arguments. It is a fundamental OOP pillar.

2. Types

A) Compile-Time Polymorphism (Static / Method Overloading)

Resolved at compile time. Same method name, different parameter list.

class Calculator {
    int add(int a, int b)          { return a + b; }
    double add(double a, double b) { return a + b; }
    int add(int a, int b, int c)   { return a + b + c; }
}

B) Run-Time Polymorphism (Dynamic / Method Overriding)

Resolved at runtime via dynamic method dispatch. Parent reference holds child object; overridden child method is called.

3. Comparison

FeatureCompile-TimeRun-Time
Also calledStatic / OverloadingDynamic / Overriding
Resolved atCompile timeRuntime
Achieved byMethod overloadingMethod overriding
Inheritance neededNoYes
PerformanceFasterSlightly slower (dispatch)

4. Example — Shape, Rectangle, Method Overriding

class Shape {
    void displayArea() {
        System.out.println("Shape: area not defined.");
    }
}

class Rectangle extends Shape {
    double length, width;
    Rectangle(double l, double w) { length = l; width = w; }

    @Override
    void displayArea() {
        System.out.println("Rectangle Area = " + (length * width));
    }
}

class Circle extends Shape {
    double radius;
    Circle(double r) { radius = r; }

    @Override
    void displayArea() {
        System.out.printf("Circle Area = %.2f%n", Math.PI * radius * radius);
    }
}

public class Main {
    public static void main(String[] args) {
        Shape s;

        s = new Rectangle(5, 3);
        s.displayArea();   // Rectangle Area = 15.0   ← runtime dispatch

        s = new Circle(4);
        s.displayArea();   // Circle Area = 50.27
    }
}
💡 Concept Booster
Run-time polymorphism is like a universal remote — the same button (method call) operates a TV, AC, or fan (different objects) differently at runtime. The JVM decides which "channel" to tune to based on the actual object type.

public class ExceptionDemo {

7MQ5(a) — Explain Java Stream API. Describe Intermediate and Terminal operations. Write program to print sum of even numbers from ArrayList of 1–10.

1. Java Stream API (Java 8+)

A Stream is a sequence of elements from a source (collection, array) supporting functional-style aggregate operations. Streams are lazy (nothing executes until a terminal op is called), don't store data, and can be parallelised.

2. Stream Pipeline

Source (Collection / Array / I-O) │ [Intermediate Operations] — lazy, return Stream, 0 or more filter(), map(), sorted(), distinct(), limit(), flatMap()… │ [Terminal Operation] — eager, triggers pipeline, exactly 1 collect(), forEach(), reduce(), count(), sum(), min(), max()…

3. Intermediate Operations

OperationDescription
filter(Predicate)Select elements matching condition
map(Function)Transform each element
sorted()Sort elements
distinct()Remove duplicates
limit(n)Truncate to first n elements

4. Terminal Operations

OperationDescription
collect()Collect into List, Set, Map, etc.
forEach()Perform action on each element
reduce()Aggregate to single value
count()Number of elements
sum() / min() / max()Numeric summaries

5. Program — Sum of Even Numbers from 1 to 10

import java.util.ArrayList;
import java.util.stream.IntStream;

public class StreamDemo {
    public static void main(String[] args) {
        // Create ArrayList with 1 to 10
        ArrayList<Integer> numbers = new ArrayList<>();
        IntStream.rangeClosed(1, 10).forEach(numbers::add);

        // Stream pipeline: filter evens → sum
        int sumOfEvens = numbers.stream()
                .filter(n -> n % 2 == 0)       // Intermediate
                .mapToInt(Integer::intValue)    // Intermediate
                .sum();                          // Terminal

        System.out.println("Sum of even numbers (1-10) = " + sumOfEvens);
        // Output: Sum of even numbers (1-10) = 30  (2+4+6+8+10)

        System.out.print("Even numbers: ");
        numbers.stream()
               .filter(n -> n % 2 == 0)
               .forEach(n -> System.out.print(n + " "));
        // Output: Even numbers: 2 4 6 8 10
    }
}
💡 Concept Booster
Stream pipeline is a factory assembly line: raw parts (data) enter, pass through processing stations (intermediate ops), and the finished product rolls out at the end (terminal op). The line only starts when the last station is ready — that's lazy evaluation!
7MQ5(b) — Compare and contrast switch-case statement with switch-expression in Java. Explain with suitable examples.

1. Traditional switch-case Statement

Available since Java 1.0. Uses case, break, and default labels. Problems: fall-through behaviour, verbose syntax, cannot be used as an expression.

int day = 3;
String name;
switch (day) {
    case 1: name = "Monday";    break;
    case 2: name = "Tuesday";   break;
    case 3: name = "Wednesday"; break;
    case 4: name = "Thursday";  break;
    case 5: name = "Friday";    break;
    default: name = "Weekend";  break;
}
System.out.println(name); // Wednesday

// Fall-through example (classic bug):
switch (day) {
    case 1:
    case 2: System.out.println("Early week"); break; // fall-through from 1 to 2
    default: break;
}

2. Switch Expression (Java 14+ Standard)

Uses arrow syntax (->). Is an expression (has a return value). No fall-through. Compiler enforces exhaustiveness for expressions. Multiple labels per case supported.

int day = 3;
String name = switch (day) {    // switch is now an expression
    case 1 -> "Monday";
    case 2 -> "Tuesday";
    case 3 -> "Wednesday";
    case 4 -> "Thursday";
    case 5 -> "Friday";
    default -> "Weekend";
};
System.out.println(name);  // Wednesday

Switch Expression with yield (multi-line case block)

int score = 85;
String grade = switch (score / 10) {
    case 10, 9 -> "A+";    // multiple labels
    case 8 -> {
        System.out.println("Good performance!");
        yield "A";           // yield returns value from block
    }
    case 7 -> "B";
    case 6 -> "C";
    default -> "F";
};
System.out.println("Grade: " + grade); // Grade: A

💡 Concept Booster
Old switch is a long IF-ELSE chain with booby traps (fall-through). New switch expression is a clean lookup table — ask a question, get a direct guaranteed answer. Safer, more readable, and can be assigned to a variable.

7MQ6(a) — Describe LinkedList in Java. Describe any five methods with example.

1. LinkedList

LinkedList in java.util implements both List and Deque interfaces. Internally uses a doubly-linked list — each node holds data and references to both the next and previous nodes.

null ← [prev|"Apple"|next] ↔ [prev|"Banana"|next] ↔ [prev|"Cherry"|next] → null (head) (tail)

Strengths: O(1) insertion/deletion at head/tail.
Weakness: O(n) random access (no index-based jump).

2. Five Methods with Example

import java.util.LinkedList;

public class LLDemo {
    public static void main(String[] args) {
        LinkedList<String> list = new LinkedList<>();

        // 1. add(E e) — appends element to end of list
        list.add("Banana");
        list.add("Cherry");
        list.add("Elderberry");
        System.out.println("After add():      " + list);
        // [Banana, Cherry, Elderberry]

        // 2. addFirst(E e) — inserts element at the beginning
        list.addFirst("Apple");
        System.out.println("After addFirst(): " + list);
        // [Apple, Banana, Cherry, Elderberry]

        // 3. addLast(E e) — appends element at the end
        list.addLast("Fig");
        System.out.println("After addLast():  " + list);
        // [Apple, Banana, Cherry, Elderberry, Fig]

        // 4. remove(int index) — removes element at given index
        list.remove(2);   // removes "Cherry" (index 2)
        System.out.println("After remove(2):  " + list);
        // [Apple, Banana, Elderberry, Fig]

        // 5. get(int index) — returns element at specified index
        String elem = list.get(1);
        System.out.println("get(1): " + elem);   // Banana

        // Extra useful methods:
        System.out.println("size(): " + list.size());            // 4
        System.out.println("contains(Apple): " + list.contains("Apple")); // true
        System.out.println("peek(): " + list.peek());            // Apple (head, no remove)
        System.out.println("poll(): " + list.poll());            // Apple (removes head)
        System.out.println("After poll(): " + list);            // [Banana, Elderberry, Fig]
    }
}

3. Method Summary

MethodDescriptionTime
add(e)Append to tailO(1)
addFirst(e)Insert at headO(1)
addLast(e)Insert at tailO(1)
remove(index)Remove by positionO(n)
get(index)Retrieve by positionO(n)
💡 Concept Booster
LinkedList is like a chain of train compartments — attaching or removing a compartment at either end is quick. But finding the 50th seat means walking through all previous compartments. Use it when insertions/deletions outweigh lookups.
7MQ6(b) — Describe HashMap in Java. Describe any five methods with example.

1. HashMap

HashMap (java.util) stores data as key-value pairs. Uses hashing to compute bucket index for O(1) average-case operations. Allows one null key and multiple null values. Does not maintain insertion order. Not thread-safe.

Key → hashCode() → bucket index → Bucket Array ┌───┬─────────────────────────────────────────┐ │ 0 │ null │ │ 1 │ ("Alice" → 90) │ │ 2 │ ("Bob" → 85) → ("Eve" → 78) ← collision│ │ 3 │ ("Charlie" → 92) │ └───┴─────────────────────────────────────────┘

2. Five Methods with Example

import java.util.HashMap;
import java.util.Map;

public class HMDemo {
    public static void main(String[] args) {
        HashMap<String, Integer> scores = new HashMap<>();

        // 1. put(K, V) — inserts OR updates a key-value mapping
        scores.put("Alice", 90);
        scores.put("Bob",   85);
        scores.put("Charlie", 92);
        scores.put("Alice", 95);   // updates Alice's score (duplicate key)
        System.out.println("After put: " + scores);

        // 2. get(K) — returns value for key, or null if absent
        int aliceScore = scores.get("Alice");
        System.out.println("Alice score: " + aliceScore);  // 95

        // 3. containsKey(K) — checks if key exists
        System.out.println("Has Bob: " + scores.containsKey("Bob"));  // true
        System.out.println("Has Eve: " + scores.containsKey("Eve"));  // false

        // 4. remove(K) — removes the mapping for the given key
        scores.remove("Bob");
        System.out.println("After remove Bob: " + scores);

        // 5. entrySet() — iterate all key-value pairs
        System.out.println("\nAll entries:");
        for (Map.Entry<String, Integer> e : scores.entrySet()) {
            System.out.println("  " + e.getKey() + " → " + e.getValue());
        }

        // Extra:
        System.out.println("size(): " + scores.size());
        System.out.println("getOrDefault: " + scores.getOrDefault("Dave", 0));
    }
}

3. Method Summary

MethodDescriptionTime
put(k,v)Insert or update key-value pairO(1) avg
get(k)Retrieve value by keyO(1) avg
containsKey(k)Check if key existsO(1) avg
remove(k)Delete entry by keyO(1) avg
entrySet()Iterate all key-value pairsO(n)
💡 Concept Booster
HashMap is like a dictionary — look up a word (key) and instantly get its definition (value). Hashing lets Java jump directly to the right "page" instead of reading from page 1 every time — O(1) magic!

The Spring Container is the core of the Spring Framework. It creates objects (beans), injects dependencies, configures them, and manages their complete lifecycle — all based on configuration metadata (XML, annotations, or Java config).

Part 2 — Spring Bean Life Cycle

A Spring bean goes through the following lifecycle stages managed by the container:

1. Instantiation → Container creates bean via constructor 2. Populate Properties → Dependencies injected (DI) 3. BeanNameAware → setBeanName(id) called 4. BeanFactoryAware → setBeanFactory() called 5. ApplicationContextAware→ setApplicationContext() called 6. BeanPostProcessor → postProcessBeforeInitialization() 7. @PostConstruct → custom init method 8. InitializingBean → afterPropertiesSet() 9. BeanPostProcessor → postProcessAfterInitialization() ─────────── Bean is READY and in use ─────────── 10. @PreDestroy → custom cleanup method 11. DisposableBean → destroy()
@Component
public class MyBean implements InitializingBean, DisposableBean {

    @PostConstruct
    public void init() {
        System.out.println("@PostConstruct — initialising resources");
    }

    @Override
    public void afterPropertiesSet() {
        System.out.println("afterPropertiesSet() — post-init logic");
    }

    @PreDestroy
    public void cleanup() {
        System.out.println("@PreDestroy — releasing resources");
    }

    @Override
    public void destroy() {
        System.out.println("destroy() — final cleanup");
    }
}
💡 Concept Booster
Spring container is a smart factory manager — it hires workers (beans), equips them with tools (DI), trains them (init), puts them to work, and ensures they clean their workspace before leaving (destroy). You write the job description; Spring runs the entire HR department.

Spring Boot is an opinionated, convention-over-configuration extension of the Spring Framework that simplifies creating stand-alone, production-ready Spring applications with minimal setup.

Part 2 — RESTful API with Spring Boot

REST (Representational State Transfer) is an architectural style for web services using HTTP methods (GET, POST, PUT, DELETE) to perform CRUD on resources. Spring Boot provides @RestController to build REST APIs easily.

HTTP Method Mapping

HTTP MethodAnnotationCRUD Operation
GET@GetMappingRead / Retrieve
POST@PostMappingCreate
PUT@PutMappingUpdate
DELETE@DeleteMappingDelete
import org.springframework.web.bind.annotation.*;
import java.util.*;

@RestController                    // @Controller + @ResponseBody
@RequestMapping("/api/students")
public class StudentController {

    private Map<Integer, String> db = new HashMap<>();

    // GET all students
    @GetMapping
    public Map<Integer, String> getAll() { return db; }

    // GET student by ID
    @GetMapping("/{id}")
    public String getById(@PathVariable int id) {
        return db.getOrDefault(id, "Student not found");
    }

    // POST — create student
    @PostMapping
    public String add(@RequestParam int id, @RequestParam String name) {
        db.put(id, name);
        return "Student added: " + name;
    }

    // PUT — update student
    @PutMapping("/{id}")
    public String update(@PathVariable int id, @RequestParam String name) {
        db.put(id, name);
        return "Updated student " + id + " to " + name;
    }

    // DELETE — remove student
    @DeleteMapping("/{id}")
    public String delete(@PathVariable int id) {
        db.remove(id);
        return "Deleted student " + id;
    }
}

// POST   http://localhost:8080/api/students?id=1&name=Aarav
// PUT    http://localhost:8080/api/students/1?name=Sharma
// DELETE http://localhost:8080/api/students/1

Spring Boot is a fully-furnished apartment — Spring gives you the land and bricks; Boot moves you in with furniture already set up. REST API is the intercom system — clients request specific actions (GET/POST/DELETE) and you respond over a standard HTTP/JSON channel.
