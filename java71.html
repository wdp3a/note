Discuss different data types and control structures in Java with examples.
7 Marks
Definition

Data types define the type and size of data a variable can hold. Java is a statically typed language — every variable must be declared with a type before use.

Control structures govern the flow of execution in a program: sequential, conditional, and iterative.

Control Structures

Java provides three categories of control structures:

Java Code Example 
// Data Types & Control Structures Demo
public class DataTypesDemo {
    public static void main(String[] args) {

        // ── Primitive Data Types ──
        int     rollNo  = 101;
        double  cgpa    = 8.75;
        char    grade   = 'A';
        boolean passed  = true;
        long    regNo   = 2300520100123L;

        System.out.println("Roll: " + rollNo + " CGPA: " + cgpa);

        // ── if-else (Selection) ──
        if (cgpa >= 9.0) {
            System.out.println("Distinction");
        } else if (cgpa >= 7.5) {
            System.out.println("First Class");
        } else {
            System.out.println("Pass");
        }

        // ── switch (Selection) ──
        switch (grade) {
            case 'A': System.out.println("Excellent"); break;
            case 'B': System.out.println("Good");      break;
            default: System.out.println("Average");
        }

        // ── for loop (Iteration) ──
        System.out.print("Squares: ");
        for (int i = 1; i <= 5; i++) {
            System.out.print(i * i + " ");
        }
        System.out.println();

        // ── while loop ──
        int n = 5, fact = 1;
        while (n > 0) { fact *= n--; }
        System.out.println("5! = " + fact);

        // ── do-while loop ──
        int x = 0;
        do {
            System.out.print(x + " ");
            x++;
        } while (x < 3);
        System.out.println();
    }
}
Output
Roll: 101 CGPA: 8.75 First Class Excellent Squares: 1 4 9 16 25 5! = 120 0 1 2
Key Points
  • Java has 8 primitive data types and several non-primitive (reference) types.
  • int is the most used numeric type; double for decimals.
  • if-else and switch control conditional branching.
  • for is used when iteration count is known; while when condition-based.
  • do-while guarantees at least one execution.
  • break exits a loop; continue skips current iteration.
02
Explain the concept of Java Virtual Machine (JVM) and Java Runtime Environment (JRE).
7 Marks
Definition

JVM (Java Virtual Machine) is an abstract computing machine that enables Java programs to run on any platform. It interprets bytecode (.class files) into machine-specific instructions.

JRE (Java Runtime Environment) = JVM + Core Libraries. It provides the minimum environment necessary to run Java applications.

JDK (Java Development Kit) = JRE + Development Tools (javac, javadoc, jar). Required for development.

Diagram – Java Execution Architecture
JVM Internal Working

1. Class Loader Subsystem: Loads, links and initializes .class files. Has three loaders: Bootstrap, Extension, Application.

2. Memory Areas:

AreaPurposeShared?
HeapStores objects and instance variablesYes (all threads)
StackMethod calls, local variables, framesNo (per thread)
Method AreaClass metadata, static variables, bytecodeYes
PC RegisterAddress of current JVM instructionNo (per thread)
Native StackNative method execution (C/C++)No (per thread)

3. Execution Engine: Contains Interpreter (executes bytecode line by line) and JIT Compiler (compiles hot code to native machine code for speed).

4. Garbage Collector: Automatically reclaims heap memory for objects no longer referenced.

Key Points
  • WORA – Write Once, Run Anywhere; JVM abstracts the underlying OS.
  • JDK ⊃ JRE ⊃ JVM (superset relationship).
  • JIT Compiler makes Java nearly as fast as compiled languages.
  • JVM is platform-dependent; bytecode is platform-independent.
  • Garbage Collection prevents memory leaks automatically.
03
Explain abstraction and encapsulation with examples.
7 Marks
Definitions

Abstraction: Hiding the implementation details and showing only the essential features to the user. Achieved via abstract classes and interfaces.

Encapsulation: Binding data (variables) and methods that operate on the data into a single unit (class), and restricting direct access using access modifiers. Also called data hiding.

Diagram
Encapsulation Example 
// Encapsulation: Data hiding with getters and setters
class BankAccount {
    private double balance;   // private field – hidden from outside
    private String owner;

    public BankAccount(String owner, double initialBalance) {
        this.owner = owner;
        this.balance = initialBalance;
    }

    // Getter
    public double getBalance() { return balance; }

    // Setter with validation
    public void deposit(double amount) {
        if (amount > 0) balance += amount;
    }

    public void withdraw(double amount) {
        if (amount <= balance) balance -= amount;
        else System.out.println("Insufficient funds!");
    }
}

// Abstraction: Abstract class hides implementation
abstract class Shape {
    abstract double area();   // abstract method – no body
    void display() {
        System.out.println("Area = " + area());
    }
}

class Circle extends Shape {
    double r;
    Circle(double r) { this.r = r; }
    @Override
    double area() { return Math.PI * r * r; }
}

public class Main {
    public static void main(String[] args) {
        // Encapsulation demo
        BankAccount acc = new BankAccount("Alice", 1000.0);
        acc.deposit(500);
        acc.withdraw(200);
        System.out.println("Balance: " + acc.getBalance());

        // Abstraction demo
        Shape s = new Circle(5);
        s.display();
    }
}
Output
Balance: 1300.0 Area = 78.53981633974483
Key Points
  • Abstraction → What to do (hide complexity, show only interface)
  • Encapsulation → How to protect data (bind + restrict access)
  • Encapsulation uses private fields + public getters/setters.
  • Abstraction uses abstract class or interface.
  • Both are pillars of OOP and promote modularity and security.
04
Explain constructors in Java with suitable examples.
7 Marks
Definition

A constructor is a special method that is automatically called when an object is created using the new keyword. It is used to initialize the object's state (instance variables).

Properties of Constructors
  • Name must be same as the class name.
  • No return type (not even void).
  • Automatically invoked on object creation with new.
  • Can be overloaded (multiple constructors with different parameters).
  • If no constructor is defined, Java provides a default constructor.
Types of Constructors
Java Code 
class Student {
    String name;
    int age;
    double cgpa;

    // 1. Default Constructor
    Student() {
        name = "Unknown";
        age  = 0;
        cgpa = 0.0;
        System.out.println("Default Constructor called");
    }

    // 2. Parameterized Constructor
    Student(String n, int a, double c) {
        this.name = n;
        this.age  = a;
        this.cgpa = c;
        System.out.println("Parameterized Constructor called");
    }

    // 3. Copy Constructor
    Student(Student s) {
        this.name = s.name;
        this.age  = s.age;
        this.cgpa = s.cgpa;
        System.out.println("Copy Constructor called");
    }

    void display() {
        System.out.println("Name:" + name + " Age:" + age + " CGPA:" + cgpa);
    }
}

public class ConstructorDemo {
    public static void main(String[] args) {
        Student s1 = new Student();                  // Default
        s1.display();

        Student s2 = new Student("Alice", 20, 8.9);  // Parameterized
        s2.display();

        Student s3 = new Student(s2);               // Copy
        s3.display();
    }
}
Output
Default Constructor called Name:Unknown Age:0 CGPA:0.0 Parameterized Constructor called Name:Alice Age:20 CGPA:8.9 Copy Constructor called Name:Alice Age:20 CGPA:8.9
Key Points
  • Constructor chaining is done using this() (same class) or super() (parent class).
  • If a parameterized constructor is defined, default constructor is NOT auto-provided.
  • Constructors cannot be static, abstract, or final.
  • this keyword refers to the current object inside a constructor.
05
Explain parameter passing in Java with examples.
7 Marks
Definition

Java uses Pass by Value exclusively. However, the behavior differs for primitive and reference types:

• For primitives: a copy of the actual value is passed → changes inside method do not affect the original.

• For objects (references): a copy of the reference (address) is passed → changes to the object's state are reflected outside, but reassigning the reference itself is not.

Diagram – Pass by Value vs Reference Type
Java Code 
public class ParameterDemo {

    // Pass by Value – primitive
    static void changeValue(int n) {
        n = 99;  // only local copy changes
        System.out.println("Inside method: n = " + n);
    }

    // Pass by Reference (object reference by value)
    static void changeArray(int[] arr) {
        arr[0] = 99;  // modifies actual heap object
        System.out.println("Inside method: arr[0] = " + arr[0]);
    }

    // Reassigning reference – no effect outside
    static void reassign(int[] arr) {
        arr = new int[]{1,2,3};  // only local ref changes
        System.out.println("Reassigned inside method");
    }

    public static void main(String[] args) {
        // Primitive test
        int x = 10;
        changeValue(x);
        System.out.println("After method: x = " + x); // still 10

        // Object test
        int[] myArr = {1, 2, 3};
        changeArray(myArr);
        System.out.println("After method: arr[0] = " + myArr[0]); // 99!

        // Reassign test
        int[] b = {10, 20};
        reassign(b);
        System.out.println("After reassign: b[0] = " + b[0]); // still 10
    }
}
Output
Inside method: n = 99 After method: x = 10 Inside method: arr[0] = 99 After method: arr[0] = 99 Reassigned inside method After reassign: b[0] = 10
Key Points
  • Java always uses Pass by Value — there is no pass by reference in Java.
  • For primitives, value is copied — original is unaffected.
  • For objects, the reference (address) is copied — object state can be modified.
  • Reassigning the reference inside a method does not affect the original reference.

Explain method overloading and method overriding with examples.
7 Marks
Definitions

Method Overloading (Compile-time Polymorphism): Multiple methods in the same class with the same name but different parameter lists (type, number, or order). Resolved at compile time.

Method Overriding (Runtime Polymorphism): A method in a subclass has the same name, return type, and parameters as a method in the parent class. Resolved at runtime.

Comparison Table
FeatureOverloadingOverriding
ClassSame classParent–Child classes
ParametersMust differMust be same
Return typeCan differMust be same (covariant allowed)
BindingCompile-time (static)Runtime (dynamic)
PolymorphismCompile-timeRuntime
@OverrideNot usedShould be used
static methodsCan be overloadedCannot be overridden
Java Code 
// ── METHOD OVERLOADING ──
class Calculator {

    int add(int a, int b) {               // 2 ints
        return a + b;
    }

    double add(double a, double b) {   // 2 doubles
        return a + b;
    }

    int add(int a, int b, int c) {     // 3 ints
        return a + b + c;
    }
}

// ── METHOD OVERRIDING ──
class Animal {
    void sound() {
        System.out.println("Animal makes a sound");
    }
}

class Dog extends Animal {
    @Override
    void sound() {                      // overrides parent method
        System.out.println("Dog barks: Woof!");
    }
}

class Cat extends Animal {
    @Override
    void sound() {
        System.out.println("Cat meows: Meow!");
    }
}

public class PolymorphismDemo {
    public static void main(String[] args) {
        // Overloading
        Calculator c = new Calculator();
        System.out.println(c.add(3, 4));         // int version
        System.out.println(c.add(3.5, 1.5));     // double version
        System.out.println(c.add(1, 2, 3));      // 3-param version

        // Overriding – runtime polymorphism
        Animal a1 = new Dog();  // upcasting
        Animal a2 = new Cat();
        a1.sound();  // Dog's sound called at runtime
        a2.sound();  // Cat's sound called at runtime
    }
}
Output
7 5.0 6 Dog barks: Woof! Cat meows: Meow!
Key Points
  • Overloading is static binding; overriding is dynamic binding.
  • @Override annotation prevents accidental errors in overriding.
  • Overriding enables runtime polymorphism (core OOP feature).
  • A method declared final or static cannot be overridden.
  • Overriding method cannot have a more restrictive access modifier than the parent.

Explain inheritance types in Java.
7 Marks
Definition

Inheritance is an OOP mechanism where a subclass (child) acquires the properties and behaviors of a superclass (parent). It promotes code reusability and establishes an IS-A relationship. Achieved using the extends keyword.

Types of Inheritance
Java Code – Multilevel & Hierarchical 
// Multilevel Inheritance
class Animal {
    void eat()   { System.out.println("Animal eats"); }
}

class Dog extends Animal {
    void bark()  { System.out.println("Dog barks"); }
}

class Puppy extends Dog {
    void weep()  { System.out.println("Puppy weeps"); }
}

// Hierarchical Inheritance
class Cat extends Animal {
    void meow()  { System.out.println("Cat meows"); }
}

public class InheritanceDemo {
    public static void main(String[] args) {
        Puppy p = new Puppy();
        p.eat();  p.bark();  p.weep();  // multilevel

        Cat c = new Cat();
        c.eat();  c.meow();              // hierarchical
    }
}
Output
Animal eats Dog barks Puppy weeps Animal eats Cat meows
Key Points
  • Java uses extends for class inheritance, implements for interfaces.
  • Multiple inheritance through classes is not supported in Java to avoid the Diamond Problem.
  • All classes implicitly extend java.lang.Object.
  • super keyword accesses parent class members and constructors.
  • Inheritance promotes code reuse and supports polymorphism.

Explain access modifiers in Java.
7 Marks
Definition

Access modifiers (or access specifiers) define the scope and visibility of classes, methods, variables, and constructors in Java. They are a key mechanism of encapsulation.

Access Levels Visualization

Java Code 
package school;

public class Teacher {
    private   String salary  = "50000";  // only within Teacher
              String empId   = "T101";    // default: school package
    protected String dept    = "CS";      // school pkg + subclasses
    public    String name    = "Alice";   // everywhere

    private void   showSalary() { System.out.println(salary); }
    public void    showInfo()   { System.out.println(name + " - " + dept); }
}

class SubTeacher extends Teacher {
    void display() {
        // salary    → ERROR (private)
        System.out.println(dept);    // OK (protected)
        System.out.println(name);    // OK (public)
    }
}

public class Main {
    public static void main(String[] args) {
        Teacher t = new Teacher();
        t.showInfo();   // public – accessible
        // t.showSalary() → ERROR (private)
    }
}
Key Points
  • private provides the highest encapsulation (most restrictive).
  • public is least restrictive — accessible from anywhere.
  • protected allows subclasses in different packages to access members.
  • default (package-private) is the visibility when no modifier is specified.
  • Top-level classes can only be public or default.
09
Explain compile-time and runtime polymorphism in Java.
7 Marks
Definition

Polymorphism means "one name, many forms." It allows a single interface to represent different underlying forms (data types or classes).

Java supports two types: Compile-time (Static) and Runtime (Dynamic) polymorphism.

Polymorphism Overview
Java Code – Both Types 
// ── 1. COMPILE-TIME POLYMORPHISM (Method Overloading) ──
class Printer {
    void print(int x) {
        System.out.println("Integer: " + x);
    }
    void print(String s) {
        System.out.println("String: " + s);
    }
    void print(double d, int n) {
        System.out.println("Double+Int: " + d + ", " + n);
    }
}

// ── 2. RUNTIME POLYMORPHISM (Method Overriding + Upcasting) ──
class Shape {
    void draw() { System.out.println("Drawing Shape"); }
}

class Circle extends Shape {
    @Override
    void draw() { System.out.println("Drawing Circle ○"); }
}

class Rectangle extends Shape {
    @Override
    void draw() { System.out.println("Drawing Rectangle □"); }
}

public class PolyDemo {
    public static void main(String[] args) {
        // Compile-time
        Printer p = new Printer();
        p.print(42);
        p.print("AKTU");
        p.print(3.14, 2);

        // Runtime – same reference, different behavior
        Shape[] shapes = {new Circle(), new Rectangle(), new Shape()};
        for (Shape s : shapes) {
            s.draw();  // resolved at runtime based on actual object type
        }
    }
}
Output
Integer: 42 String: AKTU Double+Int: 3.14, 2 Drawing Circle ○ Drawing Rectangle □ Drawing Shape
Key Points
  • Compile-time polymorphism → Method Overloading → resolved by compiler.
  • Runtime polymorphism → Method Overriding + Upcasting → resolved by JVM.
  • Dynamic Method Dispatch: when parent reference holds child object, overridden method of child is called.
  • Runtime polymorphism does NOT apply to data members (fields), only methods.

Explain abstract class and interface with examples.
7 Marks
Definitions

Abstract Class: A class declared with keyword abstract that cannot be instantiated. It may contain both abstract (no body) and concrete (with body) methods. Used for partial abstraction.

Interface: A pure abstract type declared with keyword interface. All methods are implicitly public abstract (before Java 8) and all variables are public static final. Used for 100% abstraction and multiple inheritance.

Comparison Table
FeatureAbstract ClassInterface
Keywordabstract classinterface
MethodsAbstract + ConcreteAbstract (default/static in Java 8+)
VariablesAny typepublic static final only
ConstructorsAllowedNot allowed
InheritanceSingle (extends)Multiple (implements)
AbstractionPartial (0-100%)Complete (100%)
SpeedFastSlightly slower
Java Code 
// ── ABSTRACT CLASS ──
abstract class Vehicle {
    String brand;

    Vehicle(String b) { brand = b; }

    abstract void fuelType();       // must override

    void start() {                   // concrete method
        System.out.println(brand + " starting...");
    }
}

class Car extends Vehicle {
    Car(String b) { super(b); }
    @Override
    void fuelType() { System.out.println(brand + ": Petrol"); }
}

class ElectricCar extends Vehicle {
    ElectricCar(String b) { super(b); }
    @Override
    void fuelType() { System.out.println(brand + ": Electric ⚡"); }
}

// ── INTERFACE ──
interface Printable {
    void print();                   // public abstract by default
}

interface Showable {
    void show();
}

class Document implements Printable, Showable {
    public void print() { System.out.println("Printing document..."); }
    public void show()  { System.out.println("Showing document..."); }
}

public class AbstractDemo {
    public static void main(String[] args) {
        Vehicle v1 = new Car("Toyota");
        v1.start(); v1.fuelType();

        Vehicle v2 = new ElectricCar("Tesla");
        v2.start(); v2.fuelType();

        Document doc = new Document();
        doc.print(); doc.show();
    }
}
Output
Toyota starting... Toyota: Petrol Tesla starting... Tesla: Electric ⚡ Printing document... Showing document...
Key Points
  • Abstract class cannot be instantiated with new.
  • Abstract class can have a constructor (called via super()).
  • Interface variables are public static final (constants).
  • Java 8+ allows default and static methods in interfaces.
  • A class can implement multiple interfaces but extend only one abstract class.

Explain multiple inheritance issue and its solution using interfaces.
7 Marks
The Diamond Problem

Java does NOT support multiple inheritance through classes to avoid the Diamond Problem. This occurs when a class inherits from two classes that have the same method, causing ambiguity about which method to call.

Diamond Problem Diagram
Java Code – Solution via Interface 
// Interfaces – no implementation → no ambiguity
interface Flyable {
    void fly();
}

interface Swimmable {
    void swim();
}

interface Runnable {
    void run();
}

// Duck implements MULTIPLE interfaces → multiple inheritance!
class Duck implements Flyable, Swimmable, Runnable {
    public void fly()  { System.out.println("Duck is flying 🦆"); }
    public void swim() { System.out.println("Duck is swimming 🌊"); }
    public void run()  { System.out.println("Duck is running 🏃"); }
}

// Default method conflict resolution (Java 8+)
interface A {
    default void greet() { System.out.println("Hello from A"); }
}

interface B {
    default void greet() { System.out.println("Hello from B"); }
}

class C implements A, B {
    @Override
    public void greet() {        // must override to resolve conflict
        A.super.greet();           // explicitly choose A's version
        System.out.println("Hello from C (resolved)");
    }
}

public class MultiInheritDemo {
    public static void main(String[] args) {
        Duck d = new Duck();
        d.fly(); d.swim(); d.run();

        C c = new C();
        c.greet();
    }
}
Output
Duck is flying 🦆 Duck is swimming 🌊 Duck is running 🏃 Hello from A Hello from C (resolved)
Key Points
  • Java avoids the Diamond Problem by not allowing multiple class inheritance.
  • Interfaces solve this: since they have no state or implementation (before Java 8), there's no ambiguity.
  • Java 8 introduced default methods in interfaces — if two interfaces have the same default method, the implementing class must override it.
  • A class can implement any number of interfaces.
  • Use InterfaceName.super.method() syntax to explicitly choose an interface's default method.
