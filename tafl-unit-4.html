What is Push Down Automata (PDA)? Design PDA for L = {wcwᴿ | w ∈ {a,b}*}.

Part 1: Prerequisite — Context-Free Languages

A Context-Free Language (CFL) is generated by rules of the form A → α — one non-terminal on the left, anything on the right. Think of it as: "a single variable can be replaced by any string." All regular languages are CFLs, but CFLs are more powerful — they can handle nested/matching patterns (like brackets) that finite automata cannot, because they use a stack for memory.

Part 2: What is a Pushdown Automaton (PDA)?

Formal Definition

A Pushdown Automaton (PDA) is a Finite Automaton + a stack, written as the 7-tuple M = (Q, Σ, Γ, δ, q₀, Z₀, F). The stack gives it unlimited memory for counting/matching, which lets it recognise all Context-Free Languages. Memory trick: "PDA = FA + Stack."

Components of PDA

7-Tuple Components
Q — Finite set of states
Σ — Input alphabet (e.g. {a, b})
Γ — Stack alphabet (e.g. {A, B, Z₀})
δ — Transition function: Q × (Σ ∪ {ε}) × Γ → 2^(Q × Γ*)
q₀ — Initial state
Z₀ — Initial stack symbol (bottom marker)
F — Set of accepting (final) states

How PDA Works

  • Each step: read one input symbol (or skip with ε) + look at stack top → move to new state + push/pop the stack.
  • Two ways to accept: reach a final state (F), OR empty the stack — both are equivalent.
  • PDA is non-deterministic by default — the same (state, input, stack-top) can have multiple valid moves (like choosing a path at a fork).
  • Think of it as: "Read → Check stack → Decide → Push/Pop."

Transition Notation

Notation
δ(q, a, A) = {(q', γ)}

Meaning:
  State:  q → q'
  Input:  consume 'a'
  Stack:  replace top A with string γ

Edge label format: a, A / γ
  (read a from input, pop A, push γ)

Part 3: Design PDA for L = {wcwᴿ | w ∈ {a,b}*}

Language Description

Strings of the form wcwᴿ: write any string w, then the separator c, then w backwards. The c acts as a landmark — it tells the PDA "stop pushing, start matching." Examples: c (empty w), aca, bcb, abcba, aabcbaa.

Strategy (3 phases)

  1. 01 Phase 1 — Push: Read each symbol of w (a or b) and push it onto the stack. The stack now holds w in order.
  2. 02 Phase 2 — Center: Read c. Don't push anything — just switch to match mode. This is your pivot.
  3. 03 Phase 3 — Pop/Match: Read wᴿ one symbol at a time. Each must match the stack top exactly → pop on match. Mismatch = reject.
  4. 04 Accept: Input is fully consumed AND stack has only Z₀ left → move to final state q₃. ✓

PDA M = (Q, Σ, Γ, δ, q₀, Z₀, F)
Q = {q₀, q₁, q₂, q₃}
Σ = {a, b, c}
Γ = {A, B, Z₀}
q₀ = q₀ (start state)
Z₀ = Z₀ (initial stack symbol)
F = {q₃}

Differentiate between DPDA and NPDA with suitable example. Also discuss Two Stack PDA.

1. Deterministic PDA (DPDA)

Definition — DPDA

A PDA is Deterministic if at every step, there is at most one possible move. Given any (state, input, stack-top) combination, the machine has no choice — it always takes a single fixed action. Think of it as a GPS with no alternate routes.

Formal Conditions for Determinism

  • For every (q, a, A), at most one transition exists: |δ(q, a, A)| ≤ 1.
  • No conflict between ε-move and real-input move: if δ(q, ε, A) is defined, then δ(q, a, A) must be undefined for all a ∈ Σ.
  • Result: always a single, predictable execution path. Easy to implement as actual code.

2. Non-Deterministic PDA (NPDA)

Definition — NPDA

A PDA is Non-Deterministic if at some point it can make multiple different moves for the same (state, input, stack-top). It accepts a string if any one of its possible paths leads to acceptance. Think of it as trying all doors simultaneously — if any door opens, you're in.

  • Multiple transitions allowed: |δ(q, a, A)| > 1 for some configurations.
  • Conceptually explores all paths in parallel — accept if at least one path succeeds.
  • Strictly more powerful than DPDA — can recognise languages DPDA cannot (e.g. wwᴿ without a center marker).

⚡

Key insight: A DPDA for wwᴿ is impossible without a center marker — it would need to decide deterministically when to "flip" from push to pop mode, which requires knowing the exact midpoint in advance. The NPDA's ε-guess does exactly this: it tries all possible midpoints simultaneously, and the correct one succeeds.

4. Two Stack PDA

Definition — Two Stack PDA

A Two Stack PDA has two independent stacks that can be pushed/popped separately at every step. Written as an 8-tuple M = (Q, Σ, Γ₁, Γ₂, δ, q₀, Z₀, F). Each transition looks at the state, input symbol, and the top of both stacks before deciding the next move. Think of it as two registers you can grow/shrink freely.

Significance of Two-Stack PDA

  • Equal in power to a Turing Machine — this is the crucial fact. Adding a second stack gives you unlimited, addressable memory.
  • Can recognise languages that are NOT context-free, like aⁿbⁿcⁿ.
  • How it simulates a TM: Stack-1 = left portion of the tape, Stack-2 = right portion. Moving the "head" left or right = popping from one stack and pushing onto the other.
  • Power hierarchy to memorise: 1-stack PDA = CFL < 2-stack PDA = TM = RE.

Two-Stack PDA for aⁿbⁿcⁿ

2-Stack Strategy
Language: L = {aⁿbⁿcⁿ | n ≥ 1}

Phase 1: Read a's → Push A onto Stack-1
Phase 2: Read b's → Pop A from Stack-1, Push B onto Stack-2
Phase 3: Read c's → Pop B from Stack-2
Accept: Both stacks empty (only Z₀ remains)

δ(q₀, a, Z₀, Z₀) = (q₀, AZ₀, Z₀)   push A on S1
δ(q₀, a, A, Z₀)  = (q₀, AA, Z₀)    push more A
δ(q₀, b, A, Z₀)  = (q₁, ε, BZ₀)    pop A, push B on S2
δ(q₁, b, A, B)   = (q₁, ε, BB)     continue
δ(q₁, c, Z₀, B)  = (q₂, Z₀, ε)     pop B with each c
δ(q₂, c, Z₀, B)  = (q₂, Z₀, ε)
δ(q₂, ε, Z₀, Z₀) = (q₃, Z₀, Z₀)   accept
Conclusion

Three-level power ladder: DPDA (deterministic, least flexible) → NPDA (non-deterministic, handles all CFLs) → Two-Stack PDA (= Turing Machine, handles everything computable). Each upgrade adds a strictly larger class of languages. NPDA handles the OR/palindrome cases DPDA can't; two stacks handle the counting-triple cases NPDA can't.

Construct PDA equivalent to CFG: S→aAA, A→aS|bS|a

Prerequisite: CFG to PDA Conversion

Key Theorem

Every CFG G can be converted to an equivalent PDA M with just 3 states. The PDA mimics the grammar's leftmost derivation: non-terminals on the stack get "expanded" by ε-moves, and terminals on the stack get "matched and consumed" by reading input. When the stack is empty, the input is accepted.

Standard Conversion Algorithm (Leftmost Derivation)

  1. 01Create states: q₀ (init), q₁ (work loop), q₂ (accept).
  2. 02Initialize: push start symbol S → δ(q₀, ε, Z₀) = (q₁, SZ₀).
  3. 03Expand rule: for each production A → α, add δ(q₁, ε, A) = (q₁, α) — replace the non-terminal A on the stack with its RHS (pushed in reverse order).
  4. 04Match terminal: for each terminal a, add δ(q₁, a, a) = (q₁, ε) — when stack top matches input, consume both.
  5. 05Accept: δ(q₁, ε, Z₀) = (q₂, Z₀) — stack fully drained → accept.

Design PDA for language L = {aⁱbʲcᵏ | i = j or j = k}

Understanding the Language

Language Description

L = {aⁱbʲcᵏ | i = j OR j = k} — strings of a's, then b's, then c's, where either #a's = #b's or #b's = #c's (or both). This is simply L₁ ∪ L₂ — the union of two simpler languages. The OR is the key: you only need one of the two equalities to hold.

L₁: i = j

Number of a's equals number of b's. c's can be anything. Examples: ab, aabbc, aabbccc

L₂: j = k

Number of b's equals number of c's. a's can be anything. Examples: bc, abbc, aaabbbccc

L = L₁ ∪ L₂. A non-deterministic PDA handles union naturally: it guesses at the start which branch to verify, then follows that branch deterministically.

Strategy

  • At the very start, non-deterministically split into two branches via ε-moves.
  • Branch 1 (i=j): Push one A per a. Pop one A per b. Let all c's pass freely. Accept when stack is empty after all b's.
  • Branch 2 (j=k): Ignore all a's. Push one B per b. Pop one B per c. Accept when stack is empty after all c's.

Formal PDA

PDA M = (Q, Σ, Γ, δ, q₀, Z₀, F)
Q = {q₀, q₁, q₂, q₃, q₄, q₅, q₆, q₇}
Σ = {a, b, c}
Γ = {A, B, Z₀}
F = {q₃, q₇}

Understanding Even Palindromes

Language Description

L = {WWᴿ | W ∈ {a,b}*} is the set of even-length palindromes — strings that read the same forwards and backwards, with an even number of characters. Unlike wcwᴿ, there is no center marker 'c'. So the PDA must guess where the midpoint is. Examples: ε, aa, bb, abba, aabbbbaa.

⚡

Key Insight: No DPDA can recognise wwᴿ — you can't know deterministically when the first half ends without a marker. The ε-move that "guesses" the midpoint is what makes this require non-determinism. This is the classic proof that NPDA is strictly more powerful than DPDA.

Strategy

  1. 01Phase 1 (Push): Read symbols and push each onto the stack. At any point, make a non-deterministic ε-move to "declare" the midpoint has been reached — switch to Phase 2.
  2. 02Phase 2 (Pop/Match): For each remaining input symbol, check it matches the stack top. Pop on match; reject on mismatch.
  3. 03Accept: Input is fully read AND stack has only Z₀ left → accept.

Formal PDA

Q = {q₀, q₁, q₂}
Σ = {a, b}
Γ = {A, B, Z₀}
F = {q₂}

PDA to CFG Conversion — Standard Algorithm

Key Theorem

Every PDA accepting by empty stack can be converted to a CFG. The trick is creating a non-terminal [p, A, q] for each "journey" — it represents: "Starting in state p with stack symbol A on top, I can pop A and end up in state q." Each such journey becomes a grammar rule.

Step-by-Step Algorithm

  1. 01Start Symbol: For each state q, the start of the grammar is: S → [q₀, Z₀, q] — "the PDA starts with Z₀ and can end up in any state."
  2. 02ε-pop: If the PDA pops A and moves from p to q without reading input: [p, A, q] → ε.
  3. 03Single push: If reading 'a' in state p pops A and pushes B, moving to q: add [p, A, r] → a [q, B, r] for every possible end state r.
  4. 04Multiple push: If pushing B₁B₂...Bₖ, chain the non-terminals: [p, A, rₖ] → a [q, B₁, r₁] [r₁, B₂, r₂] ... [rₖ₋₁, Bₖ, rₖ] for all combinations of intermediate states.

Worked Example

δ(q₀, a, A)  = (q₀, AA)
δ(q₀, b, A)  = (q₁, ε)
δ(q₁, b, A)  = (q₁, ε)
δ(q₁, ε, Z₀) = (q₁, ε)

Convert grammar into PDA accepting by empty stack.

Two Modes of PDA Acceptance

Acceptance by Final State

Accept when the PDA reaches a state in F after consuming all input. The stack can have anything in it — it doesn't matter. This is the more intuitive mode.

Acceptance by Empty Stack

Accept when the stack is completely empty after consuming all input. No final states are needed. This mode is natural for grammar simulations — the grammar "drains" to nothing.

📌

Equivalence Theorem: Both acceptance modes recognise exactly the same set of languages. Any PDA accepting by final state can be converted to one accepting by empty stack (and vice versa). So you can use whichever is more convenient for a given problem.

CFG → PDA (Empty Stack) Conversion

Algorithm

  1. 01Initialize: push start symbol S onto the stack via a single ε-move from q₀ to q₁.
  2. 02For each grammar rule A → α: add ε-transition δ(q₁, ε, A) = (q₁, α) — the PDA "expands" non-terminals on the stack without reading input.
  3. 03For each terminal a ∈ Σ: add δ(q₁, a, a) = (q₁, ε) — when a terminal on the stack matches the next input symbol, consume both.
  4. 04When the stack is empty (only Z₀ left, then popped), the input is accepted. No final states needed.
  5. 05No final states — acceptance purely by empty stack. This keeps the PDA design minimal.

Converting Final State PDA to Empty Stack PDA

  1. 01Add a new start state q₀' and a new "drain" state qₑ.
  2. 02From q₀': push a new bottom marker Z₀' below the original stack: δ(q₀', ε, Z₀') = (q₀, Z₀Z₀').
  3. 03From each original final state f: add ε-moves to qₑ that pop any stack symbol: δ(f, ε, A) = (qₑ, ε) for all A.
  4. 04In qₑ: keep popping everything until the stack is empty: δ(qₑ, ε, A) = (qₑ, ε) for all A. When the stack empties, acceptance is complete.
Conclusion

CFG → Empty Stack PDA needs just one looping state (q₁). It works by simulating leftmost derivation: ε-moves expand non-terminals on the stack, and input-matching moves consume terminals. The stack "drains" to empty exactly when the input is fully derived. Simple, elegant, and powerful.

Complete PDA → CFG Algorithm

Theorem

Given a PDA M accepting by empty stack, we can build an equivalent CFG. The non-terminal [p, A, q] encodes: "From state p, popping stack symbol A, I can eventually reach state q." Each PDA transition becomes one or more grammar rules using these triple non-terminals.

Step-by-Step Construction

  1. 01Variables: One triple [p, A, q] for every combination of two states p, q and stack symbol A, plus the start S.
  2. 02Start productions: S → [q₀, Z₀, q] for every state q — "the PDA starts with Z₀ and can end in any state."
  3. 03ε-pop: If δ(p, ε, A) ∋ (q, ε), add [p, A, q] → ε — popping A moves directly from p to q.
  4. 04Single push: If δ(p, a, A) ∋ (r, B), add [p, A, q] → a[r, B, q] for all states q.
  5. 05Multi push: If δ(p, a, A) ∋ (r, B₁B₂...Bₙ), chain the triples: [p,A,qₙ] → a[r,B₁,q₁][q₁,B₂,q₂]...[qₙ₋₁,Bₙ,qₙ].
  6. 06Cleanup: Remove useless productions (unreachable from S, or can't derive terminals).

Design two stack PDA for language L = {aⁿbⁿcⁿ | n ≥ 1}

Why Normal PDA Fails

⚠️

Fact: aⁿbⁿcⁿ is NOT a Context-Free Language — no single-stack PDA can recognise it. The problem: to check all three counts are equal, you'd need to "remember" n twice simultaneously, which one stack can't do. By the CFL Pumping Lemma, this language fails the pumping test. A Two-Stack PDA solves it — because 2 stacks = Turing Machine power.

Prerequisite: Two-Stack PDA Model

Two-Stack PDA Definition

A Two-Stack PDA has two independent stacks (Stack-1 and Stack-2), written as a 9-tuple M = (Q, Σ, Γ₁, Γ₂, δ, q₀, Z₁, Z₂, F). Each transition reads the current state, input symbol, and tops of both stacks, then produces a new state and updates both stack tops. Think of it as: two separate "notebooks" the machine can write on simultaneously.

Formal Notation for Transitions

Notation
δ(q, a, A, B) = (q', α, β)

Where:
  q  = current state
  a  = input (or ε)
  A  = top of Stack-1
  B  = top of Stack-2
  q' = next state
  α  = new string on Stack-1
  β  = new string on Stack-2

Strategy for aⁿbⁿcⁿ

  • Phase 1 — a's (state q₀): Read each 'a', push A onto Stack-1. Stack-1 becomes your counter for a's. Stack-2 untouched.
  • Phase 2 — b's (state q₁): For each 'b', simultaneously pop one A from Stack-1 and push B onto Stack-2. This "transfers" the count: if #a's = #b's, Stack-1 empties perfectly; Stack-2 now holds the count of b's.
  • Phase 3 — c's (state q₂): For each 'c', pop one B from Stack-2. If #c's = #b's, Stack-2 empties exactly when all c's are read.
  • Accept (state q₃): Both stacks back to Z₁ and Z₂ only, input exhausted → all three counts were equal. ✓

Γ₁ = {A, Z₁} (Stack-1 alphabet)
Γ₂ = {B, Z₂} (Stack-2 alphabet)
q₀ = q₀, F = {q₃}

Why 2 stacks = Turing Machine: Stack-1 holds the left part of a TM tape; Stack-2 holds the right part. The "read head" sits between the two tops. Conclusion
