01
Explain exception hierarchy in Java.
7 Marks ▾
Definition

An exception is an abnormal event that disrupts the normal flow of program execution. Java provides a comprehensive exception hierarchy rooted at the Throwable class in the java.lang package.

Concept

The entire hierarchy descends from java.lang.Object. The class Throwable has two direct subclasses:

  • Error – Serious problems that applications should not try to catch (e.g., OutOfMemoryError, StackOverflowError).
  • Exception – Conditions that programs should handle. It is further divided into:
    • Checked Exceptions – Must be declared or handled at compile time (e.g., IOException, SQLException).
    • Unchecked Exceptions (RuntimeException) – Detected at runtime (e.g., NullPointerException, ArrayIndexOutOfBoundsException).
Diagram – Exception Hierarchy
Key Points
Throwable is the root of all exceptions and errors.
Checked exceptions must be handled at compile time using throws or try-catch.
Unchecked exceptions (RuntimeException) are detected at runtime.
Errors indicate serious JVM-level failures; never catch them.
Custom exceptions extend Exception or RuntimeException.
getMessage(), printStackTrace() are key Throwable methods.
Conclusion

Java's exception hierarchy provides a structured, object-oriented mechanism to handle errors. Understanding the hierarchy helps developers write robust, fault-tolerant programs by catching the right type of exception at the right level.

02
Write a Java program demonstrating exception handling.
7 Marks ▾
Definition

Exception Handling is a mechanism to handle runtime errors gracefully using the keywords: try, catch, finally, throw, and throws.

Concept
  • try – Block of code that may throw an exception.
  • catch – Handles the exception; multiple catch blocks allowed.
  • finally – Always executes regardless of exception (used for cleanup).
  • throw – Explicitly throws an exception.
  • throws – Declares exceptions a method may throw.
Syntax
try {
    // risky code
} catch (ExceptionType e) {
    // handle exception
} finally {
    // always executes
}
Java Code
// Custom Exception
class InsufficientFundsException extends Exception {
    double amount;
    InsufficientFundsException(double amount) {
        super("Insufficient funds! Short by: " + amount);
        this.amount = amount;
    }
}

class BankAccount {
    private double balance;

    BankAccount(double balance) { this.balance = balance; }

    // 'throws' declares checked exception
    void withdraw(double amount) throws InsufficientFundsException {
        if (amount > balance) {
            throw new InsufficientFundsException(amount - balance);
        }
        balance -= amount;
        System.out.println("Withdrawn: " + amount + ", Balance: " + balance);
    }
}

public class ExceptionDemo {
    public static void main(String[] args) {
        BankAccount acc = new BankAccount(5000.0);

        try {
            acc.withdraw(2000);    // Success
            acc.withdraw(4000);    // Fails – InsufficientFunds

            // Unchecked exception demo
            int[] arr = new int[3];
            arr[10] = 5;            // ArrayIndexOutOfBoundsException

        } catch (InsufficientFundsException e) {
            System.out.println("[CAUGHT] Custom Exception: " + e.getMessage());
        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("[CAUGHT] Array Error: " + e.getMessage());
        } catch (Exception e) {
            System.out.println("[CAUGHT] General: " + e.getMessage());
        } finally {
            System.out.println("[FINALLY] Execution complete. Resources freed.");
        }
    }
}
Output
Withdrawn: 2000.0, Balance: 3000.0 [CAUGHT] Custom Exception: Insufficient funds! Short by: 1000.0 [FINALLY] Execution complete. Resources freed.
Key Points
Multiple catch blocks: most specific exception first.
finally always executes even if no exception occurs.
throw explicitly throws; throws declares in method signature.
Custom exceptions by extending Exception class.
03
Differentiate between Character Streams and Byte Streams.
7 Marks ▾
Definition

In Java I/O, streams are sequences of data. Java provides two categories:

  • Byte Streams – Handle raw binary data in 8-bit bytes. Base classes: InputStream / OutputStream.
  • Character Streams – Handle 16-bit Unicode characters for text. Base classes: Reader / Writer.
Diagram – Stream Class Hierarchy
Comparison Table
FeatureByte StreamCharacter Stream
Data Unit8-bit bytes16-bit Unicode characters
Base ClassesInputStream / OutputStreamReader / Writer
Use CaseBinary files (images, audio)Text files (.txt, .java)
Key ClassesFileInputStream, FileOutputStreamFileReader, FileWriter
BufferedBufferedInputStreamBufferedReader
EncodingNo encoding supportHandles Unicode encoding
PerformanceSlightly faster for binaryBetter for text processing
Methodread() returns int (0–255)read() returns char (0–65535)
Java Code
import java.io.*;

public class StreamDemo {
    public static void main(String[] args) throws IOException {

        // ── BYTE STREAM ──
        FileOutputStream fos = new FileOutputStream("byte_data.bin");
        fos.write(65);   // writes byte 65 (ASCII 'A')
        fos.close();

        FileInputStream fis = new FileInputStream("byte_data.bin");
        System.out.println("Byte Read: " + fis.read()); // prints 65
        fis.close();

        // ── CHARACTER STREAM ──
        FileWriter fw = new FileWriter("char_data.txt");
        fw.write("Hello AKTU!");
        fw.close();

        BufferedReader br = new BufferedReader(
                              new FileReader("char_data.txt"));
        String line = br.readLine();
        System.out.println("Char Read: " + line);
        br.close();
    }
}
Output
Byte Read: 65 Char Read: Hello AKTU!
Conclusion

Use Byte Streams for binary data (images, audio) and Character Streams for text data. Character streams are Unicode-aware and preferred for internationalized text processing.

04
Differentiate between wait() and notify().
7 Marks ▾
Definition

wait() and notify() are methods of the Object class used for inter-thread communication. They must be called from within a synchronized context.

Concept
  • wait() – Causes the current thread to release the lock and wait until another thread calls notify() or notifyAll() on the same object.
  • notify() – Wakes up one waiting thread.
  • notifyAll() – Wakes up all waiting threads.
Diagram – wait() / notify() Interaction
Comparison Table
Featurewait()notify()
PurposePauses current thread executionWakes up a waiting thread
LockReleases the lock immediatelyReleases lock after exiting synchronized block
Thread StateRUNNING → WAITINGMoves target from WAITING → RUNNABLE
Overloadswait(), wait(ms)notify(), notifyAll()
Wakes upN/AOne random waiting thread
ExceptionThrows InterruptedExceptionNo exception
LocationInside synchronized block (mandatory)Inside synchronized block (mandatory)
Java Code
class SharedResource {
    synchronized void waitMethod() throws InterruptedException {
        System.out.println(Thread.currentThread().getName() + ": Calling wait()");
        wait();   // releases lock and waits
        System.out.println(Thread.currentThread().getName() + ": Resumed after notify()");
    }

    synchronized void notifyMethod() {
        System.out.println(Thread.currentThread().getName() + ": Calling notify()");
        notify();  // wakes one waiting thread
    }
}

public class WaitNotifyDemo {
    public static void main(String[] args) {
        SharedResource obj = new SharedResource();

        Thread t1 = new Thread(() -> {
            try { obj.waitMethod(); } 
            catch (InterruptedException e) { e.printStackTrace(); }
        }, "Thread-A");

        Thread t2 = new Thread(() -> {
            try { Thread.sleep(1000); } 
            catch (InterruptedException e) {}
            obj.notifyMethod();
        }, "Thread-B");

        t1.start(); t2.start();
    }
}
Output
Thread-A: Calling wait() Thread-B: Calling notify() Thread-A: Resumed after notify()
Conclusion

wait() and notify() enable inter-thread communication and are essential for implementing the Producer-Consumer problem. Always use them inside synchronized blocks to avoid IllegalMonitorStateException.

05
Write a Java program that creates two threads — one to print even numbers and another to print odd numbers.
7 Marks ▾
Concept

Two threads share a common lock object and take turns printing odd and even numbers using wait() and notify(). This demonstrates inter-thread communication and synchronization.

Flow Diagram
Java Code
class PrintNumbers {
    private int num = 1;
    private final int MAX = 10;
    private boolean isOdd = true;  // start with odd

    // Prints odd numbers: 1, 3, 5, 7, 9
    public synchronized void printOdd() {
        while (num <= MAX) {
            while (!isOdd) {          // not my turn
                try { wait(); } catch (InterruptedException e) { return; }
            }
            if (num <= MAX) {
                System.out.println("ODD  Thread: " + num);
                num++;
            }
            isOdd = false;  // pass turn to even
            notify();
        }
    }

    // Prints even numbers: 2, 4, 6, 8, 10
    public synchronized void printEven() {
        while (num <= MAX) {
            while (isOdd) {           // not my turn
                try { wait(); } catch (InterruptedException e) { return; }
            }
            if (num <= MAX) {
                System.out.println("EVEN Thread: " + num);
                num++;
            }
            isOdd = true;   // pass turn to odd
            notify();
        }
    }
}

public class OddEvenThreads {
    public static void main(String[] args) {
        PrintNumbers pn = new PrintNumbers();

        Thread oddThread  = new Thread(pn::printOdd,  "ODD");
        Thread evenThread = new Thread(pn::printEven, "EVEN");

        oddThread.start();
        evenThread.start();
    }
}
Output
ODD Thread: 1 EVEN Thread: 2 ODD Thread: 3 EVEN Thread: 4 ODD Thread: 5 EVEN Thread: 6 ODD Thread: 7 EVEN Thread: 8 ODD Thread: 9 EVEN Thread: 10
Key Points
Flag isOdd controls whose turn it is.
wait() inside while loop (not if) prevents spurious wakeups.
synchronized method ensures mutual exclusion.
Method references pn::printOdd used with Thread constructor.
06
Explain thread lifecycle and thread creation methods.
7 Marks ▾
Definition

A thread is the smallest unit of execution. Java supports multithreading via the java.lang.Thread class. Every thread passes through a well-defined lifecycle (set of states) from creation to termination.

Thread Lifecycle State Diagram
Thread States
StateDescriptionTrigger
NEWThread created but not startednew Thread()
RUNNABLEReady to run or currently runningstart()
BLOCKEDWaiting to acquire a monitor lockSynchronized block contention
WAITINGIndefinitely waiting for notificationwait(), join()
TIMED_WAITINGWaiting for a specific timesleep(ms), wait(ms)
TERMINATEDThread has finished executionrun() returns or exception
Thread Creation Methods

Java provides two primary ways to create threads:

Method 1: Extending Thread class

class MyThread extends Thread {
    @Override
    public void run() {
        for (int i = 1; i <= 3; i++)
            System.out.println(getName() + ": " + i);
    }
}

public class ThreadCreation {
    public static void main(String[] args) {
        // Method 1 – Extend Thread
        MyThread t1 = new MyThread();
        t1.setName("Thread-Extend");
        t1.start();

        // Method 2 – Implement Runnable
        Thread t2 = new Thread(() -> {
            for (int i = 1; i <= 3; i++)
                System.out.println("Thread-Lambda: " + i);
        });
        t2.start();
    }
}
Output
Thread-Extend: 1 Thread-Lambda: 1 Thread-Extend: 2 Thread-Lambda: 2 Thread-Extend: 3 Thread-Lambda: 3 (order may vary)
Conclusion

The thread lifecycle defines six states managed by the JVM thread scheduler. Threads are created by extending Thread or implementing Runnable. The start() method triggers the JVM to call run() in a new execution context.

07
Compare extending Thread class and implementing Runnable interface.
7 Marks ▾
Definition

Java provides two approaches for thread creation:

  • Extending Thread class – Inherit from java.lang.Thread and override run().
  • Implementing Runnable interface – Implement the single-abstract-method run() from java.lang.Runnable.
Diagram
Comparison Table
Featureextends Threadimplements Runnable
InheritanceInherits Thread; can't extend other classFree to extend any class ✅
CouplingTightly coupled to ThreadLoosely coupled, reusable
Object creationnew MyThread().start()new Thread(new MyTask()).start()
OverheadEach object is a threadTask object separate from Thread
OOP DesignViolates single responsibilityFollows SRP principle ✅
Lambda supportNot supportedFunctional interface → Lambda ✅
Executor FrameworkNot compatibleCompatible with ExecutorService ✅
PreferredSimple, quick demosProduction code (recommended) ✅
Java Code – Both Approaches
// Approach 1: Extending Thread
class ThreadExtend extends Thread {
    @Override
    public void run() {
        System.out.println("[Extend]  Thread: " + getName());
    }
}

// Approach 2: Implementing Runnable
class RunnableImpl implements Runnable {
    @Override
    public void run() {
        System.out.println("[Runnable] Thread: "
            + Thread.currentThread().getName());
    }
}

public class ThreadComparison {
    public static void main(String[] args) {
        // Approach 1
        ThreadExtend t1 = new ThreadExtend();
        t1.setName("T1-Extend");
        t1.start();

        // Approach 2
        Thread t2 = new Thread(new RunnableImpl(), "T2-Runnable");
        t2.start();

        // Approach 3: Lambda (Runnable as FunctionalInterface)
        Thread t3 = new Thread(
            () -> System.out.println("[Lambda]   Thread: "
                + Thread.currentThread().getName()), "T3-Lambda");
        t3.start();
    }
}
Output
[Extend] Thread: T1-Extend [Runnable] Thread: T2-Runnable [Lambda] Thread: T3-Lambda
Conclusion

Implementing Runnable is the preferred approach as it promotes loose coupling, supports multiple inheritance of behavior, and works seamlessly with Java's Executor Framework and lambda expressions. Use extends Thread only for simple, standalone thread tasks.

08
Explain synchronization and inter-thread communication.
7 Marks ▾
Definition

Synchronization is a mechanism that ensures only one thread at a time can access a shared resource (critical section), preventing race conditions and data inconsistency.

Inter-thread Communication is the process of threads communicating and cooperating by notifying each other about their state changes using wait(), notify(), and notifyAll().

Synchronization – Monitor Lock Diagram
Types of Synchronization
  • Synchronized Method – Lock on the object (this).
  • Synchronized Block – Lock on a specified object; finer granularity.
  • Static Synchronized – Lock on the Class object (class-level lock).
Java Code – Synchronization + Inter-thread Communication (Producer-Consumer)
class Buffer {
    private int data;
    private boolean hasData = false;

    // Producer: puts data into buffer
    public synchronized void produce(int val) throws InterruptedException {
        while (hasData) {
            System.out.println("Producer waiting... buffer full");
            wait();           // wait until consumer reads
        }
        data = val;
        hasData = true;
        System.out.println("Produced: " + data);
        notify();           // notify consumer
    }

    // Consumer: reads data from buffer
    public synchronized void consume() throws InterruptedException {
        while (!hasData) {
            System.out.println("Consumer waiting... buffer empty");
            wait();           // wait until producer puts data
        }
        System.out.println("Consumed: " + data);
        hasData = false;
        notify();           // notify producer
    }
}

public class SyncDemo {
    public static void main(String[] args) {
        Buffer buf = new Buffer();

        Thread producer = new Thread(() -> {
            for (int i = 1; i <= 3; i++) {
                try { buf.produce(i * 10); } 
                catch (InterruptedException e) {}
            }
        }, "Producer");

        Thread consumer = new Thread(() -> {
            for (int i = 1; i <= 3; i++) {
                try { buf.consume(); } 
                catch (InterruptedException e) {}
            }
        }, "Consumer");

        producer.start();
        consumer.start();
    }
}
Output
Produced: 10 Consumed: 10 Produced: 20 Consumed: 20 Produced: 30 Consumed: 30
Key Points
Race condition: multiple threads modify shared data simultaneously causing inconsistency.
synchronized keyword acquires the intrinsic (monitor) lock of the object.
wait() inside while (not if) prevents spurious wakeups.
notifyAll() wakes all threads; use when multiple threads wait on different conditions.
Deadlock: occurs when two threads wait on each other's lock indefinitely.
Always release locks in finally if using explicit Lock objects.
Conclusion

Synchronization prevents data corruption in concurrent environments, while inter-thread communication (wait/notify) allows threads to cooperate efficiently. Together they are the foundation of thread-safe Java applications and design patterns like Producer-Consumer.
