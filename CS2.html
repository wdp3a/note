What is computer security? Discuss confidentiality and integrity.
Definition

Computer Security refers to the protection of computer systems, networks, and data from unauthorized access, theft, damage, or disruption. Its main goal is to ensure that information is safe, accurate, and available to authorized users only.

Key Points
  • Confidentiality: Only authorized persons can access the information. For example, your bank password should only be known to you. It prevents unauthorized disclosure of data. Achieved using encryption, passwords, and access controls.
  • Integrity: Data must remain accurate and unchanged unless modified by an authorized person. For example, if you send ₹100 in a transaction, it should not change to ₹1000. It prevents unauthorized modification of data.
  • Availability (bonus point): The third pillar – information must be available to authorized users whenever needed. These three together form the CIA Triad of security.
Conclusion
Computer security is built on the CIA Triad. Confidentiality protects data from exposure; Integrity protects data from tampering. Both are essential for any secure system.

What is Encryption and Decryption in cryptography?
⚡ Concept Booster

Cryptography is the science of hiding information using codes and ciphers so that only the intended person can read it. Think of it as writing a secret letter in a language only you and your friend understand.

Definition

Encryption is the process of converting plain readable data (plaintext) into an unreadable format (ciphertext) using an algorithm and a key, so that unauthorized persons cannot read it.

Decryption is the reverse process — converting the ciphertext back to the original plaintext using a key, so the authorized receiver can read the message.

Key Points
  • Plaintext → Encryption → Ciphertext (data becomes unreadable)
  • Ciphertext → Decryption → Plaintext (data becomes readable again)
  • Key is used in both processes. Without the correct key, decryption is impossible.
  • Example: "HELLO" → encrypted → "MJQQT" → decrypted → "HELLO"
  • Types: Symmetric Encryption (same key for both), Asymmetric Encryption (public & private key pair).
Conclusion
Encryption and decryption are the core tools of cryptography. Encryption protects data during storage and transmission; decryption allows the rightful owner to read it.
03
What are the roles of cipher and key in cryptography?
Definition

A Cipher is an algorithm (a set of rules or steps) used to perform encryption and decryption. A Key is a secret value (a string of bits/characters) that is fed into the cipher to produce the encrypted or decrypted output.

Key Points
  • Role of Cipher: It defines the method/algorithm for transforming data. For example, Caesar Cipher shifts letters by a fixed number. AES, DES, RSA are modern ciphers.
  • Role of Key: It controls how the cipher operates. Even if someone knows the cipher (algorithm), without the key they cannot decrypt the data. The security of encryption depends on the key, not on hiding the algorithm.
  • Kerckhoffs's Principle: A cipher should be secure even if everything about the system is public knowledge, except the key.
  • Longer key = stronger security. Example: AES-128 (128-bit key) vs AES-256 (256-bit key).
Conclusion
The cipher provides the method, and the key provides the secret. Together they ensure data security. Without the correct key, the cipher alone is useless to an attacker.

What are the principles of secure design / secure architecture principles?
Introduction

Secure design principles are a set of guidelines followed by security engineers while building systems to make them resistant to attacks. These were proposed by Saltzer & Schroeder and are fundamental to building secure software and systems.

Key Principles
  • Principle of Least Privilege: Every user or program should have only the minimum rights needed to perform their task. No extra permissions.
  • Fail-Safe Defaults: By default, access should be denied. Access is given only when explicitly permitted.
  • Economy of Mechanism: Keep the design as simple as possible. Simple systems are easier to test and verify.
  • Complete Mediation: Every access to a resource must be checked for authorization — no shortcuts.
  • Open Design: Security should not depend on keeping the design secret. (Kerckhoffs's principle)
  • Separation of Privilege: Require more than one condition (e.g., two keys) to grant access to sensitive operations.
  • Psychological Acceptability: Security mechanisms should be easy for users to understand and use correctly.
Conclusion
These principles form the foundation of secure system design. Following them reduces vulnerabilities and makes systems harder to attack.

What is SSL and how does it work? Differentiate between HTTPS, SSL and TLS.
⚡ Concept Booster

When you visit a website, data travels between your browser and the server. Without security, hackers can read this data. SSL/TLS creates a secure, encrypted tunnel for this data transfer.

Definition

SSL (Secure Sockets Layer) is a security protocol that establishes an encrypted connection between a web server and a browser, ensuring that all data passed between them remains private and secure.

How SSL Works
  • Step 1 – Handshake: The browser contacts the server and requests a secure connection.
  • Step 2 – Certificate: The server sends its SSL Certificate (which contains its public key) to the browser.
  • Step 3 – Verification: The browser verifies the certificate with a trusted Certificate Authority (CA).
  • Step 4 – Session Key: A shared session key is created using asymmetric encryption for symmetric encrypted communication.
  • Step 5 – Secure Communication: All data is now encrypted using this session key.
Difference: HTTPS, SSL, TLS
  • SSL – Old protocol (now deprecated). Was used to secure internet connections. Has known vulnerabilities.
  • TLS (Transport Layer Security) – Upgraded, more secure version of SSL. TLS 1.3 is the latest. Modern websites use TLS, not SSL.
  • HTTPS – HTTP + TLS/SSL = HTTPS. It is the secure version of HTTP. When you see a 🔒 padlock in your browser, the website is using HTTPS (which uses TLS underneath).
Conclusion
SSL is the older protocol, TLS is its improved successor, and HTTPS is the application-level result of using TLS to secure HTTP communication.

Explain System Call Interposition.
⚡ Concept Booster

A System Call is a request made by a program to the operating system to perform privileged operations like reading a file, opening a network connection, or allocating memory. Normal programs cannot directly access hardware — they must go through the OS via system calls.

Definition

System Call Interposition is a security technique where a monitor (a security layer) intercepts system calls made by an application before they reach the operating system kernel. The monitor checks whether the call is safe or malicious, and either allows or denies it.

Key Points
  • It works like a security guard between the application and the OS kernel.
  • If an application tries to do something harmful (e.g., delete a system file or open a suspicious network port), the monitor blocks it.
  • It is used for sandboxing untrusted programs — running them in a restricted environment.
  • Tools like Systrace, seccomp (used in Linux) use system call interposition.
  • It provides fine-grained control over what a program can and cannot do.
Conclusion
System Call Interposition is a powerful security mechanism that monitors application behavior at the OS boundary, preventing malicious or unauthorized actions before they can cause harm.

Discuss problems associated with ptrace.
⚡ Concept Booster

ptrace is a system call in Linux/Unix that allows one process (the tracer/monitor) to observe and control the execution of another process (the tracee). It is used for debugging and is also the basis for system call interposition tools like Strace.

Introduction

While ptrace is useful for debugging and monitoring, it has several security and performance problems that make it unreliable for security-critical interposition.

Problems with ptrace
  • TOCTOU (Time Of Check to Time Of Use) Attack: There is a time gap between when ptrace checks a system call argument and when the kernel actually uses it. An attacker can modify the argument in this gap to bypass security checks. This is the most serious flaw.
  • Performance Overhead: ptrace requires context switches between the traced process and the monitor for every system call. This is very slow and causes significant performance degradation.
  • Complexity in Multi-threaded Programs: ptrace has difficulty correctly handling multi-threaded applications because multiple threads making system calls simultaneously create race conditions.
  • Incomplete Coverage: ptrace may miss certain system calls or signals, creating gaps in monitoring that attackers can exploit.
  • Limited to Single Tracer: Only one process can trace another at a time using ptrace, limiting flexibility.
Conclusion
ptrace is useful for debugging but is unsuitable for production security enforcement due to TOCTOU vulnerabilities, performance issues, and multi-threading problems. Modern alternatives like seccomp are preferred.

What is the difference between Discretionary Access Control, Mandatory Access Control, UNIX access control and Windows access control?
⚡ Concept Booster

Access Control is the process of deciding who can access which resources (files, folders, devices) in a system. Different systems use different models to implement this.

Key Differences
  • Discretionary Access Control (DAC): The owner of a resource decides who can access it. For example, you own a file and you choose who can read, write, or execute it. It is flexible but less secure — owners may make poor decisions. Used in most standard OS.
  • Mandatory Access Control (MAC): Access is controlled by the system (administrator/policy), not the owner. Resources are assigned security labels (e.g., Top Secret, Confidential) and users have clearance levels. Even the file owner cannot override the policy. Used in military and high-security systems (e.g., SELinux).
  • UNIX Access Control: Uses DAC model. Each file has an owner, a group, and permissions for Owner/Group/Others using read (r), write (w), execute (x) bits. For example: rwxr-xr--. Simple and effective.
  • Windows Access Control: Uses a more advanced DAC model called ACL (Access Control List). Each file/folder has an ACL listing specific users and their permissions. More granular than UNIX. Supports inheritance of permissions. Uses SID (Security Identifiers) to identify users.
Conclusion
DAC gives control to the owner; MAC gives control to the system. UNIX uses simple permission bits while Windows uses detailed ACLs — both are DAC models but with different levels of granularity.

What is Web Security?
Definition

Web Security (also called Web Application Security) refers to the protection of websites, web applications, and web services from attacks, unauthorized access, data theft, and malicious exploitation over the internet.

Key Points
  • Web security protects against threats like SQL Injection, XSS, CSRF, Session Hijacking, Phishing, and more.
  • It ensures that user data (like passwords, credit card numbers) is not stolen or tampered with.
  • Key tools and techniques include: HTTPS, Firewalls, Input Validation, Authentication, Encryption, Security Headers.
  • The OWASP Top 10 is a widely recognized list of the most critical web application security risks.
  • Web security protects three parties: the server (where the app runs), the client (browser), and the data in transit.
Conclusion
Web security is essential in today's internet-driven world. Without it, sensitive user data and business operations are at constant risk from cyber attackers.

What is SQL injection attack? Explain briefly.
⚡ Concept Booster

SQL (Structured Query Language) is used by websites to communicate with their databases. For example, when you log in, the website sends an SQL query to the database to check your username and password.

Definition

SQL Injection is a web attack where the attacker inserts malicious SQL code into an input field (like a login form or search box) to manipulate the database query and gain unauthorized access to data.

Key Points
  • How it works: Suppose a login query is: SELECT * FROM users WHERE username='input' AND password='input'. An attacker types ' OR '1'='1 as input. The query becomes always true and the attacker logs in without a valid password.
  • What attackers can do: Read sensitive data, modify or delete database records, bypass login authentication, and sometimes execute commands on the server.
  • Prevention: Use Prepared Statements / Parameterized Queries, input validation, and stored procedures. Never directly include user input in SQL queries.
Conclusion
SQL Injection is one of the most dangerous and common web attacks. It exploits improper input handling to manipulate databases. Parameterized queries are the best defense.

What is Cross Site Scripting (XSS)? Mention anti-XSS tools/protection.
⚡ Concept Booster

A website can display content entered by users (like comments, usernames, search queries). If the website doesn't validate this input, an attacker can enter malicious scripts instead of normal text.

Definition

Cross Site Scripting (XSS) is a web attack where an attacker injects malicious JavaScript code into a trusted website. When other users visit that page, the malicious script runs in their browser without their knowledge, stealing cookies, session tokens, or redirecting them to fake sites.

Types & Key Points
  • Stored XSS: Malicious script is permanently stored in the database (e.g., in a comment section). Every user who loads that page gets attacked.
  • Reflected XSS: The script is embedded in a URL. When the victim clicks the URL, the script executes in their browser.
  • DOM-based XSS: The attack happens in the browser's DOM environment without involving the server.
  • Anti-XSS Protections:
    • Input Validation & Output Encoding (HTML encode user input)
    • Content Security Policy (CSP) headers
    • HttpOnly Cookies (prevents JavaScript from accessing cookies)
    • Anti-XSS Libraries: OWASP ESAPI, DOMPurify, XSS filters
    • Browser built-in XSS filters (X-XSS-Protection header)
Conclusion
XSS attacks exploit a website's trust to run attacker scripts in victim browsers. Proper input handling, output encoding, and CSP headers are the best defense.

What is Cross Site Request Forgery (CSRF)?
⚡ Concept Booster

When you log into a website, your browser stores a session cookie. The website uses this cookie to verify you are logged in. CSRF exploits this by tricking your browser into sending requests to that website without your knowledge.

Definition

CSRF (Cross Site Request Forgery) is an attack where an attacker tricks an already-authenticated user into unknowingly submitting a malicious request to a web application. The application cannot tell if the request came from the real user or from the attacker's page.

Key Points
  • Example: You are logged into your bank. You visit a malicious website. That site silently sends a request to your bank to transfer money using your active session.
  • CSRF exploits the website's trust in the user's browser (since the cookie is automatically sent).
  • Unlike XSS (which exploits the user's trust in the website), CSRF exploits the website's trust in the user.
  • Prevention: Use CSRF Tokens (unique random tokens added to forms), SameSite Cookie attribute, re-authentication for sensitive actions, and Referer header validation.
Conclusion
CSRF tricks authenticated users into performing unwanted actions on a trusted website. CSRF tokens are the most effective defense against this attack.

What are covert channels and their disadvantages/problems in VMM security?
⚡ Concept Booster

A VMM (Virtual Machine Monitor) or Hypervisor runs multiple virtual machines (VMs) on a single physical machine. These VMs should be completely isolated from each other — but covert channels can break this isolation.

Definition

A Covert Channel is a secret communication path that allows a process to transfer information in a way that violates the system's official security policy — using resources that are not intended for communication (like CPU usage, memory, disk I/O timing).

Problems in VMM Security
  • Information Leakage: A malicious VM can use covert channels (e.g., by observing CPU or cache timing) to steal data from another VM on the same physical host — breaking isolation.
  • Difficult to Detect: Covert channels do not use normal network paths, so traditional security tools like firewalls cannot detect them.
  • Types in VMM context: Storage Covert Channels (using shared storage) and Timing Covert Channels (measuring response times to infer secret data).
  • Hard to Eliminate: Since they exploit shared physical resources (CPU cache, RAM), completely eliminating covert channels in a shared environment is nearly impossible.
  • Low bandwidth but still dangerous: Even if they transfer data slowly, they can leak passwords, encryption keys, or sensitive information over time.
Conclusion
Covert channels are hidden communication paths that bypass security policies. In VMM environments, they are particularly dangerous because they can break VM isolation without being detected by standard security tools.

Give benefits of IPsec.
⚡ Concept Booster

IPsec (Internet Protocol Security) is a suite of protocols that secures communication at the Network Layer (Layer 3) of the OSI model. It is commonly used in VPNs (Virtual Private Networks).

Definition

IPsec provides end-to-end security for IP packets by authenticating and encrypting each IP packet in a communication session.

Benefits of IPsec
  • Data Confidentiality: Encrypts packets so that even if intercepted, the data cannot be read.
  • Data Integrity: Ensures that packets have not been modified during transmission using cryptographic hash functions.
  • Authentication: Verifies that packets come from a legitimate, trusted source (not a fake/impersonated source). Prevents IP spoofing.
  • Anti-Replay Protection: Prevents attackers from capturing and re-sending old packets to replay attacks.
  • Transparent to Applications: Works at the network layer, so applications don't need to be modified to benefit from IPsec security.
  • VPN Support: IPsec is the backbone of secure VPN tunnels used by organizations to connect remote offices and employees.
Conclusion
IPsec provides a comprehensive security solution at the network level — offering confidentiality, integrity, authentication, and replay protection — making it ideal for VPNs and secure network communication.

Why would you recommend using DNSSEC?
⚡ Concept Booster

DNS (Domain Name System) is like the phone book of the internet. It converts domain names (like google.com) into IP addresses. However, standard DNS has no security — attackers can manipulate DNS responses in a DNS Spoofing / Cache Poisoning attack.

What is DNSSEC?

DNSSEC (DNS Security Extensions) is a set of security extensions added to DNS that use digital signatures to verify that the DNS response you receive is authentic and has not been tampered with.

Why Recommend DNSSEC?
  • Prevents DNS Spoofing/Poisoning: Without DNSSEC, attackers can redirect users to fake websites by providing false IP addresses. DNSSEC prevents this.
  • Ensures Data Integrity: Digital signatures ensure DNS records have not been modified by a man-in-the-middle attacker.
  • Builds Trust: Users can be confident they are connecting to the correct, legitimate website.
  • Chain of Trust: DNSSEC creates a cryptographic chain of trust from the root DNS servers down to the individual domain, making it extremely difficult to forge.
  • Protects Against Pharming: Pharming attacks (redirecting to malicious sites at the DNS level) are blocked by DNSSEC.
Conclusion
DNSSEC should be used because standard DNS is vulnerable to spoofing and poisoning attacks. DNSSEC adds authentication and integrity verification, making DNS responses trustworthy.

How many look-up zones are in DNS?
⚡ Concept Booster

A DNS Zone is a portion of the DNS namespace that is managed by a specific DNS server. DNS lookup zones store information about domain names and their corresponding IP addresses.

Answer

There are two types of DNS lookup zones:

The Two Look-up Zones
  • 1. Forward Lookup Zone: Resolves a domain name → IP address. This is the most common type. Example: When you type "google.com", the forward lookup zone returns its IP address (142.250.190.46). Uses A records (for IPv4) and AAAA records (for IPv6).
  • 2. Reverse Lookup Zone: Resolves an IP address → domain name. It is the opposite of forward lookup. Example: Given IP 142.250.190.46, it returns "google.com". Uses PTR (Pointer) records. Useful for logging, security auditing, and verifying email servers.
Conclusion
DNS has two lookup zones — Forward (name to IP) and Reverse (IP to name). Both are essential for proper DNS operation and network security verification.

Define Firewall and its uses.
Definition

A Firewall is a network security system (hardware, software, or both) that monitors and controls incoming and outgoing network traffic based on predefined security rules. It acts as a barrier between a trusted internal network and an untrusted external network (like the internet).

Uses of Firewall
  • Traffic Filtering: Allows legitimate traffic and blocks unauthorized or suspicious traffic based on IP addresses, ports, and protocols.
  • Preventing Unauthorized Access: Stops hackers, bots, and unauthorized users from entering the internal network.
  • Protection from Malware: Blocks malicious traffic that may carry viruses, worms, or trojans.
  • Monitoring & Logging: Keeps logs of all network traffic for security auditing and intrusion detection.
  • VPN Support: Many firewalls support VPN connections for secure remote access.
  • Types: Packet Filtering Firewall, Stateful Inspection Firewall, Application Layer Firewall (Proxy Firewall), Next-Generation Firewall (NGFW).
Conclusion
A firewall is the first line of defense for any network. It acts as a security gatekeeper — allowing safe traffic and blocking threats before they can enter the internal network.

What is Session Hijacking and why is it successful?
⚡ Concept Booster

When you log into a website, the server creates a session and gives your browser a session ID (stored as a cookie). This ID is used to recognize you on subsequent requests without asking for your password again.

Definition

Session Hijacking is an attack where an attacker steals a valid session ID (session token) of a logged-in user and uses it to impersonate that user, gaining unauthorized access to the web application — without knowing the username or password.

Why is it Successful?
  • Session IDs sent over HTTP: If HTTPS is not used, session cookies travel as plaintext and can be intercepted by a network sniffer (Man-in-the-Middle attack).
  • Predictable Session IDs: If session IDs are not random enough, attackers can guess them.
  • XSS Exploitation: Attacker uses XSS to steal session cookies from the victim's browser using JavaScript (document.cookie).
  • Session Fixation: Attacker tricks the user into using a session ID that the attacker already knows.
  • Long Session Timeouts: Sessions that never expire give attackers a long window to use the stolen token.
Conclusion
Session hijacking is successful because session tokens are often poorly protected. Using HTTPS, secure/HttpOnly cookie flags, short timeouts, and token regeneration after login are key countermeasures.

What is the significance of Confinement Principle?
⚡ Concept Booster

Imagine you hire a contractor to work inside your house but you don't want them to take anything outside. Confinement in computing is similar — restricting a program so it cannot leak information or resources outside its allowed boundary.

Definition

The Confinement Principle (proposed by Butler Lampson) states that a program should be restricted so that it cannot communicate or leak information outside its authorized boundaries, even if it is malicious or compromised.

Significance
  • Prevents Data Leakage: Even if a program is malicious, confinement ensures it cannot send sensitive data to unauthorized external parties.
  • Sandboxing: Confinement is the basis of sandboxing — running programs in an isolated environment (e.g., browser sandboxes, containers like Docker).
  • Limits Damage: If a program is compromised, confinement limits the damage it can cause — it cannot affect other parts of the system.
  • Challenges: Achieving complete confinement is very hard due to covert channels — a confined process may still leak info through side channels (CPU timing, memory usage).
  • Used in: Operating system sandboxes, virtual machines, Java security model, and containerization.
Conclusion
The confinement principle is crucial for limiting the impact of malicious or compromised programs. It forms the theoretical basis for sandboxing and containment technologies used in modern security systems.

Discuss software fault isolation.
⚡ Concept Booster

Normally, different programs running in the same process share the same memory space. If one part crashes or has a bug, it can corrupt everything else. Software Fault Isolation (SFI) prevents this by creating boundaries within the same process.

Definition

Software Fault Isolation (SFI) is a technique that confines untrusted code within a specific region of memory so that any fault, bug, or malicious action in that code cannot affect the rest of the application or system — without using hardware protection or separate processes.

Key Points
  • How it works: The code is modified (instrumented) before execution. Instructions that access memory are checked to ensure they only access allowed memory regions.
  • No separate process needed: Isolation is achieved at software level, making it faster than process-level isolation.
  • Used in: Web browsers (to safely run plugins), Native Client (NaCl) by Google, WebAssembly sandbox.
  • Benefit: Good performance with strong isolation — the code cannot jump to or write into unauthorized memory.
  • Limitation: Covert channels may still exist; also requires careful implementation to ensure all code paths are covered.
Conclusion
SFI is an efficient way to run untrusted code safely within a trusted environment. It is widely used in browsers and runtime environments to prevent malicious or buggy code from compromising the entire system.

What is the use of kernel in UNIX operating system?
⚡ Concept Booster

An operating system has two main layers: the Kernel (inner core, talks to hardware) and the Shell (outer layer, interface for users). The kernel is the heart of the OS.

Definition

The Kernel is the core component of the UNIX operating system that directly manages the hardware resources of the computer and provides essential services to all other parts of the OS and to applications.

Uses of Kernel in UNIX
  • Process Management: Creates, schedules, and terminates processes. Manages multitasking.
  • Memory Management: Allocates and deallocates memory to processes. Manages virtual memory and paging.
  • File System Management: Manages file creation, reading, writing, deletion, and permissions in the UNIX file system.
  • Device Management: Communicates with hardware devices (disk, keyboard, monitor) through device drivers.
  • System Call Interface: Provides a secure interface (system calls) for user programs to request kernel services like file I/O and process creation.
  • Security Enforcement: Enforces user permissions, access controls, and privilege separation.
Conclusion
The UNIX kernel is the central authority of the OS — managing hardware, memory, processes, and files. All user programs depend on the kernel to perform any meaningful operation.

What are some advantages and limitations of UNIX?
Advantages of UNIX
  • Multi-user & Multi-tasking: Multiple users can work simultaneously, and multiple programs can run at the same time.
  • Security: Strong file permission system (owner/group/others), user authentication, and privilege separation make UNIX inherently secure.
  • Stability & Reliability: UNIX systems can run for years without rebooting. Used in servers and critical infrastructure.
  • Portability: Written mostly in C, UNIX can be compiled and run on different hardware platforms.
  • Powerful Shell: The UNIX shell supports scripting and automation of complex tasks with simple commands.
  • Open Source Variants: Linux (UNIX-like) is freely available and widely used.
Limitations of UNIX
  • Complex for Beginners: Command-line interface is not user-friendly. Steep learning curve for non-technical users.
  • Limited GUI Support: UNIX was originally designed for CLI, not graphical interfaces.
  • Hardware Compatibility: Not all devices have UNIX-compatible drivers.
  • Cost: Commercial UNIX versions (like Solaris, HP-UX) can be expensive.
Conclusion
UNIX is powerful, secure, and stable — ideal for servers and developers. However, its complexity makes it challenging for general consumers compared to Windows or macOS.
23
What is a privilege? Explain ways to drop privileges.
⚡ Concept Booster

In an OS, not every program needs full administrative power. A program running with too many privileges is dangerous — if compromised, the attacker gets all those privileges too. Dropping privileges is like removing extra keys from a keyholder once they are no longer needed.

Definition

A Privilege is a special permission or right granted to a process or user to perform operations beyond normal user capabilities — such as reading protected files, binding to low port numbers (below 1024), or modifying system settings.

Ways to Drop Privileges
  • setuid() / seteuid(): A process running as root can call setuid() to permanently change its user ID to a less-privileged user, dropping root privileges.
  • Privilege Separation: Split a program into two parts — one high-privilege part that does the sensitive task, and one low-privilege part that does the rest. The high-privilege part exits after doing its job. (Used in OpenSSH).
  • Capabilities (Linux): Instead of giving full root access, Linux Capabilities allow giving only specific powers (like CAP_NET_BIND_SERVICE to bind port 80) and revoking them after use.
  • chroot Jail: Restricts a process to a specific directory, so even if it runs as root, it cannot access files outside that directory.
  • Using Non-root Accounts: Design applications to run as a dedicated non-root service account rather than root from the start.
Conclusion
Privileges should be held only as long as needed and dropped immediately after use. This follows the Principle of Least Privilege and significantly limits damage if a program is compromised.
24
What are the goals of confidentiality policies?
⚡ Concept Booster

A Confidentiality Policy is a set of rules that an organization or system follows to control who can access sensitive information. The most famous model is the Bell-LaPadula Model, used in military systems.

Definition

Confidentiality Policies are security policies designed to prevent unauthorized disclosure (leakage) of sensitive information. They define rules about who can read what data.

Goals of Confidentiality Policies
  • Prevent Unauthorized Disclosure: Ensure that sensitive data is only accessible to authorized individuals. This is the primary goal.
  • No Read Up (Simple Security Property): A user with low clearance cannot read data with a higher classification level. (e.g., a "Confidential" user cannot read "Top Secret" files).
  • No Write Down (Star Property): A user with high clearance cannot write data to a lower level. This prevents a high-clearance user from leaking sensitive info to a low-clearance file.
  • Data Classification: Classify data into levels (Public, Internal, Confidential, Top Secret) and ensure each level is protected appropriately.
  • Enforce Need-to-Know: Even authorized users should only access information they need for their specific job function.
Conclusion
Confidentiality policies aim to prevent data leakage through strict access controls. The Bell-LaPadula "no read up, no write down" rules are the classic implementation of these goals.

Define hash function. What is its use?
Definition

A Hash Function is a mathematical function that takes an input (data of any size) and produces a fixed-size output called a hash value, digest, or fingerprint. It is a one-way function — you cannot reverse it to get the original input.

Example: SHA-256 always produces a 256-bit output regardless of input size. "Hello" → a8483... (64 hex chars)

Uses of Hash Function
  • Password Storage: Instead of storing actual passwords, systems store their hash values. Even if the database is hacked, the actual password cannot be recovered.
  • Data Integrity Verification: When you download a file, you can compare its hash with the official hash to confirm the file was not modified or corrupted.
  • Digital Signatures: Hash functions are used in creating digital signatures. The hash of a document is signed, not the whole document.
  • Message Authentication Codes (MAC): Ensures messages have not been tampered with during transmission.
  • Blockchain: Each block in a blockchain contains the hash of the previous block, ensuring immutability.
  • Common Hash Algorithms: MD5 (weak, deprecated), SHA-1 (weak), SHA-256, SHA-3 (secure).
Conclusion
Hash functions provide a fast, one-way way to represent data uniquely. They are essential for password security, data integrity, digital signatures, and many other cryptographic applications.

What is the main difference between virus and worm?
Quick Definitions

A Virus is a malicious program that attaches itself to a legitimate file/program and spreads when that file is shared or executed by a user. It requires human action to spread.

A Worm is a self-replicating malicious program that spreads automatically over a network without needing to attach to any file and without requiring any human action.

Key Differences
  • Spreading: Virus needs a host file + user action to spread. Worm spreads on its own through networks.
  • Host Requirement: Virus requires a host file (like .exe, .doc). Worm is standalone — no host file needed.
  • Speed of Spread: Worms spread much faster than viruses since they are autonomous.
  • Damage: Both can cause damage; worms also consume bandwidth and can slow down entire networks.
  • Examples: Virus — ILOVEYOU, Melissa. Worm — Morris Worm, WannaCry (which also had ransomware).
Conclusion
The key difference is that a virus needs a host and human action to spread, while a worm is self-sufficient and spreads automatically across networks. Worms are generally faster and harder to contain.

What is Ransomware?
Definition

Ransomware is a type of malicious software (malware) that encrypts the victim's files or locks their computer, making the data inaccessible, and then demands a ransom payment (usually in cryptocurrency like Bitcoin) from the victim to restore access.

Key Points
  • How it spreads: Through phishing emails, malicious attachments, infected websites, or exploiting software vulnerabilities.
  • What it does: Encrypts all important files (documents, photos, databases) with a key only the attacker knows. Displays a ransom note demanding payment.
  • Famous Examples: WannaCry (2017) — affected 200,000+ computers worldwide; CryptoLocker; Petya/NotPetya.
  • Impact: Can shut down hospitals, businesses, and government systems. Victims may lose critical data permanently.
  • Prevention: Regular data backups, keeping software updated, not clicking suspicious links, using antivirus software, and email filtering.
Conclusion
Ransomware is one of the most destructive cyber threats today. Regular offline backups are the most effective way to recover without paying the ransom. Prevention is always better than cure.

What is the use of frame busting in web security?
⚡ Concept Booster

Clickjacking is a web attack where an attacker embeds a legitimate website (like your bank) inside an invisible <iframe> on their malicious page. You think you're clicking on the malicious page, but you're actually clicking on the hidden bank page — performing actions unknowingly.

Definition

Frame Busting is a technique used by websites to prevent themselves from being loaded inside an <iframe> on another site. It is used to defend against Clickjacking attacks.

How It Works & Key Points
  • JavaScript Method: The website includes a script that checks if it is the top-level window. If it's inside an iframe, the script "busts out" by forcing itself to be the top window: if(top != self) top.location = self.location;
  • Better Alternative – X-Frame-Options Header: Modern web security uses the HTTP header X-Frame-Options: DENY (or SAMEORIGIN) to tell browsers to refuse loading the page inside any iframe. This is more reliable than JavaScript frame busting.
  • Content Security Policy (CSP): The frame-ancestors directive in CSP is the latest recommended way to control iframe embedding.
  • Frame busting protects sensitive pages like login pages, banking pages, and settings pages from clickjacking.
Conclusion
Frame busting protects users from clickjacking by preventing websites from being embedded in iframes. The X-Frame-Options header and CSP frame-ancestors are the modern, recommended solutions.

What is the difference between Cache Memory and RAM?
⚡ Concept Booster

Think of memory like a chef's workspace. RAM is the large counter where all ingredients (data) for the current meal are kept. Cache is the small tray right next to the chef's hand — holding only the most frequently needed ingredients for instant access.

Key Differences
  • Location: Cache is located inside or very close to the CPU. RAM (main memory) is located on the motherboard, farther from the CPU.
  • Speed: Cache is much faster than RAM (nanoseconds vs. tens of nanoseconds). It provides data to the CPU at nearly CPU speed.
  • Size: Cache is small (KB to a few MB). RAM is much larger (GB range).
  • Cost: Cache is significantly more expensive per byte than RAM.
  • Purpose: Cache stores frequently used data for ultra-fast CPU access, reducing delays. RAM stores all data and programs currently in use.
  • Volatility: Both are volatile — data is lost when power is off.
  • Levels: Cache has L1, L2, L3 levels — L1 is fastest and smallest, closest to CPU.
Conclusion
Cache is a small, ultra-fast memory inside the CPU for frequently accessed data, while RAM is larger, slower main memory holding all active programs. Both are essential for CPU performance.

What is Botnet?
⚡ Concept Booster

Imagine thousands of computers unknowingly infected with malware and controlled by a single hacker — like an army of zombie computers. This is a botnet. The infected computers are called bots or zombies.

Definition

A Botnet (short for "Robot Network") is a network of internet-connected devices (computers, phones, IoT devices) that have been infected by malware and are secretly controlled by an attacker (called the Bot Herder or C&C — Command and Control server) without the device owners' knowledge.

Key Points
  • How devices get infected: Through malware, phishing emails, software vulnerabilities, or malicious downloads.
  • Uses of Botnets by attackers:
    • DDoS Attacks – Flood a target server with traffic to take it down
    • Spam Campaigns – Send millions of spam emails
    • Click Fraud – Generate fake ad clicks
    • Credential Stuffing – Try stolen passwords on many sites
    • Cryptocurrency Mining – Use victim's CPU to mine crypto
  • Famous Botnets: Mirai (attacked IoT devices), Zeus, Conficker.
  • Defense: Keep software updated, use antivirus, monitor network traffic for unusual behavior.
Conclusion
Botnets are powerful cyber weapons made of infected "zombie" devices. They are behind many of the largest cyber attacks including massive DDoS attacks and global spam campaigns.

Why do mobile devices need security?
Introduction

Mobile phones today store enormous amounts of personal data — banking details, passwords, photos, emails, contacts, and location history. This makes them valuable targets for attackers. Mobile security ensures this data remains safe.

Why Mobile Security is Needed
  • Sensitive Data Storage: Mobiles store banking apps, passwords, personal photos, health data — all of which are high-value targets for cybercriminals.
  • Physical Loss/Theft: Mobile devices are easily lost or stolen. Without security (PIN/biometric), anyone can access all data.
  • Malicious Apps: Fake apps in unofficial app stores can steal data, track location, or show ads (adware). App permissions need to be controlled.
  • Unsecured Wi-Fi: Mobile users often connect to public Wi-Fi where man-in-the-middle attacks are easy. VPNs and HTTPS are essential.
  • SMS Phishing (Smishing): Attackers send fake SMS messages with malicious links.
  • Outdated OS: Unpatched mobile operating systems have known vulnerabilities that attackers exploit.
  • Mobile Payments: With UPI, wallets, and mobile banking, a compromised phone means direct financial loss.
Conclusion
Mobile devices are now mini-computers with access to our most sensitive information. Strong passwords, app permissions management, regular updates, and trusted app stores are essential for mobile security.

Define Authentication and Authorization.
⚡ Concept Booster

Think of entering an office building: Showing your ID to the security guard to prove who you are = Authentication. After entering, only being allowed into certain rooms = Authorization. Authentication always comes first.

Definitions

Authentication is the process of verifying the identity of a user, device, or system — confirming that they are who they claim to be.

Authorization is the process of determining what an authenticated user is allowed to do — which resources they can access and what actions they can perform.

Key Differences
  • Authentication answers: "Who are you?" — Authorization answers: "What can you do?"
  • Authentication methods: Passwords, OTP, biometrics (fingerprint, face), security tokens, certificates.
  • Authorization methods: Access Control Lists (ACL), Role-Based Access Control (RBAC), permissions.
  • Order: Authentication always happens before authorization.
  • Example: You log in to Gmail (Authentication). After login, you can only access your emails, not someone else's (Authorization).
  • Multi-Factor Authentication (MFA): Combines two or more authentication factors (password + OTP) for stronger security.
Conclusion
Authentication verifies identity; authorization controls access. Together they form the foundation of access management. Both are essential for secure systems — you must first prove who you are, then be given only the rights you need.

Explain digital evidence.
⚡ Concept Booster

Digital Forensics is the process of collecting, analyzing, and preserving electronic evidence for use in legal investigations. Just like physical crime scenes leave fingerprints, digital crime leaves behind digital traces.

Definition

Digital Evidence is any data or information that is stored or transmitted in digital form and can be used in a court of law to prove or disprove facts in a legal investigation or criminal case.

Key Points
  • Sources of Digital Evidence:
    • Computer hard drives, USB drives, SD cards
    • Emails, chat messages, social media posts
    • Browser history and cookies
    • CCTV footage, GPS location data
    • Log files from servers and applications
    • Mobile phone data (call logs, messages, photos)
  • Properties of Good Digital Evidence: It must be Authentic (not tampered), Complete (not partial), Reliable, and Believable.
  • Chain of Custody: Proper documentation of who collected, handled, and analyzed the evidence to ensure it is admissible in court.
  • Challenges: Digital evidence is fragile — it can be easily deleted, modified, or encrypted. Special forensic tools (like FTK, Autopsy, EnCase) are used to extract and preserve it without altering the original.
Conclusion
Digital evidence is crucial in modern cyber crime investigations. Its integrity must be carefully preserved through proper collection, handling, and chain of custody to be valid in legal proceedings.

Why is cyber security needed?
Introduction

Cyber Security is the practice of protecting computers, networks, systems, and data from digital attacks, unauthorized access, and damage. In today's digital world, almost everything — banking, healthcare, government, communication — runs on digital systems, making cyber security absolutely essential.

Why Cyber Security is Needed
  • Protection of Personal Data: Billions of users store personal information (Aadhaar, banking, health records) online. Without security, this data can be stolen and misused.
  • Financial Security: Online banking, UPI, and e-commerce are widespread. Cyber attacks cause massive financial losses to individuals and businesses. (Global cybercrime damages exceed trillions of dollars annually.)
  • National Security: Critical infrastructure like power grids, defense systems, water treatment plants, and communication networks are digitally controlled. Cyber attacks on these can cause national disasters.
  • Business Continuity: A cyber attack (ransomware, DDoS) can shut down a business completely. Cyber security ensures operations continue without disruption.
  • Privacy Protection: Prevents surveillance, stalking, and unauthorized monitoring of individuals.
  • Increasing Cyber Threats: Cyber attacks are increasing in frequency and sophistication every year — making security more important than ever.
  • Legal Compliance: Organizations must follow data protection laws (GDPR, IT Act 2000) to protect user data. Cyber security ensures compliance.
Conclusion
Cyber security is not optional in the modern world — it is a necessity. As our dependence on digital systems grows, so does the responsibility to protect them from ever-evolving threats. A secure cyberspace is essential for individuals, businesses, and nations alike.
