Q1 Define Turing Machine and construct TM for L = {aⁿbⁿ | n > 0} 7 marks

Definition of Turing Machine

📖 Definition

A Turing Machine (TM) is a theoretical computer invented by Alan Turing in 1936. Think of it as a robot reading/writing symbols on an infinite strip of tape, changing its internal "mood" (state) as it goes. It is the most powerful computational model — anything computable can be computed by a TM.

Formal Definition — 7-Tuple

Remember as: "Q Σ Γ δ q₀ B F" → "Queens Σing Γames δelight q₀ur Best Friends"

Q = States (all possible "moods" of the machine) Σ = Input alphabet (letters you feed the machine; no blank) Γ = Tape alphabet (all symbols on tape; Σ ⊆ Γ, includes blank B) δ = Transition function: (state, symbol) → (new state, new symbol, L or R) q₀ = Start state B = Blank symbol (marks empty cells; B ∈ Γ but B ∉ Σ) F = Accepting states (reaching any of these = ACCEPT)
📼
Infinite Tape
Unlimited memory — cells stretch infinitely left and right. Starts blank except for input.
🖊️
Read/Write Head
Sits on one cell at a time. Reads the symbol, writes a new one, then moves Left or Right.
🔄
State Control
Finite "memory" of states. δ decides: given current state + symbol → what to do next.
✅
Accept/Reject/Loop
Enters qaccept → accepts. Enters qreject → rejects. Keeps running → loops forever.
Construction for L = {aⁿbⁿ | n > 0}

TM for L = {aⁿbⁿ | n > 0} — "Cross-matching" Strategy

Core Idea 💡

Cross out one 'a' and one 'b' at a time. Keep repeating until nothing is left (accept) or counts don't match (reject). Use X to mark used a's and Y to mark used b's.

1
Cross an 'a': From the left, find the first 'a'. Replace it with X (it's now "used").
2
Cross a 'b': Scan right (skipping a's and Y's) to find the first 'b'. Replace it with Y.
3
Go back: Move left past everything until you reach the leftmost X, then go right to find the next 'a'.
4
Repeat: Keep crossing a's and b's one-by-one.
5
Accept: When q0 sees Y (no more a's left), scan right — if only Y's remain, ACCEPT.
6
Reject: Ran out of b's while a's remain, or b's remain after all a's matched → REJECT.

States (What Each State Means)

Q = {q0, q1, q2, q3, qaccept, qreject} Σ = {a, b} Γ = {a, b, X, Y, B} q0 → Scan right, looking for next 'a' to cross q1 → Found 'a' (now X); scan right to find matching 'b' q2 → Found 'b' (now Y); scan left to return to start q3 → All a's matched; check no b's remain

Q2 Short notes: (i) Halting Problem   (ii) Recursive Language   (iii) Variants of TM 7 marks
Part (i)The Halting Problem
📖 Definition

The Halting Problem asks: "Given any TM M and input w, will M eventually stop, or run forever?" Turing proved in 1936 that no algorithm can answer this for all M and w. It is the most famous unsolvable problem in computer science.

Proof by Contradiction — "The Liar's Trick"

1
Pretend H exists: Assume TM H is a magic oracle — H(M,w) = YES if M halts on w, NO if M loops forever.
2
Build the Trouble-maker D: Construct TM D using H. D(⟨M⟩): if H says "M halts on ⟨M⟩" → D loops. If H says "M loops" → D halts. D does the opposite of what H predicts.
3
Run D on itself — Paradox:
• If D halts on ⟨D⟩ → H says YES → D must loop → contradiction!
• If D loops on ⟨D⟩ → H says NO → D must halt → contradiction!
4
Conclusion: Both cases are impossible → H cannot exist → Halting Problem is undecidable.
⚠️ Key Result — Memorize This

Halting Problem is RE but NOT Recursive. A TM can recognize it (accept if M halts) but cannot decide it (cannot always reject if M loops). It was the first proven undecidable problem.

Part (ii)Recursive Language
📖 Definition — "Always Gives an Answer"

A language L is Recursive (Decidable) if a TM exists that always halts — it never loops.
• w ∈ L → TM halts and accepts
• w ∉ L → TM halts and rejects
Think of it as a reliable "yes/no" machine with no "maybe".

Key Properties — Quick Recall

  • Closed under everything: union, intersection, complement, concatenation, Kleene star.
  • If L is recursive → L̄ (complement) is also recursive. This is the big difference from RE.
  • Every regular language and every CFL is automatically recursive.
  • Recursive ⊂ RE (recursive is a smaller, "nicer" class).

Q3 Define PCP and Modified PCP with Applications 7 marks

Post's Correspondence Problem (PCP)

📖 Definition — "Domino Matching Game"

Proposed by Emil Post in 1946. You have two lists of strings A and B. You need to pick a sequence of indices (repeats allowed) so that reading A's strings top-to-bottom and B's strings bottom-to-top gives the same concatenated string. If no such sequence exists — you can never know for certain. PCP is undecidable.

Formal Definition

Given two lists of strings over alphabet Σ:

A = [w₁, w₂, ..., wₙ] ← Top strings B = [v₁, v₂, ..., vₙ] ← Bottom strings Find indices i₁, i₂, ..., iₖ (k ≥ 1, repeats OK) such that: w(i₁)·w(i₂)·...·w(iₖ) = v(i₁)·v(i₂)·...·v(iₖ) This matching sequence is called the "solution."

Example — PCP Instance

IndexA (Top)B (Bottom)
1aaaa
2aabab
3bb

Try sequence: 1, 2, 3 →

Top: a · aab · b = aaabb Bot: aaa · ab · b = aaaabb ✗ Try sequence: 2, 1, 3 → Top: aab · a · b = aabab Bot: ab · aaa · b = abaab ✗ Try sequence: 1, 1, 2, 3 → Top: a · a · aab · b = aaaabb Bot: aaa · aaa · ab · b = aaaaaabb ✗ Many PCP instances have no solution — and we CANNOT determine this in general.
⚠️ Why Undecidable?

PCP is undecidable — proved by reducing the Halting Problem to PCP. If you could solve PCP, you could solve the Halting Problem — but that's impossible. So PCP is impossible too.

Modified PCP (MPCP)

Modified PCP (MPCP) — "Must Start with Pair 1"

📖 Definition

MPCP is PCP with one extra rule: the solution must begin with index 1 (i₁ = 1 is forced). This "smaller" problem is still undecidable. Its purpose: MPCP is proved undecidable first (from Halting Problem), then used to prove PCP undecidable.

Proof Chain — How Undecidability Flows

1
Halting Problem is undecidable (Turing, 1936).
2
Reduce Halting Problem → MPCP: encode TM computation as MPCP pairs. MPCP has a solution iff TM accepts. So MPCP is undecidable.
3
Reduce MPCP → PCP: use a star-symbol (★) encoding to transform any MPCP into an equivalent PCP. So PCP is undecidable.
4
Chain: Halting → MPCP → PCP. All three are undecidable.

Applications of PCP

  • Proving other problems undecidable: PCP is a go-to tool — reduce PCP to the new problem to show it's undecidable.
  • CFG ambiguity: Determining if a context-free grammar is ambiguous is proved undecidable via PCP.
  • CFL intersection: Checking if two CFLs share a word is proved undecidable via PCP.
  • Formal verification: String matching under constraints appears in compiler theory.
✅ Conclusion — Quick Summary

PCP: Pick indices freely, match top = bottom. MPCP: Same, but must start at index 1. Both are undecidable. Proof chain: Halting Problem → MPCP → PCP. Used everywhere to prove other problems undecidable.

Q4 Design TM for language L = {aⁿ⁺²bⁿ | n > 0} 7 marks

Language L = {aⁿ⁺²bⁿ | n > 0} — "Always 2 Extra a's"

📖 Language Description

The count of a's is always exactly 2 more than the count of b's. Examples: aaab (3 a's, 1 b, n=1), aaaabb (4 a's, 2 b's, n=2), aaaaabbb (5 a's, 3 b's, n=3).

💡 Core Insight — The Simple Plan

First, cross out the 2 "extra" a's unconditionally. Then match the remaining a's with b's one-to-one (like the aⁿbⁿ TM). Simple!

Algorithm — Two Phases

1
Phase 1 — Kill the extras: Mark the first 'a' as X (q0→q1), then mark the second 'a' as X (q1→q2). If fewer than 2 a's exist → reject immediately.
2
Phase 2 — Standard matching: From q2, match each remaining 'a' with a 'b' one-to-one (just like aⁿbⁿ TM).
3
Accept: After all a's are matched, only X's and Y's remain → accept.
4
Reject: Any leftover unmatched a or b → reject.

States (What Each Means)

Q = {q0, q1, q2, q3, q4, q5, qaccept, qreject} Σ = {a, b} Γ = {a, b, X, Y, B} q0 → Mark first 'a' as X (Phase 1, step 1) q1 → Mark second 'a' as X (Phase 1, step 2) q2 → Look for next 'a' to match (Phase 2 start) q3 → Move right to find matching 'b' q4 → Found 'b'; move left to return to q2 q5 → Verify no b's remain (accept check)

Q5 Design TM for language L = {aⁿbⁿcⁿ | n ≥ 1} 7 marks

Language L = {aⁿbⁿcⁿ | n ≥ 1} — The Classic Non-CFL

📖 Why This Language is Famous

{aⁿbⁿcⁿ} is the poster child for "TM can do it but PDA cannot." A PDA has only one stack and can count two things (a vs b) but not three simultaneously. A TM can count all three with ease. It's a recursive (decidable) language.

Strategy — Three-Symbol Cross-Match 💡

Use markers: X for used a's, Y for used b's, Z for used c's. In each round, cross one a, one b, and one c simultaneously.

1
Find leftmost unmarked 'a' → replace with 'X'. Enter state q1.
2
Scan right (skip a's and X's) → find leftmost unmarked 'b' → replace with 'Y'. Enter state q2.
3
Scan right (skip b's and Y's) → find leftmost unmarked 'c' → replace with 'Z'. Enter state q3.
4
Scan all the way left back to the leftmost X → enter q0 for next round.
5
Accept: When q0 sees Y (no more a's), scan right through all Y's and Z's — if blank reached, ACCEPT.
6
Reject: Any mismatch (extra a, b, or c without a match) → REJECT.

States Summary

q0 : Scan right for 'a' → mark X. If sees Y → all a's done, go to q4. q1 : Skip a's/X's, find 'b' → mark Y. No 'b' found → reject. q2 : Skip b's/Y's, find 'c' → mark Z. No 'c' found → reject. q3 : Move ALL the way left back to X → restart q0. q4 : Scan Y's. When Z found → enter q5. q5 : Scan Z's. Blank → ACCEPT. Extra c → REJECT.

Q6 Explain Recursive and Recursively Enumerable Languages 7 marks

Recursive (Decidable) Languages — "Always Gives an Answer"

📖 Definition

A language L is Recursive if a TM M exists that always halts (never loops) and:
• w ∈ L → M accepts (halts in accept state)
• w ∉ L → M rejects (halts in reject state)
Think of it as a machine with a guaranteed "yes or no" — no "maybe forever."

Key Properties — Quick Recall

  • Closed under all standard operations: union, intersection, complement, concatenation, Kleene star.
  • If L is recursive → L̄ is also recursive (flip accept/reject states). This does NOT hold for RE.
  • Every Regular language and every CFL is automatically recursive (they are "subsets").
  • Recursive ⊂ RE — recursive is the "nice" inner circle of RE.

Examples

L = {aⁿbⁿcⁿ | n≥1} All CFLs All Regular Languages L = {ww | w∈{a,b}*} {aⁿbⁿ | n≥0}
Recursively Enumerable Languages

Recursively Enumerable (RE) Languages — "Confirms Yes, Maybe Not No"

📖 Definition

A language L is Recursively Enumerable (RE) if a TM M exists where:
• w ∈ L → M eventually accepts (halts with yes)
• w ∉ L → M either rejects OR loops forever (you may never know!)
Also called "semi-decidable" or "Turing-recognizable."

Key Properties — Quick Recall

  • Closed under union, intersection, concatenation, Kleene star.
  • NOT closed under complement — this is the key difference from Recursive!
  • If both L and L̄ are RE → L is actually Recursive (upgrade!).
  • RE languages can be "listed" (enumerated) by a TM — it eventually prints every member of L.

Examples

Q7 Explain PCP Problem and Modified PCP Problem 7 marks

This question is a deeper version of Q3. Full PCP definition and examples are in Q3. Below is the key proof content for exam.

Proving PCP Undecidable — The Reduction Chain

Step 1: Halting Problem → MPCP (MPCP is Undecidable)

1
Given any TM M and input w, build an MPCP instance that encodes M's computation on w.
2
The pairs simulate M's transition steps. A valid "match" in MPCP = a valid accepting computation path of M on w.
3
MPCP has a solution ⟺ M accepts w. Since "M accepts w" is undecidable (Halting Problem), MPCP is undecidable.
4
MPCP is proved undecidable — we cannot determine in general if a forced-start-at-1 solution exists.

Step 2: MPCP → PCP (PCP is Undecidable)

Transform any MPCP instance into PCP using star (★) symbol encoding:

For each pair (wᵢ, vᵢ) in MPCP, create modified PCP pairs: Top: insert ★ after each character → ★w[1]★w[2]...★w[k] Bot: insert ★ before each character → v[1]★v[2]★...v[k]★ Add a special "first pair" that forces the PCP solution to start at index 1. Add a terminating pair (★, ★) to finish cleanly. Result: PCP solution starting with the special pair ⟺ MPCP solution starting at index 1.

Q8 Explain Turing-Church Thesis and Recursively Enumerable Languages 7 marks

Church-Turing Thesis — "TM = Computation"

📜 Statement (Not a Theorem — A Belief!)

"Any function that can be computed by any well-defined step-by-step procedure (algorithm) can also be computed by a Turing Machine."
In short: Turing Machine = the most powerful possible computer.

Historical Background

  • Alonzo Church (1936): Proposed λ-calculus. Defined "computable" as "lambda-definable."
  • Alan Turing (1936): Independently proposed TM. Proved it equivalent to λ-calculus.
  • Kurt Gödel: Defined recursive functions — also proved equivalent to TM.
  • All three models turned out to compute exactly the same functions. This convergence gave us confidence the thesis is true.

Equivalent Models — All Equally Powerful as TM

λ
Lambda Calculus
Church's model. Function abstraction and application. Foundation of functional programming.
🔢
Recursive Functions
Gödel's model. Built from primitive recursive functions + minimization operator (μ).
🖥️
RAM Model
Models real computers (registers, memory). Equivalent to TM in power.
📼
Turing Machine
The standard theoretical model. Infinite tape + finite state control.
📝 Critical Exam Point

Church-Turing Thesis is a hypothesis, not a proven theorem. It can't be proved mathematically because "effective algorithm" isn't formally defined. But no counterexample has ever been found in 90 years.

Why It Matters

  • If a problem has no TM solution → it has no algorithmic solution at all (in any language, on any hardware).
  • Establishes TM as the universal yardstick for "what is computable."
  • Explains why Halting Problem is truly unsolvable — not just hard, but impossible.
  • Modern computers are TM-equivalent (same functions, just faster with finite resources).
Recursively Enumerable Languages

Recursively Enumerable Languages — Detailed

📖 Definition

L is Recursively Enumerable (RE) if a TM M exists such that:
• w ∈ L → M halts and accepts
• w ∉ L → M rejects OR loops forever
Also called semi-decidable or Turing-recognizable.

Four Key Characterizations

  • L is RE ⟺ L is Type-0 in Chomsky hierarchy (unrestricted grammar).
  • L is RE ⟺ some TM can enumerate (list) all strings of L eventually.
  • L is RE AND L̄ is RE ⟺ L is Recursive (upgrade to decidable).
  • Recursive ⊂ RE: every recursive language is RE, not vice versa.

✅ Conclusion

Church-Turing Thesis: TM is the ultimate model of computation — anything any algorithm can do, a TM can too. RE languages are those a TM can "recognize" but not necessarily "decide." Together these define the theoretical ceiling of what computing can and cannot do.

Q9 Short notes: (i) TM as Computer of Integer Functions   (ii) Universal Turing Machine 7 marks
Part (i)TM as Computer of Integer Functions
📖 Definition

A TM can compute number functions, not just accept/reject strings. Give it integers as input (encoded on tape), and it computes the output and leaves it on the tape. If you think of it as a calculator on an infinite strip of paper — that's TM as an integer function computer.

How Integers Are Represented — Unary (Tally Marks)

Integer n is stored as (n+1) ones. Multiple arguments are separated by 0:

Integer n is represented as n+1 ones: 0 → 1 (one tally) 1 → 11 (two tallies) 2 → 111 (three tallies) 3 → 1111 (four tallies) Multiple arguments separated by '0': f(2, 3) → tape: 111 0 1111 ↑2 ↑3

Types of Functions TM Can Compute

  • Total Function: Defined for ALL inputs. TM always halts and outputs the result. e.g., f(n) = n+1.
  • Partial Function: Defined for SOME inputs only. TM may loop on undefined values. e.g., integer division (undefined when divisor = 0).
  • A function is Turing-computable if any TM can compute it.

Example: Successor — f(n) = n+1 (simplest TM function)

Input: 1ⁿ⁺¹ (n+1 ones for integer n) Action: Simply scan right past all 1's, write one more '1' at the end. Output: 1ⁿ⁺² (representing n+1) TM: q0 sees 1 → move R. Sees B → write 1, halt.

Example: Addition — f(m, n) = m + n

Input: 1^(m+1) 0 1^(n+1) [two groups of tallies separated by 0] Steps: 1. Change the '0' separator to '1' (merges both groups into one) 2. Erase the last '1' (correction for the extra 1 in unary) Output: 1^(m+n+1) representing m+n
Part (ii)Universal Turing Machine (UTM)
📖 Definition — "The Master TM"

A Universal Turing Machine (UTM) is a TM U that can simulate any other TM M on any input w. You give UTM the code of M (written as a string ⟨M⟩) plus input w, and UTM runs M on w — accepting iff M would accept, looping iff M would loop. UTM is the theoretical ancestor of the modern computer.

How UTM Works

Figure 4: Universal Turing Machine — Simulates any TM M on input w

How UTM Works — Three Tapes

1
Tape 1 — M's description: Stores the encoded TM M (its states, alphabet, transitions written as binary strings).
2
Tape 2 — The actual input w: This is M's working tape. UTM reads/writes here while simulating M.
3
Tape 3 — Current state of M: Tracks what state M is in at each step of the simulation.
4
Each simulation step: Read state (Tape 3) + symbol (Tape 2) → look up transition in ⟨M⟩ (Tape 1) → write new symbol, move head on Tape 2, update state on Tape 3.
5
Terminate: When M reaches qaccept or qreject → UTM does the same. If M loops → UTM loops.

Why UTM is Revolutionary

  • UTM = programmable computer. One machine, but it can run any program (encoded TM). Basis of von Neumann architecture.
  • Proves TMs are closed under simulation — a TM can simulate itself.
  • L(UTM) = {⟨M,w⟩ | M accepts w} is RE but NOT Recursive.
  • Used to prove Halting Problem undecidable — if UTM could solve halting, you'd have a contradiction.
  • Foundation of interpreters — one interpreter can run any code.
✅ Conclusion

TM computes integer functions using tally (unary) encoding. UTM is the "TM of TMs" — feeds it the code of any machine and it simulates it. This makes UTM the theoretical blueprint for all programmable computers. L(UTM) is RE but undecidable — the Halting Problem in disguise.

Deterministic vs Non-Deterministic TM

📖 DTM — "One Choice Only"

In a Deterministic TM (DTM), each (state, symbol) pair has exactly one possible next move. δ: Q × Γ → Q × Γ × {L, R} is a function. The computation is a straight line — one path, no branches.

📖 NTM — "Explore All Paths Simultaneously"

In a Non-Deterministic TM (NTM), each (state, symbol) pair can have multiple possible next moves. δ: Q × Γ → P(Q × Γ × {L, R}) is a relation. The computation is a tree — NTM explores all branches in parallel. Accepts if any one branch accepts.

TM for L = {ww | w ∈ (a+b)*} — "A String Repeated Twice"

📖 Language Description

L contains all strings that are exactly some string w concatenated with itself. Examples: aa, bb, abab, babaabab, aabbaabb... The length must be even and both halves must be identical. Not context-free (needs TM).

Strategy — Zig-Zag Symbol Matching 💡

Pick one symbol from the front, go find its matching symbol at the "corresponding" position in the second half. Mark both. Repeat until done.

1
Find midpoint: Use "zig-zag" — alternate crossing a symbol at the leftmost uncrossed position and a symbol at the rightmost uncrossed position. When they meet, that's the midpoint.
2
Check even length: If zig-zag crosses meet with no symbols left, length is even. Odd length → reject.
3
Match symbols: Position i in first half must equal position i in second half. Compare each pair.
4
Accept/Reject: All pairs match → accept. Any mismatch → reject.

Simpler 2-Tape Method

1
Copy entire input onto Tape 2.
2
Find midpoint of Tape 1 by scanning length.
3
Compare second half of Tape 1 (left-to-right) with first half of Tape 2 (left-to-right).
4
All match + both exhausted together → accept.

Language L = {a²ⁿbⁿ | n ≥ 1} — "Twice as Many a's as b's"

📖 Language Description

For n ≥ 1, the count of a's is exactly double the count of b's. The a's always come in even count. Examples: aab (2 a's, 1 b, n=1), aaaabb (4 a's, 2 b's, n=2), aaaaaabbb (6 a's, 3 b's, n=3).

💡 Strategy — "Two a's per b"

For every b we encounter, we must cross out exactly two a's. So the TM marks two a's (→ XX) for every one b (→ Y) in each round. Simple extension of the aⁿbⁿ TM.

Algorithm

1

2
In state q1, continue right and mark the second unmarked 'a' with 'X'.
3
In state q2, continue right past remaining a's and X's, skip Y's, and mark the first unmarked 'b' with 'Y'.
4
Move all the way left (state q3) back to find the next pair of a's.
5
Repeat until no unmarked a's remain. Then verify no unmarked b's remain. Accept only if both are exhausted together.

Q12 Explain Universal Turing Machine (UTM) 7 marks

Universal Turing Machine (UTM) — "The Master Simulator"

📖 Definition

A Universal Turing Machine (UTM) is a TM U that, given the encoding ⟨M, w⟩ of any TM M and any input w, simulates M on w exactly:
• U accepts ⟨M,w⟩ ⟺ M accepts w
• U rejects ⟨M,w⟩ ⟺ M rejects w
• U loops on ⟨M,w⟩ ⟺ M loops on w
One machine that can run every other machine — the software computer.

Formal Specification

UTM: U(⟨M, w⟩) simulates M on w Where: ⟨M⟩ = binary encoding of TM M w = input string to M U accepts ⟨M,w⟩ ⟺ M accepts w U rejects ⟨M,w⟩ ⟺ M rejects w U loops on ⟨M,w⟩ ⟺ M loops on w

Encoding a TM M

To represent TM M = (Q, Σ, Γ, δ, q₀, B, F) as a string ⟨M⟩:

1
Encode states: Represent states q₁, q₂, ... as 0¹, 0², 0³, ... (unary encoding using 0s).
2
Encode symbols: Represent tape symbols a₁, a₂, ... similarly in unary.
3
Encode directions: Left = 0, Right = 00.
4
Encode transitions: Each δ(qᵢ, aⱼ) = (qₖ, aₗ, D) encoded as: encode(qᵢ) 1 encode(aⱼ) 1 encode(qₖ) 1 encode(aₗ) 1 encode(D).
5
Concatenate: All transition encodings separated by '11'. Final ⟨M⟩ = all transitions. Then ⟨M,w⟩ = ⟨M⟩ 111 w.

UTM Architecture — Three Tape Design

Figure 6: UTM Three-Tape Architecture

UTM Simulation Algorithm

1
Initialize: Place ⟨M⟩ on Tape 1, w on Tape 2, q₀ on Tape 3.
2
Lookup: Read current state from Tape 3, current symbol from Tape 2. Search Tape 1 for matching transition.
3
Execute: Write the output symbol to Tape 2, move the head on Tape 2, update state on Tape 3.
4
Halt check: If current state (Tape 3) is an accepting state of M → UTM accepts. If rejecting state → UTM rejects.
5
Loop: If M doesn't halt, UTM doesn't halt — correctly simulating M's behavior.

Properties of UTM — 5 Key Points

  • UTM is itself a TM — proves TMs can describe and run other TMs.
  • L(UTM) = {⟨M,w⟩ | M accepts w} is RE but NOT Recursive — the Halting Problem itself!
  • UTM = theoretical basis for stored-program computers (von Neumann architecture).
  • Shows one fixed program can simulate all programs — the idea behind interpreters.
  • UTM is used directly to prove the Halting Problem is undecidable.

UTM vs Actual Computers

✅ Conclusion

UTM is one of the most profound ideas in all of computer science: one machine to run them all. It proves that hardware and software can be separated — the same physical machine (UTM) runs different programs (encoded TMs). Every laptop you use is a physical UTM. Its existence also implies the Halting Problem is unsolvable.

Q13 Explain Variants of Turing Machine 7 marks

Variants of Turing Machine — "Same Power, Different Shape"

📖 The One Thing to Remember

All TM variants (except read-only TM) are computationally equivalent to the standard single-tape TM. They recognize the same class of languages. They differ only in convenience or speed, not in what they can compute. More tapes ≠ more power.

1. Multi-Tape Turing Machine — "Multiple Scratch Pads"

📝 Description

Has k ≥ 2 tapes, each with its own independent read/write head. Transition reads all heads at once and updates all tapes in one step. More convenient for complex tasks (e.g., keep input on Tape 1, do scratch work on Tape 2, store output on Tape 3).

δ: Q × Γᵏ → Q × Γᵏ × {L,R,S}ᵏ where k = number of tapes, S = Stay (optional: don't move this head)
  • Why it's NOT more powerful: Any k-tape TM can be simulated by a 1-tape TM. Store all k tapes on one tape with separator markers. Scan back-and-forth to simulate each head. Overhead: O(t²) time.
  • Used for: UTM (3 tapes), complex constructions.
Figure 7: Multi-Tape TM (3 tapes)

2. Non-Deterministic TM (NTM) — "Explore All Paths at Once"

📝 Description

Each (state, symbol) pair may have multiple next moves. NTM branches into all possibilities simultaneously (computation tree). Accepts if any branch accepts. Rejects only if all branches reject.

  • Simulation: Any NTM → 3-tape DTM using BFS over the computation tree. Time: exponential in NTM's steps.
  • NTM may be exponentially faster than DTM, but recognizes the same languages.
Figure 8: NTM Computation Tree — Accepts if any branch accepts

3. Two-Way Infinite Tape TM

  • Tape extends infinitely in both left and right directions (no left end boundary).
  • Simulated by standard TM by "folding" the tape — one track for the original, one for the reverse direction.
  • Equivalent to standard TM in power.

4. Multi-Head TM

  • One tape with k independent read/write heads that can move simultaneously.
  • Transition reads all k heads at once and updates all of them.
  • More efficient but same power as single-head TM.
  • Simulation: mark head positions on tape; simulate each head movement.

5. Two-Dimensional (2D) TM

  • Tape is a two-dimensional infinite grid (like an infinite chessboard).
  • Head can move Up, Down, Left, or Right.
  • Still equivalent to standard TM (2D grid encoded as 1D tape).

6. Read-Only TM (Two-Way FA)

  • Head can only read, never write. It can move left or right on input.
  • This variant is equivalent to a Finite Automaton (DFA/NFA).
  • Less powerful than standard TM.

Q14 Explain Recursive and Recursively Enumerable Languages (Complete) 7 marks

Recursive Languages — Complete Treatment

📖 Definition — "The Yes/No Machine"

A language L is Recursive (Decidable) if a TM M exists where:
• w ∈ L → M halts and accepts
• w ∉ L → M halts and rejects
M is called a decider — it always gives a verdict, never gets stuck in an infinite loop.

Characteristics — What Makes It "Recursive"

  • TM is guaranteed to always halt on any input — it's a total function.
  • There is a real program (algorithm) that solves membership in L with certainty.
  • Also called Turing-decidable or totally computable.

Closure Properties of Recursive Languages

Intersection (L₁ ∩ L₂)YesRun M₁ then M₂. Accept iff both accept.
Complement (L̄)YesSwap accept/reject states of M. M always halts.
ConcatenationYesTry all splits of w; check each part. Enumerate splits.
Kleene StarYesEnumerate decompositions; check each.

Recursively Enumerable Languages — Semi-Decidable

📖 Definition — "The Maybe Machine"

A language L is Recursively Enumerable (RE) if a TM M exists where:
• w ∈ L → M eventually halts and accepts
• w ∉ L → M rejects OR loops forever (you may never know which!)
Also called Turing-recognizable or partially decidable.

Characterizations — Four Ways to Identify RE

  • L is RE ⟺ L is generated by an unrestricted (Type-0) grammar.
  • L is RE ⟺ some TM can enumerate all strings in L (print them one by one).
  • L is RE AND L̄ is RE ⟺ L is Recursive.
  • Recursive ⊂ RE — every recursive language is also RE.

Key Theorems — Must Know

📜 Theorem 1 — The Golden Rule

L is Recursive ⟺ BOTH L and L̄ are Recursively Enumerable.
Intuition: If you can "recognize yes" AND your complement can "recognize no" — together you can always decide.

📜 Theorem 2 — The Famous Example

The Halting Problem is RE but NOT Recursive. Its complement (the "non-halting" problem) is NOT even RE.
This is WHY complement closure fails for RE — because L̄(Halting) is not RE.

📜 Theorem 3 — The Subset Relationship

Every Recursive language is RE, but NOT every RE language is Recursive.
Recursive ⊂ RE ⊂ All Languages.

✅ Final Conclusion

Recursive languages are those for which a TM always terminates with a definite answer (yes/no). RE languages are those for which a TM can confirm membership but may loop forever on non-members. The distinction is fundamental to computability theory and defines the limits of what computers can solve. Problems outside RE are absolutely unsolvable by any computational model.
