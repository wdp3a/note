01
Explain DoS attacks and various mitigation techniques.
▼
🔵 Introduction

A Denial of Service (DoS) attack is a cyber attack that makes a machine or network resource unavailable to legitimate users by overwhelming it with traffic or requests. The goal is NOT to steal data, but to crash or slow down the service.

📌 Simple analogy: Imagine 1000 people calling a restaurant's phone line at once — no real customer can get through.
🟢 Types of DoS Attacks

1. Volume-Based Attacks

  • Flood the bandwidth with massive traffic
  • Examples: UDP Flood, ICMP Flood (Ping Flood), Amplification attacks

2. Protocol Attacks

  • Exploit weaknesses in Layer 3/4 protocols
  • Examples: SYN Flood, Ping of Death, Smurf Attack

3. Application Layer Attacks

  • Target web application layer (Layer 7)
  • Examples: HTTP Flood, Slowloris

4. DDoS (Distributed DoS)

Attack launched from multiple compromised machines (botnet) simultaneously — much harder to stop than regular DoS.

Attack TypeTargetMethod
SYN FloodTCP handshakeIncomplete 3-way handshake
UDP FloodBandwidthMassive UDP packets
Smurf AttackNetworkSpoofed ICMP broadcast
HTTP FloodWeb serverFake GET/POST requests
SlowlorisWeb serverKeep connections open slowly
📊 Diagram – DDoS Attack Flow
🟢 Mitigation Techniques
  1. Rate Limiting: Limit number of requests from a single IP per second.
  2. Firewall Rules: Block suspicious IPs and unusual traffic patterns.
  3. Ingress Filtering: Block packets with spoofed source IP addresses.
  4. Load Balancers: Distribute incoming traffic across multiple servers.
  5. DDoS Protection Services: Use services like Cloudflare, AWS Shield to absorb attack traffic.
  6. SYN Cookies: Protect against SYN Flood by not allocating resources until handshake completes.
  7. Black-hole Routing: Route attack traffic to a "null" interface — drops all malicious packets.
  8. Anycast Diffusion: Spread traffic across distributed servers worldwide.
🔴 Important Exam Points
  • DoS = single source; DDoS = multiple sources (botnet)
  • SYN Flood exploits TCP 3-way handshake
  • Smurf attack uses spoofed ICMP + broadcast
  • Slowloris keeps connections open with partial HTTP headers — hard to detect
  • Common trap: DoS doesn't steal data, only disrupts availability

🔵 Introduction

Real-world protocols are standardized rules and procedures used by computers to communicate securely over networks. They define how data is formatted, transmitted, and authenticated.

TLS – How It Works (Real-World Steps)

  1. Client sends ClientHello (supported cipher suites, TLS version)
  2. Server responds with ServerHello + digital certificate
  3. Client verifies server certificate with CA (Certificate Authority)
  4. Client sends pre-master secret encrypted with server's public key
  5. Both derive session keys from pre-master secret
  6. Secure encrypted channel established — data transferred safely

IPSec – Two Modes

  • Transport Mode: Encrypts only payload (data)
  • Tunnel Mode: Encrypts entire IP packet — used in VPNs

SSH – Steps to Use

  1. Client initiates TCP connection to server port 22
  2. Key exchange (Diffie-Hellman) to establish shared secret
  3. Server authenticates using host key
  4. User authenticates (password or public key auth)
  5. Encrypted shell session begins
🔴 Important Exam Points
  • TLS replaced SSL — TLS 1.3 is current standard
  • IPSec uses AH (Authentication Header) and ESP (Encapsulating Security Payload)
  • SSH default port = 22, HTTPS = 443
  • Kerberos uses tickets and KDC (Key Distribution Center)
  • PGP uses both symmetric + asymmetric encryption (hybrid)

03
What is DNS? Explain DNS working, DNS cache poisoning and DNS security.
▼
🔵 Introduction

DNS (Domain Name System) is the Internet's "phone book." It translates human-readable domain names (like google.com) into IP addresses (like 142.250.80.46) that computers use to identify each other.

🟢 DNS Working – Step by Step
  1. User types www.example.com in browser
  2. Browser checks its local DNS cache — if found, done!
  3. Query sent to Recursive Resolver (usually ISP's DNS server)
  4. Resolver queries Root Name Server → gets address of TLD server
  5. Resolver queries TLD Server (.com, .org) → gets address of Authoritative Server
  6. Authoritative Name Server returns the final IP address
  7. Resolver caches result and returns IP to browser
  8. Browser connects to the IP address
📊 DNS Resolution Diagram
🟢 DNS Cache Poisoning

Definition: An attacker injects fake/malicious DNS records into a resolver's cache, redirecting users to malicious websites without their knowledge.

How it Works:

  1. Attacker sends many fake DNS responses to the resolver before the real response arrives
  2. If fake response is accepted, malicious IP is cached
  3. Users asking for bank.com are redirected to attacker's fake site
  4. Users enter credentials on fake site → Credential Theft!
⚠️ Also called DNS Spoofing. Used for Phishing attacks.
🟢 DNS Security (DNSSEC)
  • DNSSEC adds digital signatures to DNS records
  • Resolver can verify the response is authentic and untampered
  • Uses public key cryptography — zone signing keys (ZSK) and key signing keys (KSK)
  • DNS over HTTPS (DoH): Encrypts DNS queries inside HTTPS
  • DNS over TLS (DoT): Encrypts DNS traffic using TLS
ThreatSolution
Cache PoisoningDNSSEC (digital signatures)
EavesdroppingDoH / DoT (encryption)
DDoS on DNSAnycast routing + rate limiting
🔴 Important Exam Points
  • DNS runs on UDP port 53 (TCP for large responses)
  • TTL (Time To Live) determines how long DNS cache holds a record
  • Cache poisoning = Kaminsky Attack (famous 2008 attack)
  • DNSSEC does NOT encrypt, only authenticates

04
Explain Routing Security.
▼
🔵 Introduction

Routing Security deals with protecting the routing infrastructure of the Internet from attacks that could redirect, intercept, or disrupt data packets. Routers exchange routing information using protocols like BGP, OSPF, RIP.

🟢 Routing Attacks

1. BGP Hijacking

An attacker advertises false BGP routes, causing internet traffic to be redirected through their networks. Famous example: Pakistan Telecom hijacking YouTube (2008).

2. Route Injection / Spoofing

Injecting false routing updates into routing protocols to create black holes or redirect traffic.

3. Route Flapping

Repeatedly adding/removing routes causing instability and service disruption.

4. Man-in-the-Middle via Routing

Attacker inserts malicious router in path to intercept all data.

AttackProtocol AffectedImpact
BGP HijackingBGPTraffic redirection, blackholing
OSPF SpoofingOSPFFalse routes, loops
RIP SpoofingRIPRoute poisoning

Routing Security Measures

  • Route Filtering: Only accept routes from trusted neighbors
  • Authentication: MD5/SHA authentication for routing protocols
  • BGPsec: Cryptographic path validation for BGP
  • RPKI (Resource Public Key Infrastructure): Associates IP prefixes with authorized ASes
  • IRR (Internet Routing Registry): Validates announced routes
  • Prefix Limits: Limit number of prefixes per neighbor
  • Private AS filtering: Block routes with private AS numbers
🔴 Important Exam Points
  • BGP = Border Gateway Protocol = Internet's routing protocol
  • BGP Hijacking → traffic goes through wrong AS (Autonomous System)
  • RPKI = most important modern fix for BGP security
  • OSPF uses MD5 authentication to prevent spoofing
⚡ Quick Revision
BGP Hijack = Redirect RPKI = Key fix Route Filter = Defense Auth = MD5/SHA

What are the benefits of HTTPS and why is HTTPS not used for all web traffic?
▼
🔵 Introduction

HTTPS (HyperText Transfer Protocol Secure) = HTTP + TLS/SSL encryption. It ensures secure communication between browser and web server. The lock icon 🔒 in browsers indicates HTTPS.

🟢 Benefits of HTTPS
#BenefitExplanation
1EncryptionData in transit is encrypted — no eavesdropping
2AuthenticationVerifies server identity via digital certificate
3Data IntegrityDetects tampering — data cannot be altered en route
4TrustUsers see padlock — increases confidence
5SEO BenefitGoogle ranks HTTPS sites higher
6Prevents MitMNo man-in-the-middle attacks possible
7ComplianceRequired for PCI-DSS, GDPR compliance
🟢 Why HTTPS Is Not Used Everywhere
  • 🔴 Performance Overhead: TLS handshake adds latency; encryption/decryption uses more CPU
  • 🔴 Cost: SSL certificates (especially EV certs) cost money (though Let's Encrypt is free)
  • 🔴 Configuration Complexity: Proper setup requires expertise
  • 🔴 Legacy Systems: Old IoT devices, embedded systems can't handle TLS
  • 🔴 Internal Networks: Intranet traffic sometimes uses plain HTTP assuming internal security
  • 🔴 Cache Limitations: CDN caches work less effectively with end-to-end encryption
  • 🔴 Certificate Management: Certificates expire, need renewal — operational burden
⚡ Note: Modern trend is "HTTPS Everywhere." Browsers now show warning for HTTP sites.
🔴 Important Exam Points
  • HTTPS = HTTP + TLS (not SSL — SSL is deprecated)
  • HTTPS uses port 443, HTTP uses port 80
  • Three properties: Confidentiality + Integrity + Authentication (CIA)
  • Even with HTTPS, server can still be hacked — HTTPS only protects transit
⚡ Quick Revision
Memory Trick
HTTPS benefits: E-A-I-T = Encryption, Authentication, Integrity, Trust

06
How are vulnerabilities exploited in web applications?
▼
🔵 Introduction

Web application vulnerabilities are weaknesses in the code, configuration, or logic of a web app that attackers exploit to gain unauthorized access, steal data, or disrupt services. OWASP Top 10 lists the most critical ones.

🟢 Key Vulnerabilities and How They're Exploited

1. SQL Injection (SQLi)

  • Attacker inserts malicious SQL code into input fields
  • Example: ' OR 1=1; -- in login form bypasses authentication
  • Fix: Use parameterized queries / prepared statements

2. Cross-Site Scripting (XSS)

  • Attacker injects malicious JavaScript into web pages
  • Runs in victim's browser — steals cookies/sessions
  • Types: Stored XSS, Reflected XSS, DOM-based XSS
  • Fix: Input validation + Output encoding

3. Cross-Site Request Forgery (CSRF)

  • Tricks authenticated user into making unwanted requests
  • Fix: CSRF tokens, SameSite cookies

4. Broken Authentication

  • Weak passwords, session fixation, no account lockout
  • Fix: MFA, strong session management

5. Insecure Direct Object Reference (IDOR)

  • Changing user_id=123 to user_id=124 accesses another user's data
  • Fix: Authorization checks on every request

6. Command Injection

  • Attacker inserts OS commands via input fields
  • Example: ; rm -rf /
  • Fix: Input sanitization, avoid shell execution
VulnerabilityOWASP RankImpact
SQL Injection#3Data theft, auth bypass
XSS#3Session hijacking
Broken Auth#2Account takeover
IDOR#1Unauthorized access
CSRF#10Unwanted actions
🔴 Important Exam Points
  • SQLi = most common and dangerous web attack
  • XSS runs in client browser, not on server
  • CSRF = confused deputy attack
  • OWASP = Open Web Application Security Project
  • WAF (Web Application Firewall) helps block many of these attacks

Describe various types of security threats in detail.

🔵 Introduction

A security threat is any potential danger that could exploit a vulnerability to harm information systems. Threats can be intentional (attacks) or unintentional (accidents, natural disasters).

🟢 Classification of Threats

A. Based on Source

TypeDescriptionExample
Internal ThreatsFrom within the organizationDisgruntled employee, data theft
External ThreatsFrom outside attackersHackers, state actors
UnintentionalAccidental damageWrong email recipient, human error

B. Major Threat Types

1. Malware (Malicious Software)

  • Virus: Attaches to files, spreads when executed
  • Worm: Self-replicates across networks without user action
  • Trojan: Disguised as legitimate software
  • Ransomware: Encrypts files, demands ransom
  • Spyware: Secretly monitors user activity
  • Rootkit: Hides malware at OS/kernel level

2. Social Engineering

  • Phishing: Fake emails trick users into revealing credentials
  • Vishing: Voice phishing via phone calls
  • Smishing: SMS phishing
  • Pretexting: Creating fake scenarios to extract info

3. Network Threats

  • Sniffing: Capturing network packets to read data
  • Spoofing: Faking IP/MAC address
  • Man-in-the-Middle (MitM): Intercepting communication between two parties

4. Physical Threats

  • Theft of hardware, shoulder surfing, tailgating, dumpster diving

5. Advanced Persistent Threats (APT)

Long-term, targeted attacks by skilled adversaries (often nation-states). Stay undetected for months.

🔴 Important Exam Points
  • Worm ≠ Virus: Worm spreads without human action
  • Ransomware = most impactful modern threat (WannaCry, Petya)

What are Rootkits / Knark / LRK v4 trojans? Explain features, types, detection and prevention.
▼
🔵 Introduction

A rootkit is a collection of malicious tools designed to give an attacker persistent, hidden root-level access to a computer. The attacker can control the system while remaining completely invisible to the victim and security tools.

Analogy: A rootkit is like a ghost living in your house — it does things without you ever seeing it.
🟢 Types of Rootkits
TypeLevelDescription
User-modeApplicationModify user-space programs (ls, ps, netstat)
Kernel-modeOS KernelModify kernel — most dangerous, hardest to detect
Bootloader (Bootkit)Boot sectorInfects MBR, loads before OS
HypervisorBelow OSRuns actual OS as VM — very stealthy
FirmwareHardwareHidden in BIOS/UEFI firmware

Knark Rootkit

  • Linux kernel-level rootkit (kernel module / LKM)
  • Hides processes, files, network connections from the OS
  • Uses /proc filesystem manipulation
  • Allows attacker to execute commands remotely

LRK v4 (Linux Rootkit v4)

  • User-mode rootkit — replaces system binaries (ls, ps, who, netstat, etc.)
  • Modified binaries hide attacker's files, processes, connections
  • Installs backdoor sniffer to capture passwords
  • Hides itself from most detection tools

Features of Rootkits (General)

  • Process hiding — attacker processes invisible in ps list
  • File hiding — malicious files invisible in directory listing
  • Network hiding — open ports not shown in netstat
  • Log tampering — removes traces from system logs
  • Backdoor installation — persistent remote access
  • Privilege escalation — gain root/admin access
🟢 Detection Methods
  • Integrity Checking: Use tools like Tripwire to detect modified system files
  • Behavioral Analysis: Monitor unusual system behavior
  • Memory Forensics: Analyze RAM dumps for hidden processes
  • Bootable Antivirus: Scan from clean bootable media (bypasses infected OS)
  • Rootkit Scanners: chkrootkit, rkhunter, GMER
  • Cross-view Analysis: Compare results from multiple tools
🔵 Prevention
  • Keep OS and software updated
  • Use Secure Boot (UEFI) to prevent bootkit installation
  • Least privilege principle — don't run as root
  • Mandatory Access Controls (SELinux, AppArmor)
  • Regular integrity checks of system binaries
  • Strong authentication to prevent initial compromise
🔴 Important Exam Points
  • Rootkit ≠ Virus: rootkit provides access + hiding, not self-replication
  • Kernel-mode rootkit = most dangerous
  • LRK replaces system binaries (user mode)
  • Knark = LKM (Loadable Kernel Module) based rootkit
  • Best detection: boot from clean media
⚡ Quick Revision
Rootkit = Hide + Persist Knark = Kernel LKM LRK = Binary replace Detect: chkrootkit Prevent: Secure Boot

Why do cyber criminals want to own machines?
▼
🔵 Introduction

"Owning a machine" means a hacker has gained full, unauthorized control over a computer. Cyber criminals invest significant effort to compromise and maintain control of victim machines for various profitable and malicious reasons.

🟢 Reasons Why Criminals Want to Own Machines
  1. Botnet Building: Compromised machines become "bots" used for DDoS attacks, spam campaigns, or rented to other criminals (Botnet-as-a-Service)
  2. Data Theft: Steal personal data, credit card numbers, login credentials for financial gain or dark web sale
  3. Ransomware Deployment: Encrypt victim's files and demand cryptocurrency ransom
  4. Cryptocurrency Mining (Cryptojacking): Use victim's CPU/GPU to mine crypto without their knowledge — free computing power
  5. Spam Relay: Send spam/phishing emails through victim's machine to avoid detection
  6. Proxy / Anonymization: Route illegal activities through victim's IP to hide criminal's identity
  7. Corporate Espionage: Steal trade secrets, business plans, intellectual property
  8. Keylogging & Surveillance: Monitor keystrokes, webcam, microphone to gather sensitive info
  9. Click Fraud: Generate fake ad clicks for financial profit
  10. Infrastructure Attack Staging: Use compromised machine as launch point for attacks on other systems

PowerBotnet, DDoSLeverage, extortion
AnonymityProxy routingHide identity
ResourcesCryptojackingFree computing
🔴 Important Exam Points
  • Owned machine = zombie machine in botnet terminology
  • Cryptojacking became popular after 2017 (Bitcoin boom)
  • Criminals prefer "owned" machines over direct attacks — less traceable

10
Explain logout process, its steps and potential problems.
▼
🔵 Introduction

The logout process is the mechanism by which a user ends an authenticated session with a web application. It is a critical security function — improper logout leaves sessions vulnerable to hijacking.

🟢 Steps in a Proper Logout Process
  1. User clicks "Logout" button
  2. Client sends logout request to server (GET/POST to /logout)
  3. Server invalidates/destroys the session on the server side (removes from session store)
  4. Server clears session cookies (Set-Cookie with empty value + expired date)
  5. Server deletes any authentication tokens (JWT, refresh tokens)
  6. Redirect user to login page or homepage
  7. Client-side cleanup: clear localStorage, sessionStorage, clear cached credentials
🟢 Potential Problems with Logout
ProblemDescriptionImpact
Incomplete LogoutCookie deleted client-side but session still active server-sideSession still valid if cookie is recovered
Browser Back ButtonCached pages still visible after logoutSensitive data exposure
JWT InvalidationStateless JWTs can't be easily revokedToken valid until expiry even after logout
Single Sign-On (SSO)Logging out of one app doesn't log out of all appsPartial logout, still vulnerable
Shared ComputersUser forgets to logout on public computersNext user can access account
Session FixationAttacker pre-sets session ID before authenticationSession hijack after logout/login
CSRF on LogoutAttacker forces user to logout via malicious linkDenial of service, disruption

Best Practices

  • Always destroy sessions server-side, not just client-side
  • Use Cache-Control: no-store for sensitive pages
  • Implement session timeouts (idle + absolute)
  • Use CSRF tokens for logout endpoint
  • Implement global logout for SSO systems
🔴 Important Exam Points
  • Most common mistake: deleting cookie client-side only (server session still valid)
  • JWT tokens are stateless — blacklist needed for revocation
  • Add Cache-Control: no-cache, no-store to prevent back-button attacks
⚡ Quick Revision
Server-side invalidation Clear cookies JWT = Hard to revoke Back button = Cache issue SSO partial logout

How are Virtual Operating Systems used on desktops? Explain different approaches.
▼
🔵 Introduction

Virtualization allows running multiple operating systems on a single physical machine. Each virtual OS runs in an isolated environment called a Virtual Machine (VM), managed by a Hypervisor.

Security benefit: Malware in a VM cannot (usually) escape to the host OS — strong isolation.
🟢 Approaches to Desktop Virtualization

1. Type 1 Hypervisor (Bare Metal)

  • Runs directly on hardware, no host OS
  • Examples: VMware ESXi, Hyper-V, Xen
  • Used in enterprise/servers
  • Best performance and security

2. Type 2 Hypervisor (Hosted)

  • Runs on top of a host OS
  • Examples: VirtualBox, VMware Workstation, Parallels
  • Used on desktops for testing, development
  • Easier to set up, slightly less performance

3. OS-level Virtualization (Containers)

  • Shares host OS kernel but isolates processes
  • Examples: Docker, LXC
  • Lightweight — no full OS needed
  • Less security isolation than full VMs

4. Security Applications of VMs

  • Sandboxing: Run suspicious files in isolated VM — malware can't escape
  • Malware Analysis: Analyze viruses safely in disposable VMs
  • Browser Isolation: Run untrusted web browsing in separate VM
  • Honeypots: VMs simulating vulnerable systems to attract and study attackers
  • Snapshot/Rollback: Take VM snapshots before risky operations — roll back if infected
ApproachIsolationPerformanceUse Case
Type 1 HypervisorHighHighEnterprise servers
Type 2 HypervisorHighMediumDeveloper desktop
ContainerMediumVery HighApp deployment
🔴 Important Exam Points
  • VM escape = vulnerability where malware breaks out of VM to host
  • Snapshots are excellent recovery tools after security incidents
  • Containers share kernel — less isolated than VMs
⚡ Quick Revision
Type 1 = Bare metal Type 2 = On host OS Sandbox = Malware isolation Snapshot = Rollback Container = Shared kernel
12
Define confinement principle and discuss confinement approaches at different levels.
▼
🔵 Introduction

The Confinement Principle (proposed by Butler Lampson, 1973) states that a process/program should be restricted to perform only authorized operations and cannot leak information to unauthorized parties. It limits what a program can access.

🟢 Confinement Approaches

1. Physical Confinement

  • Run untrusted code on an isolated, air-gapped machine
  • No network connection, no shared media
  • Impractical for most cases but most secure

2. OS-Level Confinement

  • chroot jail: Restricts process to a subtree of filesystem
  • Sandboxing: Limits syscalls available to a process
  • SELinux / AppArmor: Mandatory Access Control — limits process capabilities
  • Linux Namespaces: Isolate PID, network, filesystem namespaces

3. Virtual Machine Confinement

  • Run untrusted code in a VM with hypervisor isolation
  • VM boundaries prevent escape to host
  • Used in cloud computing for tenant isolation

4. Language-Based Confinement

  • Java sandbox: JVM controls what untrusted code can access
  • WebAssembly sandbox: Browser-level isolation
  • Type-safe languages prevent buffer overflows

5. Cryptographic Confinement

  • Data encrypted so even if extracted, unusable without key
  • DRM systems use this approach
⚠️ Covert Channels: A clever attacker can leak info even in confined systems through timing, power consumption, or storage channels — defeating confinement!
🔴 Important Exam Points
  • Confinement is about limiting access/action, not just authentication
  • Covert channels are the main challenge for confinement
  • chroot jail ≠ complete isolation — just filesystem restriction
  • Lampson's confinement = exam favorite historical reference
⚡ Quick Revision
Lampson 1973 chroot = FS jail VM = Best isolation Covert channel = Leak risk SELinux = MAC

Explain Risk, Vulnerability and Threat in Network Security.
▼
🔵 Introduction

These three terms are the foundation of Information Security Risk Management. They are distinct but interconnected concepts. Understanding them is essential for building any security strategy.

🟢 Definitions and Differences

1. Vulnerability

A weakness or flaw in a system, application, network, or process that can be exploited by a threat.

  • Unpatched software, weak passwords, misconfigured firewall
  • SQL injection flaw, open unnecessary ports

2. Threat

Any potential danger that could exploit a vulnerability to cause harm. A threat is the "who/what" that could attack.

  • Hackers, malware, disgruntled employees, natural disasters
  • Can be intentional or accidental

3. Risk

The probability and impact of a threat successfully exploiting a vulnerability. Risk is what we measure and manage.

Risk = Threat × Vulnerability × Impact
TermDefinitionExampleNature
VulnerabilityWeakness in systemUnpatched Apache serverInternal/Static
ThreatPotential dangerHacker with exploit toolExternal/Dynamic
RiskProbability × ImpactServer being compromisedCalculated value

Threat Agents vs Threat

  • Threat Agent: The entity that carries out the attack (human hacker, worm)
  • Threat: The action/event itself (hacking attempt, infection)

Risk Management Steps

  1. Identify Assets — what needs protection?
  2. Identify Threats — what could go wrong?
  3. Identify Vulnerabilities — how could it go wrong?
  4. Assess Risk — how likely and how bad?
  5. Mitigate Risk — patch, reduce, transfer, or accept
🔴 Important Exam Points
  • A threat without a vulnerability = no risk
  • A vulnerability without a threat = no immediate risk
  • Risk = Threat × Vulnerability × Impact (formula!)
  • CVE (Common Vulnerabilities and Exposures) is global vulnerability database
⚡ Quick Revision
Memory Trick
TVR: Threat attacks → Vulnerability → causes → Risk
Vulnerability = Weakness Threat = Potential danger Risk = T × V × I CVE = Vuln Database

What is Firewall? Explain packet filtering firewall in detail.
▼
🔵 Introduction

A Firewall is a network security device (hardware or software) that monitors and controls incoming/outgoing network traffic based on predefined security rules. It acts as a barrier between trusted internal networks and untrusted external networks.

🟢 Types of Firewalls
TypeLayerHow it works
Packet FilteringNetwork (L3/L4)Inspects packet headers
Stateful InspectionNetwork+TransportTracks connection state
Application Gateway (Proxy)Application (L7)Understands app protocols
Next-Gen Firewall (NGFW)All layersDPI + IPS + App awareness
🟢 Packet Filtering Firewall – In Detail

The simplest and oldest type. Examines each packet independently based on its header information without tracking connection state.

What it Checks (Packet Header Fields):

  • Source IP Address
  • Destination IP Address
  • Source Port
  • Destination Port
  • Protocol (TCP, UDP, ICMP)
  • Flags (SYN, ACK, FIN)

How ACL Rules Work:

Example Firewall Rules (ACL):
DENY any from 10.0.0.0/8 to any port 23 (block Telnet)
PERMIT any from any to 192.168.1.1 port 80 (allow HTTP)
DENY all (default deny)

Advantages:

  • Fast — operates at network layer
  • Simple to configure
  • Low resource consumption
  • Transparent to applications

Disadvantages:

  • Cannot inspect packet content (payload)
  • Vulnerable to IP spoofing
  • Cannot detect fragmented packet attacks
  • No awareness of connection state
  • Cannot understand application-level protocols
📊 Packet Filtering Diagram
🔴 Important Exam Points
  • Packet filtering = stateless (no connection tracking)
  • Stateful inspection = improved version that tracks connection state
  • DMZ (Demilitarized Zone) = network between two firewalls
  • Default deny rule = "deny all" at end of ACL — exam favorite!
⚡ Quick Revision
Firewall = Traffic gate Packet filter = Stateless Checks IP+Port+Protocol Fast but no payload inspect ACL = Allow/Deny rules

Explain how cybercrime originated. State and classify cyber crimes.
▼
🔵 Introduction

Cybercrime refers to criminal activities conducted using computers, networks, or the internet as either tools or targets. The term originated alongside the growth of digital computing and internet connectivity.

Cybercrime follows a structured methodology similar to the Cyber Kill Chain:

  1. Reconnaissance: Gather information about target (OSINT, social media, Google dorking)
  2. Scanning & Enumeration: Port scanning (Nmap), vulnerability scanning, service enumeration

Explain Digital Forensics life cycle.
▼
🔵 Introduction

Digital Forensics is the process of collecting, preserving, analyzing, and presenting digital evidence from computers and networks for use in criminal investigations or legal proceedings. It follows a strict lifecycle to ensure evidence admissibility.

🟢 Digital Forensics Life Cycle – Phases
  1. Identification: Identify potential sources of digital evidence (HDD, RAM, USB, mobile, cloud). Define scope of investigation.
  2. Preservation: Protect evidence from modification or destruction. Create a forensic image/clone using write blockers. Maintain Chain of Custody.
  3. Collection: Acquire physical and logical copies of evidence. Use tools: dd, FTK Imager, Autopsy. Document everything.
  4. Examination: Filter and extract relevant data from acquired evidence. Recover deleted files, extract metadata, parse logs.
  5. Analysis: Analyze extracted data to reconstruct events. Timeline analysis, correlate events, identify attacker's actions.
  6. Documentation: Create detailed, reproducible documentation of findings. Step-by-step methodology must be documented.
  7. Presentation: Present findings in court or to stakeholders. Use clear, non-technical language. Expert testimony if required.
⚠️ Chain of Custody: Documentation of who handled evidence, when and where. Any break in chain can make evidence inadmissible in court.

Key Forensic Principles

  • Locard's Exchange Principle: Every contact leaves a trace
  • Never work on original evidence — always work on forensic copy
  • Verify copy integrity using hash (MD5/SHA-256)
  • Document everything in real-time
🔴 Important Exam Points
  • Chain of Custody = most critical concept in forensics
  • Write blocker prevents modification of evidence during imaging
  • Forensic tools: Autopsy, FTK, EnCase, Volatility (RAM analysis)
  • Volatile data (RAM) should be collected FIRST — it's lost on shutdown
  • 7 phases exam order: IPCEADP
⚡ Quick Revision

🟢 Security Challenges

  7. Malware/Keylogger: Software captures passwords and personal data

What is Steganography? Explain in detail.
▼
🔵 Introduction

Steganography is the practice of hiding secret data within ordinary, non-secret files or messages to avoid detection. Unlike cryptography (which scrambles data), steganography hides the existence of the secret message.

Steganography = Hidden writing (Greek: steganos = covered + graphia = writing)
Crypto makes data unreadable. Stego makes data invisible. They're complementary.
🟢 Types of Steganography
TypeCarrierMethod
Image SteganographyJPEG, PNG, BMPLSB modification (Least Significant Bit)
Audio SteganographyMP3, WAVEcho hiding, phase coding, LSB
Video SteganographyAVI, MP4Hide in frames (image stego per frame)
Text SteganographyText filesExtra spaces, null chars, invisible chars
Network SteganographyTCP/IP packetsUse unused header fields to carry data
Document StegoPDF, DOCXWhite text on white background, tiny fonts

LSB (Least Significant Bit) Technique – Most Common

In an image, each pixel has RGB values (e.g., 11001010). The last bit (LSB) can be changed without visible difference to the human eye.

Original pixel R: 11001010 → After hiding bit '1': 11001011 → No visible change, but secret bit stored!

A 1MP image (1,000,000 pixels × 3 channels) can store ~375,000 bytes of hidden data!

Applications

  • Malicious use: Criminals hide malware instructions, C2 communication, exfiltrate data in images
  • Legitimate use: Digital watermarking, copyright protection, covert communication
  • Intelligence: Spies use stego for covert communication
🟢 Steganalysis (Detection)
  • Visual Analysis: Look for visual anomalies in images
  • Statistical Analysis: Detect LSB modification patterns (Chi-square attack)
  • File Size Analysis: Unusual file size for given image dimensions
  • Tools: StegExpose, StegDetect, binwalk
🔴 Important Exam Points
  • Stego ≠ Encryption — stego hides existence, crypto hides meaning
  • LSB = most popular technique for image stego
  • Terrorists used steganography in images posted to public websites
  • Tools: Steghide, OpenStego, DeepSound (audio)
⚡ Quick Revision
Hides existence of data LSB = Popular method Stego ≠ Crypto Steganalysis = Detection Watermarking = Legit use

What is Email? Explain Email Forensics.
▼
🔵 Introduction

Email (Electronic Mail) is a method of exchanging digital messages over computer networks. It uses protocols like SMTP (sending), POP3/IMAP (receiving) to transmit messages.

Email Forensics is the process of analyzing email evidence to investigate cybercrime, fraud, harassment, or other illegal activities.

🟢 Email Architecture
ProtocolPortPurpose
SMTP25, 587Sending emails
POP3110Downloading emails (deletes from server)
IMAP143Reading emails (kept on server)
SMTP over SSL465Secure sending
🟢 Email Forensics

Key Evidence in Email:

  • Email Headers: Most important! Contains actual routing info:
    • Received: from (actual originating server, IP)
    • X-Originating-IP (sender's real IP)
    • Message-ID (unique identifier)
    • Date, From, To, Reply-To
  • Email Body: Content, embedded links, HTML code
  • Attachments: Metadata, embedded objects, malware
  • Metadata: Creation time, modification time

Email Forensics Process:

  1. Collect Email: Extract from email client, server, or PST/MBOX files
  2. Analyze Headers: Trace the actual route of email — Received headers are read bottom to top
  3. IP Tracing: Extract originating IP, use WHOIS/GeoIP to identify location
  4. Examine Attachments: Scan for malware, extract metadata
  5. Authentication Check: Verify SPF, DKIM, DMARC records
  6. Timeline Analysis: Create chronology of email activity
  7. Document Findings: Preserve as evidence

Email Spoofing Detection

  • SPF (Sender Policy Framework): Lists authorized sending servers for a domain
  • DKIM (DomainKeys Identified Mail): Digital signature added by sending server
  • DMARC: Policy for handling SPF/DKIM failures
⚠️ "From" field in email can be easily spoofed! Always analyze the Received headers for actual origin.
🔴 Important Exam Points
  • Email headers are read bottom to top for routing analysis
  • X-Originating-IP shows real sender IP
  • SPF/DKIM/DMARC = email authentication trinity
  • Tools: Emailtrackerpro, eMailTrackerPro, MXToolbox
⚡ Quick Revision
SMTP = Send (port 25) IMAP = Read (port 143) Header bottom→top SPF+DKIM+DMARC X-Originating-IP
