Reduce the following grammar to Chomsky Normal Form (CNF):
S → bA | aB  |  A → bAA | aS | a  |  B → aBB | bS | b
Background: What is Chomsky Normal Form?
Definition — Chomsky Normal Form (CNF)

A CFG is in CNF when every rule is exactly one of two shapes:
  A → BC  — exactly two non-terminals on the right
  A → a  — exactly one terminal on the right
Memory trick: "Either split into two, or end with one terminal." The start symbol alone can produce ε if ε is in the language.

CNF matters because the CYK parsing algorithm requires it. The good news: any CFG can always be converted to an equivalent CNF without changing the language.

5-Step Recipe to Convert any CFG to CNF
  1. 1Kill ε-rules — remove all A → ε (except for the start symbol if needed).
  2. 2Kill unit rules — remove A → B where B is a lone non-terminal (chain rules).
  3. 3Kill useless symbols — remove any non-terminal that can never reach a terminal string.
  4. 4Isolate terminals — in any rule with length ≥ 2, replace each bare terminal 'a' with a new non-terminal T_a → a.
  5. 5Break long rules — if a rule has 3+ symbols on the right, split it using a new helper non-terminal until every rule has exactly 2.
Given Grammar
Original Grammar
S → bA | aB
A → bAA | aS | a
B → aBB | bS | b
Shortcut Observation

This grammar has no ε-rules and no unit rules, so Steps 1, 2, and 3 are done instantly. We jump straight to Steps 4 and 5.

Step 4 — Give Every Terminal Its Own Non-Terminal

Anywhere a terminal 'a' or 'b' appears in a rule of length ≥ 2, replace it with a proxy non-terminal:

  • Ta → a — proxy for terminal a
  • Tb → b — proxy for terminal b

Rewrite every rule of length ≥ 2 using these proxies (single-terminal rules like A → a stay as-is):

  • B → T_a BB → introduce N_2 → BB, rewrite as B → T_a N_2

Discuss inherent ambiguity of Context-Free Language (CFL) with a suitable example.
Background: Ambiguity in CFG
Definition — Ambiguous Grammar

A CFG is ambiguous if at least one string in its language has two or more different parse trees (or equivalently, two different leftmost derivations). Think of it as: the grammar gives the same sentence two different "meanings."

Inherent Ambiguity — Definition
Definition — Inherently Ambiguous CFL

A CFL is inherently ambiguous if every possible grammar for it is ambiguous — you cannot escape the ambiguity no matter how you rewrite the grammar. The ambiguity is baked into the language itself, not just one particular grammar.

Key Points to Remember
  • Inherent ambiguity is a property of the language, not of any single grammar.
  • Finding even one unambiguous grammar for L proves L is not inherently ambiguous.
  • Checking whether a CFL is inherently ambiguous is undecidable (no algorithm exists).
  • All regular languages are unambiguous — finite automata always yield clean grammars.
Classic Example of Inherently Ambiguous CFL
Standard AKTU Example

L = { aⁱ bʲ cᵏ | i = j or j = k, i,j,k ≥ 1 }
This is the union of L₁ = {aⁿbⁿcᵏ} (equal a's and b's) and L₂ = {aⁱbⁿcⁿ} (equal b's and c's). Any string where i = j = k belongs to both sub-languages — so it always has two parse trees, no matter how you write the grammar.

Why "abc" Proves Ambiguity

The string a b c (i=j=k=1) belongs to both L₁ (i=j=1 ✓) and L₂ (j=k=1 ✓). Any grammar must be able to generate it via two separate rule-paths — giving two distinct parse trees. You cannot avoid this.

Define parse tree and construct a parse tree for grammar: E → E+E | E*E | (E) | id    for string: id + id * id
Definition — Parse Tree
Definition — Parse Tree (Derivation Tree)

A parse tree is a tree that shows how a string was derived from a grammar. Simple rules to remember:
— Root = start symbol
— Internal nodes = non-terminals
— Leaves = terminals (or ε)
— Reading the leaves left-to-right gives the derived string.

Properties of a Parse Tree
  • Every internal node is labeled with a non-terminal; its children are the right-hand side of the rule applied.
  • Every leaf is a terminal or ε.
  • If a node labelled A has children X₁ X₂ ... Xₙ, then A → X₁X₂...Xₙ must be a production rule.
  • The yield (left-to-right leaves) is the string being parsed.
  • Multiple distinct parse trees for one string → grammar is ambiguous.
Given Grammar
Grammar G
E → E+E  |  E*E  |  (E)  |  id

String to parse: id + id * id
Note — This Grammar is Ambiguous

The grammar E → E+E | E*E | (E) | id is a classic ambiguous grammar. The string "id + id * id" has two distinct parse trees (one with + at root, one with * at root). We show both.

Parse Tree 1 — Addition (+) at Root

Corresponds to: (id + id) * id grouping — applying E+E first.

Parse Tree 2 — Multiplication (*) at Root

Corresponds to: id + (id * id) grouping — applying E*E first.

Key Observation

Two distinct parse trees exist for "id + id * id". This proves the grammar is ambiguous. In real compilers, this is resolved by specifying operator precedence (* over +) and associativity (left-associative), giving Tree 1 the correct semantic meaning.

Conclusion

A parse tree visually encodes the structure of derivation. The grammar E → E+E | E*E | (E) | id is ambiguous as shown by two distinct trees for "id+id*id". An unambiguous grammar separates precedence levels using intermediate non-terminals (E, T, F).

Convert the following CFG into equivalent Greibach Normal Form (GNF):
S → AA | a    A → SS | b
Background: What is Greibach Normal Form?
Definition — Greibach Normal Form (GNF)

A CFG is in GNF if every rule looks like:
  A → a α
where a is a terminal and α is zero or more non-terminals. Key idea: every derivation step must consume exactly one terminal up front — like a stack machine reading one character at a time. This makes GNF ideal for top-down (predictive) parsing.

Given Grammar
Original Grammar
S → AA | a
A → SS | b
Step 1 — Convert to CNF First

The grammar is nearly in CNF already. Rules S → AA, A → SS are in A→BC form, and S→a, A→b are in A→a form. So this grammar is already in CNF.

Step 2 — Order Non-Terminals for Substitution

Label: A₁ = S, A₂ = A. The GNF algorithm demands that rules for A₁ never start with A₂ (no "forward" non-terminal leading). We process in order and substitute to expose a terminal at the front of every rule.

Step 3 — Substitute to Remove Non-Terminal Prefixes

S → AA starts with A (a non-terminal) — this violates GNF. Fix: substitute A's productions (A → SS | b) into the first A in S → AA to expose a terminal:

Substituting A → SS | b into S → AA
S → AA
  A can be SS or b, so:
  S → SSA | bA   ← replace first A with A's RHS
  
Now S → SSA still starts with S (left recursion!)
We need to eliminate this left recursion.
Step 4 — Eliminate Left Recursion from S

S → SSA is left-recursive — S appears at the start of its own rule. Use the standard fix: introduce a helper S' to capture the recursive tail.

Left Recursion Elimination — The Pattern

If A → Aα | β, replace with: A → βA' and A' → αA' | ε.
In plain terms: pull out the "base" (β), then let A' handle repetition of the "tail" (α).

For S → SSA | bA | a:

  • Left-recursive: S → S(SA)
  • Non-left-recursive: S → bA | a
After Left Recursion Elimination
S  → bA S'  |  aS'  |  bA  |  a
S' → SA S' |  SA
Step 5 — Substitute S into A Rules for GNF

Now A → SS | b. Since S now starts with a terminal in all its rules, substitute S's GNF productions into A → SS to expose terminals at the front of A's rules:

GNF Productions for A
A → SS → (bAS' | aS' | bA | a)(bAS' | aS' | bA | a)
This is complex; simplify by using S directly:

A → bAS'S | aS'S | bAS | aS | b
Step 6 — S' Rules — Substitute S for GNF
GNF Productions for S'
S' → SA S' → substitute S:
S' → bAS'AS' | aS'AS' | bAAS' | aAS'
   | bAS'A  | aS'A  | bAA   | aA
Final GNF Summary

S  → a S'        ← terminal + non-terminals

Key Exam Insight

In GNF, every rule starts with exactly one terminal. This means each derivation step "reads" one input character — equivalent to how a predictive (top-down) parser works. The conversion process in one line: CNF → eliminate left recursion → substitute until terminal is first.

Conclusion

The grammar was converted to GNF: (1) detected left recursion in S→SSA, (2) used left-recursion elimination to introduce S', (3) substituted S's terminal-first rules into A and S' until all rules start with a terminal. All productions in the final GNF begin with a terminal symbol.

Prove that the language L = {aⁿbⁿcⁿ | n ≥ 1} is not a Context-Free Language.
Background: Pumping Lemma for CFLs
Pumping Lemma for Context-Free Languages

If L is a CFL, then there is a pumping length p ≥ 1 such that any string w ∈ L with |w| ≥ p can be split as w = uvxyz where:
  (1) |vy| ≥ 1 — at least one of v, y is non-empty
  (2) |vxy| ≤ p — the "middle" section is bounded by p
  (3) uvixyiz ∈ L for all i ≥ 0 — you can "pump" v and y up/down

Memory hook: CFL splits into 5 parts (uvxyz). You pump the 2nd and 4th parts (v and y) together. If pumping ever leaves the language — it's NOT a CFL.

Claim
Claim

L = { aⁿbⁿcⁿ | n ≥ 1 } is NOT a Context-Free Language.

Proof by Contradiction
  1. 1 Assume L is CFL → Pumping Lemma gives us a pumping length p ≥ 1.
  2. 2 Pick the string: w = aᵖbᵖcᵖ ∈ L. Its length = 3p ≥ p, so the lemma applies.
  3. 3 Split: w = uvxyz with |vy| ≥ 1 and |vxy| ≤ p.
  4. 4 Key observation: Since |vxy| ≤ p, this middle chunk spans at most two adjacent symbol blocks. It cannot simultaneously touch a's and c's (they are p characters apart). So v and y affect at most 2 of the 3 symbol types.
Case Analysis — All Possible Positions of v and y
Case 1: v and y are inside only one symbol block (e.g., only a's)

Pumping (i=2) increases only that one symbol's count. Example: more a's → aᵖ⁺ᵏbᵖcᵖ. The three counts are no longer equal → not in L. Contradiction.

Case 2: v spans the a–b boundary

Pumping adds more a's and b's, but c's stay at p. So a-count or b-count ≠ c-count → not in L. Contradiction.

Case 3: v spans the b–c boundary

Pumping adds more b's and c's, but a's stay at p. So a-count ≠ b-count or c-count → not in L. Contradiction.

Case 4: v in a-section, y in c-section (skipping b's)

This would require |vxy| ≥ p (the a-section) + p (the b-section) = 2p > p. This violates the constraint |vxy| ≤ p. So this case is impossible.

Summary Table of All Cases
Position of v,yEffect of pumping (i=2)Result
Only in a-sectionMore a's, same b's, c'saᵖ⁺ᵏbᵖcᵖ ∉ L
Only in b-sectionMore b's, same a's, c'saᵖbᵖ⁺ᵏcᵖ ∉ L
Only in c-sectionMore c's, same a's, b'saᵖbᵖcᵖ⁺ᵏ ∉ L
v in a's, y in b'sMore a's and b'saᵖ⁺ᵏbᵖ⁺ʲcᵖ ∉ L (c's differ)
v in b's, y in c'sMore b's and c'saᵖbᵖ⁺ᵏcᵖ⁺ʲ ∉ L (a's differ)
v in a's, y in c'sImpossible: |vxy|≥2p > pViolates |vxy|≤p
Conclusion of Proof
Final Contradiction

In every possible split w = uvxyz, pumping produces a string NOT in L. The Pumping Lemma guarantees pumped strings stay in L — contradiction. So our assumption was false.

∴ L = { aⁿbⁿcⁿ | n ≥ 1 } is NOT a Context-Free Language. □
Exam Tip — Why It Makes Sense

A PDA has one stack. It can match two things (push a's, pop for b's) — but not three simultaneously. {aⁿbⁿcⁿ} needs to track three counts at once, which requires a Context-Sensitive (linear-bounded) automaton, not a PDA.

Give a complete description of the Chomsky Hierarchy of formal languages and grammars.
Introduction

The Chomsky Hierarchy (1956) classifies all formal grammars into 4 nested levels — Type 0 (most powerful) down to Type 3 (most restricted). Memory trick: higher Type number = more restrictions = weaker grammar = simpler machine. Each type is a strict subset of the one above it.

Grammar = 4-tuple

G = (V, T, P, S) — V: non-terminals, T: terminals, P: production rules, S: start symbol. The Chomsky Hierarchy is entirely about what shapes of rules are allowed in P.

The Four Levels
Type 0
Unrestricted / Recursively Enumerable Languages
Rules: α → β, any α,β ∈ (V∪T)*, |α|≥1  |  Machine: Turing Machine  |  Power: Maximum
Type 1
Context-Sensitive Languages (CSL)
Rules: αAβ → αγβ, where γ≠ε  |  Machine: Linear Bounded Automaton (LBA)  |  |lhs| ≤ |rhs|
Type 2
Context-Free Languages (CFL)
Rules: A → γ, A ∈ V, γ ∈ (V∪T)*  |  Machine: Pushdown Automaton (PDA)  |  Left side is one NT
Type 3
Regular Languages (RL)
Rules: A → aB or A → a  |  Machine: Finite Automaton (DFA/NFA)  |  Most restricted

Key Properties to Remember
  • The hierarchy is strictly nested: RL ⊊ CFL ⊊ CSL ⊊ RE — each is a proper subset of the next.
  • Regular (Type 3): closed under union, concatenation, star, intersection, complement — all of them.
  • CFL (Type 2): closed under union, concatenation, star — but NOT closed under intersection or complement.
  • CSL (Type 1): closed under all Boolean operations including intersection and complement.
  • Complexity: RL — O(n) | CFL — O(n³) by CYK | CSL — PSPACE | RE — undecidable in general.
Conclusion — One-Line Summary per Type

Type 3 (Regular): DFA/NFA — simple patterns like (a|b)*.
Type 2 (CFL): PDA — nested structures like aⁿbⁿ. Used in compilers for parsing.
Type 1 (CSL): LBA — three-way balance like aⁿbⁿcⁿ.
Type 0 (RE): Turing Machine — the ultimate limit of what any computer can recognize.

Write equivalent left linear grammar from the following right linear grammar:
S → aS | aA | A → bA | b
Background — Linear Grammars
Definitions

Right Linear Grammar: Non-terminal is always on the RIGHT — rules look like A → aB or A → a.

Left Linear Grammar: Non-terminal is always on the LEFT — rules look like A → Ba or A → a.

Both generate the same class: Regular Languages. They are equivalent to each other and to DFA/NFA — just different ways of describing the same machines.

Given Right Linear Grammar
Right Linear Grammar G (right-recursive)
S → aS  |  aA
A → bA  |  b
Language Generated by G

S generates one or more a's (S → aS | aA), then A generates one or more b's. So the language is:

L(G) = a⁺b⁺ — one or more a's followed by one or more b's
Conversion Method — NFA Reversal (3 Steps)

The trick: a reversed NFA recognizes the reversed language. Converting right→left linear grammar is the same as reversing the NFA and writing the new grammar.

  1. 1Build the NFA from the right linear grammar (each non-terminal = a state)
  2. 2Reverse the NFA: swap start ↔ final states, reverse all transition arrows
  3. 3Write the left linear grammar from the reversed NFA
Step 1 — Build NFA from the Right Linear Grammar

Each non-terminal becomes a state. A rule A → aB becomes a transition from state A to state B on input 'a'. A rule A → a (no non-terminal) goes to a new final state q_F.

  • S → aS: self-loop at q_S on 'a'
  • S → aA: q_S --a→ q_A
  • A → bA: self-loop at q_A on 'b'
  • A → b: q_A --b→ q_F (final state)
Step 2 — Reverse the NFA
  • Old start q_S → becomes the new final state
  • Old final q_F → becomes the new start state
  • All arrows flip direction: q_S←a←q_S, q_A←a←q_S, q_A←b←q_A, q_F←b←q_A becomes q_A --b→ q_F (reversed)
Step 3 — Write Left Linear Grammar from Reversed NFA

In a left linear grammar, a transition X --a→ Y becomes rule Y → Xa (non-terminal on the left, terminal on the right). Reading each reversed transition:

  • q_F --b→ q_A reversed → A' → S'b (start of reversed = S')
  • q_A --b→ q_A reversed → A' → A'b (self-loop, left-recursive)
  • q_S --a→ q_A reversed → A' → S''a (hits the old start = base case)
  • q_S --a→ q_S reversed → S'' → S''a (self-loop on a's)
Final Left Linear Grammar
✓ Equivalent Left Linear Grammar
Renaming: Start=S, intermediate=A, terminal state rule

S → Ab   ← non-terminal on left, terminal on right
A → Ab   ← generates b's (left-recursively)
A → Ba   ← transition from a-section to b-section
B → Ba   ← generates a's (left-recursively)
B → a    ← base: first 'a'
Verify: Derive "aabb" using Left Linear Grammar

  ⟹ Abb          [A → Ab]
  ⟹ Babb         [A → Ba]
  ⟹ Baabb        [B → Ba]
  ⟹ aabb         [B → a]  ✓
Conclusion

The right linear grammar for L = a⁺b⁺ was converted to an equivalent left linear grammar using the NFA reversal technique: (1) right-linear grammar → NFA, (2) reverse the NFA (swap start/final, flip arrows), (3) read off the left-linear grammar. Both grammars generate exactly a⁺b⁺. This proves left and right linear grammars are equally powerful.
