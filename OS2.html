2M Define Operating System. List the objectives of an operating system.
★ 2 Marks | Frequently Asked Definition
Definition
Operating System (OS) is a system software that acts as an intermediary between the hardware of a computer and the user/application programs. It manages hardware resources and provides services for computer programs.

Simple definition: "OS is a program that controls app execution and acts as a bridge between the user and the computer hardware."
Objectives of an Operating System
  • Convenience: Make the computer system user-friendly and easy to use.
  • Efficiency: Allow computer system resources to be used in an efficient manner.
  • Ability to Evolve: Allow new features to be added without breaking existing services.
  • Resource Management: Manage CPU, memory, I/O devices, and files among competing processes.
  • Security & Protection: Prevent unauthorized access and protect user data.
  • Error Detection: Detect and handle errors in hardware and software.
  • Accounting: Track resource usage by users for billing and optimization.
AKTU Tip: Always draw the 3-layer diagram (User → OS → Hardware) for 2-mark definition questions. It instantly adds visual value.

2M What is the primary function of an operating system?
The primary function of an Operating System is to manage and coordinate hardware resources and provide a convenient interface for user programs to access these resources efficiently and safely.
Two Core Primary Functions
  • Resource Manager: OS distributes CPU time, memory, I/O devices, and file storage fairly among all running programs. It ensures no program hogs everything.
  • Extended Machine / Virtual Machine: OS hides messy hardware details from the user. It gives a clean, simple interface (system calls) so programs can work without needing to know how the hardware works.
Simple Analogy: OS is like a hotel manager — it manages all rooms (resources), ensures guests (processes) get what they need, and resolves conflicts when two guests want the same room.
2M Briefly define the term Real Time Operating System.
Real Time Operating System (RTOS) is an OS designed to process tasks within a strict time limit (deadline). The system is correct only if it gives the right result AND gives it on time. Missing the deadline = failure (in hard RTOS).
Types of RTOS
  • Hard RTOS: Missing a deadline causes system failure. Example: Missile guidance, Airbag control systems.
  • Soft RTOS: Missing a deadline degrades performance but does not cause failure. Example: Multimedia streaming, Online reservation systems.
Characteristics
  • Deterministic task scheduling
  • Fast interrupt response time
  • Small memory footprint
  • No virtual memory (usually)
  • Priority-based preemptive scheduling
Examples
Hard RTOS: VxWorks, QNX, RTLinux Soft RTOS: Windows CE, Android RTOS variants Applications: Medical devices, Robotics, Aircraft control

2M Explain the principal advantages of multiprogramming.
Multiprogramming means keeping multiple programs in memory at the same time, so when one program is waiting for I/O, the CPU can run another program instead of sitting idle. This keeps the CPU busy as much as possible.
Principal Advantages
  • High CPU Utilization: When one process waits for I/O, another runs — so the CPU is rarely idle. Utilization jumps from ~20% (single program) to 90%+.
  • Increased Throughput: More jobs are completed per unit of time since CPU is continuously busy.
  • Reduced Turnaround Time: Average job waiting time decreases as CPU switching minimizes idle periods.
  • Better Resource Utilization: Memory, CPU, I/O devices are all used more efficiently simultaneously.
  • User Responsiveness: Multiple users can use the system concurrently (basis of time-sharing).
  • Cost Effectiveness: Better return on hardware investment since resources stay active.

UNIT 02 Concurrent Processes & Synchronization 5 Questions · 2M each
2M What is the use of inter process communication and context switching?
Inter-Process Communication (IPC)
IPC is a set of methods that let processes talk to each other and coordinate their work. Without IPC, processes would be isolated — they couldn't share results or work together.
Uses of IPC
  • Data transfer between cooperating processes (e.g., producer-consumer)
  • Sharing of data / shared memory among processes
  • Event notification — one process signals another
  • Synchronization to prevent race conditions
  • Remote Procedure Calls (RPC) in distributed systems
IPC Mechanisms
Pipes (Named & Unnamed) | Message Queues | Shared Memory Semaphores | Sockets | Signals | Message Passing
Context Switching
Context Switching is when the OS saves the state of the currently running process (like a bookmark) and loads the saved state of another process so the CPU can run it. Think of it as the CPU pausing one task and resuming another.
Uses of Context Switching
  • Enables multitasking — multiple processes share one CPU
  • Allows OS to preempt a running process and switch to another
  • Facilitates time-sharing among users
  • Supports multiprogramming by switching during I/O waits
What is Saved in Context?
PCB (Process Control Block) stores: ├── Program Counter (PC) ├── CPU Registers ├── Process State ├── Memory Management Info └── I/O Status
AKTU Tip: Context switching has overhead — the CPU does no useful work during switching. This is called pure overhead.
2M Define Busy Waiting? How to overcome busy waiting using Semaphore operations.
Busy Waiting (Spin-lock) is when a process keeps looping and checking a condition over and over until it becomes true. The process is using the CPU but doing no real work — it's just wasting CPU cycles by "spinning".
// Example of Busy Waiting while (lock == 1) { // do nothing — keep looping (wasting CPU) } // critical section after lock is 0
Disadvantage of Busy Waiting
  • Wastes CPU time — CPU cycles consumed without useful work
  • Reduces system throughput and efficiency
  • Not suitable for long waits
Overcoming with Semaphores
A Semaphore is an integer variable used for process synchronization. Instead of busy-waiting, a process that can't proceed simply goes to sleep (BLOCKED state) and is woken up later. It supports two atomic operations:
wait(S) [also called P or down] — tries to enter; blocks if not allowed
signal(S) [also called V or up] — signals that resource is free
Semaphore Operations (Blocking Version)
wait(S) { S.value--; if (S.value < 0) { // Add process to S.waiting_queue block(); // Process goes to BLOCKED state (NOT spinning!) } } signal(S) { S.value++; if (S.value <= 0) { // Remove a process from S.waiting_queue wakeup(P); // Move process to READY state } }
How Busy Waiting is Eliminated
  • Instead of looping, the process calls block() → enters BLOCKED state
  • OS removes it from CPU — CPU is free to run other processes
  • When resource is available, wakeup() is called → process moves to READY queue
  • No CPU cycles are wasted during waiting!
2M What do you mean by Concurrent Processes?
Concurrent Processes are two or more processes that are active at the same time in a system. Their execution overlaps in time — either truly running in parallel (on multiple CPUs) or taking turns very rapidly on one CPU.
Types of Concurrency
  • Pseudo-Concurrency: Single CPU rapidly switches between processes (illusion of parallel execution — time-sharing)
  • True Concurrency: Multiple CPUs actually execute multiple processes simultaneously (multiprocessor systems)
Issues with Concurrent Processes
  • Race Condition: Multiple processes access shared data and the outcome depends on execution order
  • Mutual Exclusion: Only one process should access critical section at a time
  • Deadlock: Circular waiting among processes
  • Starvation: A process never gets to run
Benefits of Concurrency
  • Improved CPU utilization and throughput
  • Better user responsiveness
  • Resource sharing among processes
Example: In a web browser, the download manager, tab renderer, and JavaScript engine run as concurrent processes.
2M Define semaphore and its types.
Semaphore is a synchronization tool invented by Dijkstra. It's an integer variable used to control access to shared resources — like a token system. Only one (or a limited number of) process(es) can enter the critical section at a time. It supports two atomic operations: wait(S) and signal(S).
Types of Semaphores
1. Binary Semaphore (Mutex)
  • Value can only be 0 or 1
  • Works like a simple lock: 0 = locked, 1 = unlocked
  • Used for mutual exclusion in critical section
  • Also called Mutex Lock
Binary Semaphore S = 1; // Process P1: wait(S); // S becomes 0 (lock acquired) // Critical Section signal(S); // S becomes 1 (lock released)
2. Counting Semaphore (General Semaphore)
  • Value can be any non-negative integer
  • Used to control access to a resource with multiple instances
  • Example: Allow at most 5 processes to use a printer pool
  • Initialized to the number of available resource instances
Counting Semaphore S = 5; // 5 identical resources available // Each process does: wait(S); // S-- (use one resource instance) // Use resource signal(S); // S++ (release resource instance)
FeatureBinary SemaphoreCounting Semaphore
Value Range0 or 1 only0 to N (any non-negative)
Use CaseMutual ExclusionResource allocation (N instances)
Also Known AsMutexGeneral Semaphore
2M Define the principle of concurrency.
The Principle of Concurrency says that multiple processes can be active at the same time in a system. These processes may share resources, work together, or compete for the same resource. The OS must handle all of this correctly and efficiently.
Core Principles
  • Mutual Exclusion: At most one process executes in the critical section at any time. Prevents simultaneous access to shared resources.
  • Progress: If no process is in the critical section, a process that wishes to enter must be allowed to do so in finite time.
  • Bounded Waiting: If a process wants to enter the critical section, it must get a turn within a limited number of tries by others. No process should wait forever.
  • No Busy Waiting (desirable): Processes should not waste CPU cycles while waiting. They should block instead.
  • Fairness: Every process should eventually get a chance to run — no indefinite postponement.
Problems Arising from Concurrency
ProblemDescription
Race ConditionTwo processes access shared variable simultaneously; result depends on order
DeadlockCircular wait — each process holds a resource needed by another
StarvationA process is indefinitely denied resources it needs
Priority InversionLow priority process holds resource needed by high priority process

2M What are the Performance Criteria in CPU Scheduling?
Performance criteria in CPU scheduling measure how well an algorithm manages the CPU. These directly impact system efficiency and user experience.
  • CPU Utilization: Percentage of time CPU is busy. Higher is better. Formula: (CPU Busy Time / Total Time) × 100%
  • Throughput: Jobs per second/minute. Higher throughput = better system performance.
  • Turnaround Time: Total time for process completion from arrival. TAT = CT − AT
  • Waiting Time: Time in ready queue. WT = TAT − BT. Minimizing this is primary goal.
  • Response Time: Time until first output is produced. Critical for interactive systems.
  • Fairness: Each process gets fair share of CPU; no starvation of any process.
Trade-off: Algorithms optimizing one criterion may worsen another. E.g., SJF minimizes average waiting time but may starve long processes.
2M What do we need Scheduling?
Scheduling is needed because in a multiprogramming system, many processes want the CPU at the same time but there's only one CPU. The OS must decide who gets it next — fairly and efficiently.
Why Scheduling is Needed
  • CPU is Scarce: Only one (or few) CPU cores exist but many processes need them — scheduling allocates CPU time fairly.
  • Maximize Utilization: Without scheduling, CPU may be idle while processes wait in queue. Scheduling keeps CPU busy.
  • Multiprogramming Support: Scheduling enables multiple programs to run "simultaneously" by rapidly switching between them.
  • Fairness: Every process must get CPU time. Without scheduling, some processes might never run.
  • Priority Handling: Some processes (OS services, real-time tasks) have higher urgency — scheduling can prioritize them.
  • Response Time: Interactive users expect quick responses — scheduling minimizes wait and response time.
  • Process States: Processes move between Ready, Running, Waiting states. Scheduler decides which ready process gets the CPU next.

2M What is a safe state and an unsafe state?
These concepts are central to the Banker's Algorithm for Deadlock Avoidance.
Safe State
A system is in a safe state if there is at least one safe sequence — a way to run all processes one by one such that each process can get all the resources it needs and finish successfully. If a safe sequence exists, deadlock cannot happen.
Safe Sequence Example: Processes: P1, P2, P3 | Available Resources: 3 P2 needs 2 → gets them → runs → releases → Available = 5 P1 needs 5 → gets them → runs → releases → Available = 8 P3 needs 8 → gets them → runs → releases → Done! Safe Sequence: <P2, P1, P3> ✓ System is SAFE (All processes can finish — no deadlock possible)
Unsafe State
A system is in an unsafe state if no safe sequence exists — meaning there is a chance that processes could get stuck waiting for each other (deadlock). An unsafe state does NOT mean deadlock will definitely happen, but it's possible.
FeatureSafe StateUnsafe State
DeadlockCannot occurMay occur
Safe SequenceAt least one existsNone exists
OS ActionGrant resource requestDeny resource request
Key Rule (Banker's Algorithm): OS grants a resource request only if the resulting state is safe. If it would lead to an unsafe state, the request is denied (process must wait).
2M Explain starvation problem and its solution.
Starvation is a situation where a process keeps waiting but never gets its turn. This happens when higher-priority or shorter processes always jump ahead of it. The starving process may wait forever.
When Does Starvation Occur?
  • Priority Scheduling: A low-priority process is continuously bypassed by high-priority processes that keep arriving
  • SJF Scheduling: A long process waits forever as shorter processes keep being admitted and served first
  • Resource Allocation: A process cannot get all the resources it needs because others keep grabbing them
Solution: Aging
Aging is the solution to starvation. The idea is simple: the longer a process waits, the higher its priority gets. Eventually it becomes high-priority enough to finally get the CPU.
Aging Example: - Process P is created with priority = 10 (low) - Every 5 minutes, P's priority is increased by 1 - After 50 minutes, P has priority = 1 (highest!) - P will now be selected for execution Result: No process can starve indefinitely.
Other Solutions
  • Round-Robin Scheduling: Every process gets a fixed time quantum — no starvation possible
  • Fair Queuing: Each process gets an equal share of CPU bandwidth
  • Deadline Scheduling: Every process given a deadline to complete; resources allocated accordingly

2M What are the disadvantages of single contiguous memory allocation?
Single Contiguous Memory Allocation is the simplest memory scheme — memory is split into just two areas: one for the OS and one for a single user process. Only one user process can be in memory at a time.
Disadvantages
  • No Multiprogramming: Only one user process can be in memory at a time. CPU is idle when this process does I/O — huge waste.
  • Low CPU Utilization: CPU remains idle during I/O operations since no other process can use it. Utilization can drop below 20%.
  • Memory Waste: If the process is smaller than available memory, the remaining memory is completely wasted (severe internal fragmentation).
  • No Memory Protection Between Users: Since only one process runs, multi-user support is impossible.
  • Limited Program Size: Program must fit entirely within the available user memory area. Large programs cannot run.
  • Poor Throughput: System can only complete one job at a time, resulting in very low throughput.
  • No Virtual Memory: No mechanism to run programs larger than physical RAM.
2M What is the main function of the memory-management unit?
Memory Management Unit (MMU) is a hardware chip that converts logical (virtual) addresses into physical addresses at runtime. It sits between the CPU and RAM and performs this translation automatically every time memory is accessed.
Main Function
  • Address Translation: Converts logical addresses generated by CPU into physical addresses for actual memory access. This is the primary function.
  • Memory Protection: Checks if a process is accessing memory within its valid address range. Raises a protection fault if bounds are violated.
  • Base + Limit Register Translation: Uses base register (starting physical address) and limit register (process size) to translate and check addresses.
  • Page Table Lookup: In paging systems, MMU walks the page table to find the physical frame for each logical page.
  • TLB (Translation Lookaside Buffer): A small, fast cache inside the MMU that stores recently used address translations — so the MMU doesn't have to search the full page table every time (much faster).
Physical Address = Base Register + Logical Address (if Logical Address < Limit Register → Valid; else → Segmentation Fault)

2M Explain in brief about the Multiprogramming with fixed partitions.
Multiprogramming with Fixed Partitions (MFT) divides RAM into a fixed number of fixed-size slots (partitions) at startup. Each slot can hold exactly one process. This way, multiple processes can stay in memory at the same time.

2M Explain thrashing and locality of reference.
Thrashing
Thrashing is when a process spends more time swapping pages in and out of memory than actually running. It happens when the OS gives a process too few memory frames — the process keeps needing pages that were just swapped out, causing constant page faults and near-zero real work.
  • Process does not have enough frames to hold its active pages
  • Pages are continuously swapped out and needed again immediately
  • CPU utilization drops drastically as processes are mostly in I/O wait state
  • OS may add more processes thinking CPU is idle → makes thrashing even worse
Solution to Thrashing
  • Working Set Model: Allocate at least enough frames for a process's working set
  • Page Fault Frequency: Monitor and control page fault rate; add/remove frames dynamically
  • Reduce Degree of Multiprogramming: Suspend some processes to free frames
Locality of Reference
Locality of Reference is the observation that programs don't access memory randomly — they tend to use the same small set of addresses repeatedly over a short time. This is why caches and virtual memory work so well.
Two Types
  • Temporal Locality: If you used a memory location recently, you'll likely use it again soon. Example: A loop variable i is accessed many times in quick succession.
  • Spatial Locality: If you access one memory location, you'll likely access nearby locations too. Example: When reading array[5], you'll probably read array[6] next.
Connection: Thrashing is prevented when each process is given frames covering its current locality set (working set). The Working Set Model directly exploits the principle of locality.

UNIT 05 I/O Management & File System 6 Questions · 2M each
2M Define seek time and latency time.
Seek Time
Seek Time is the time it takes for the disk's read/write head to move to the correct track (cylinder) where the data is stored. It is the biggest part of total disk access time.
  • Measured in milliseconds (ms)
  • Depends on distance between current track and target track
  • Modern disks: average seek time ≈ 3–10 ms
  • Goal of disk scheduling algorithms: minimize total seek time
Latency Time (Rotational Latency)
Rotational Latency (Latency Time) is the time the disk takes to rotate the correct sector under the read/write head after the head has reached the right track. It depends on how fast the disk spins (RPM).
  • Average latency = time for half rotation of disk
  • For 7200 RPM disk: one rotation = 60/7200 = 8.33 ms → avg latency ≈ 4.17 ms
  • For 15000 RPM disk: avg latency ≈ 2 ms
Total Disk Access Time = Seek Time + Rotational Latency + Transfer Time Example (7200 RPM): Seek Time = 8 ms Latency = 4.2 ms (half of 8.33ms) Transfer Time = 0.5 ms ───────────────────────── Total = 12.7 ms
2M Define SCAN and C-SCAN scheduling algorithms.
SCAN Algorithm (Elevator Algorithm)
In SCAN, the disk arm moves in one direction (say, toward higher cylinder numbers), serves all requests along the way, reaches the end, then turns around and serves requests while coming back. It works exactly like an elevator — that's why it's called the Elevator Algorithm.
Example: Head at cylinder 50, moving toward higher Requests: 82, 170, 43, 140, 24, 16, 190 Upward: 50 → 82 → 140 → 170 → 190 (end) Reverse: 190 → 43 → 24 → 16 Total Head Movement: Calculated along this path
Advantage of SCAN
  • No starvation — every request is served within one pass
  • More uniform service than SSTF
C-SCAN Algorithm (Circular SCAN)
C-SCAN is a variation of SCAN. The head moves in one direction and serves requests, but when it reaches the end, it jumps straight back to cylinder 0 (without serving anything on the way back) and starts again. This gives all requests a more equal waiting time.
C-SCAN: Head at 50, moving upward Requests: 82, 170, 43, 140, 24, 16, 190 Upward: 50 → 82 → 140 → 170 → 190 (end) Return: Jump to 0 (no service on return) Restart: 0 → 16 → 24 → 43 Result: More uniform waiting than SCAN
FeatureSCANC-SCAN
Return DirectionServices requests on return tooNo service on return (jumps to start)
UniformityLess uniform (inner tracks wait longer)More uniform waiting times
FairnessGoodBetter
2M What do you mean by the I/O Buffering?
I/O Buffering is using a temporary memory area called a buffer to hold data while it moves between a device and an application. Since the CPU is much faster than I/O devices, the buffer lets the CPU continue working while data transfer happens in the background.
Need for Buffering
  • CPU processes data much faster than I/O devices can supply/accept it
  • Without buffering, CPU must wait for each byte — very inefficient
  • Buffering allows CPU to continue processing while I/O occurs in background
Types of Buffering
TypeDescription
Single BufferOS allocates one buffer in kernel memory. While user reads buffer, kernel fills next from device.
Double BufferTwo buffers alternate. While user reads buffer-1, kernel fills buffer-2. Reduces wait time significantly.
Circular BufferRing of buffers used for continuous streaming data (audio, video). Most efficient for real-time I/O.
SpoolingDisk is used as a large buffer (e.g., print jobs are stored on disk first; the printer reads from disk at its own pace).
Benefits
  • Overlaps CPU computation with I/O operations (improved throughput)
  • Smooths out speed differences between producer and consumer
  • Prevents data loss when a device is not ready to receive data immediately
2M Explain various operations associated with a file.
A File is a named collection of related data stored on a disk (secondary storage). The OS provides system calls (operations) to create, access, and manage files.
File Operations
1
Create: OS allocates space on disk, creates a directory entry for the file with name, type, location, and size attributes.
2
Open: Opens an existing file and returns a file descriptor/handle. File information is loaded into memory's open-file table.
3
Read: Data is read from the file at the current file pointer position into a user buffer. Pointer advances after read.
4
Write: Data from user buffer is written to the file at current pointer position. File size may increase.
5
Seek (Reposition): Moves the file pointer to a specific position without reading/writing. Allows random access.
6
Close: Releases the file descriptor, flushes buffers to disk, and removes entry from open-file table.
7
Delete: Removes the directory entry and deallocates disk space. File data is logically erased.
8
Truncate: Resets file length to zero (or a specified length) while keeping attributes intact. Erases contents.
2M Explain tree level directory structure.
Tree-Structured Directory (also called Hierarchical Directory) organizes files and folders in a tree with one root directory at the top. Each folder can contain files and subfolders, forming a branching hierarchy — just like the folder structure on your computer.
Structure
Key Features
  • Path Names: Files accessed via absolute path (from root) like /home/alice/file1.txt or relative path
  • Working Directory: Each process has a current working directory for relative paths
  • No Naming Conflicts: Same filename can exist in different directories — no conflict
  • Efficient Search: Only the relevant subfolder is searched — not the whole disk
  • Example: UNIX/Linux, Windows NTFS all use tree-structured directories
2M Define an I/O subsystem.
The I/O Subsystem is the part of the OS that manages all input and output operations. It hides the complexity of different hardware devices and gives programs a simple, uniform way to use any device — whether it's a keyboard, disk, or printer.
Components of I/O Subsystem
  • Device Drivers: Small programs that know how to talk to a specific hardware device. The OS sends a standard command; the driver converts it to device-specific instructions.
  • I/O Scheduler: Orders I/O requests to minimize disk head movement and improve speed (uses algorithms like SCAN, C-SCAN).
  • Buffering: A temporary memory area that holds data in transit — handles speed mismatch between the fast CPU and slow devices.
  • Caching: Stores copies of frequently-read data in fast memory, so next time the same data is needed, it comes from cache instead of the slow device.
  • Spooling: Saves output for slow devices (like a printer) onto disk first. The device reads from disk at its own pace — the program doesn't have to wait.
  • Error Handling: Detects and handles I/O errors — retries the operation, reports the error, or stops gracefully.
  • Interrupt Handling: When a device finishes its work, it sends an interrupt signal. The OS responds, processes the result, and continues other work.
