Q2 Explain Paging with example. Differentiate Paging and Segmentation. 7 M

Paging

Definition

Paging is a memory management technique in which the physical memory is divided into fixed-size blocks called frames, and the logical address space of a process is divided into equal-size blocks called pages. The OS maintains a Page Table to map logical pages to physical frames.

Key Terms

  • Page: Fixed-size block of logical address space (e.g., 4 KB)
  • Frame: Fixed-size block of physical memory (same size as page)
  • Page Table: Per-process data structure mapping page number → frame number
  • Page Number (p): Upper bits of logical address
  • Page Offset (d): Lower bits — position within the page

Address Translation in Paging

Logical Address Structure
Logical Address = [Page Number (p)] | [Offset (d)]
Physical Address = Frame_Base_Address + d
Frame_Base_Address = Page_Table[p] × Page_Size

Example

Suppose: Logical address space = 32 bytes, Page size = 8 bytes, Physical memory = 64 bytes

  • Number of pages = 32 / 8 = 4 pages
  • Number of frames = 64 / 8 = 8 frames
  • Page Table: Page 0 → Frame 3, Page 1 → Frame 6, Page 2 → Frame 1, Page 3 → Frame 5

If logical address = 13 (binary: 01101)

  • Page number p = 13 / 8 = 1
  • Offset d = 13 mod 8 = 5
  • Frame number = Page_Table[1] = 6
  • Physical address = 6 × 8 + 5 = 53

Q3 Explain the difference between External Fragmentation and Internal Fragmentation. Also explain how paging solves fragmentation problems. 7 M

Internal Fragmentation

Definition

Internal Fragmentation occurs when a process is allocated more memory than it actually needs. The extra, unused memory inside the allocated block is wasted and cannot be used by other processes.

Example: If a process requires 13 KB and the OS allocates memory in 16 KB blocks, 3 KB is wasted internally.

External Fragmentation

Definition

External Fragmentation occurs when there is enough total free memory to satisfy a request, but it is scattered in non-contiguous small chunks across memory, so no single block is large enough.

Example: 3 free blocks of 10 KB, 5 KB, 8 KB exist (total = 23 KB), but a process needing 20 KB contiguous space cannot be loaded.

Fig 2: Internal vs External Fragmentation

CauseFixed-size allocation (more than needed)Variable-size allocation over time
Occurs inPaging, fixed partitioningSegmentation, dynamic partitioning

How Paging Solves Fragmentation

Eliminates External Fragmentation

  • Physical memory is divided into equal-size frames. Any free frame can hold any page — there is no requirement for contiguous frames.
  • A process's pages can be stored in any available frames, scattered anywhere in physical memory.
  • Since frames are identical in size, there is never a situation where free frames exist but are "too small" — every frame fits every page.
  • Therefore, external fragmentation is completely eliminated by paging.

Reduces (but does not eliminate) Internal Fragmentation

  • Paging creates a small amount of internal fragmentation: the last page of a process may not be completely filled.
  • On average, half a page size is wasted per process.
  • With small page sizes (e.g., 4 KB), this waste is negligible.
  • To reduce internal fragmentation further, use a smaller page size.
Conclusion

Paging is the primary technique to eliminate external fragmentation. The trade-off is minor internal fragmentation in the last page, but this is much smaller and more manageable than external fragmentation.

Q5 Explain the concept of Paging. Also explain paging hardware support using TLB with suitable diagram. 7 M

What is Paging? (Quick Review)

Paging = Divide memory into small equal chunks. CPU uses Page Numbers (logical addresses), hardware translates them to Frame Numbers (physical addresses). The OS keeps a "Page Table" that maps these translations.

The Problem with Basic Paging

The Issue

The page table lives in RAM. Every time CPU needs data, it must: (1) look up page table in RAM, then (2) read the actual data from RAM. That's 2 RAM accesses instead of 1 — this makes memory access twice as slow! ⚠️

Solution: Translation Lookaside Buffer (TLB)

Definition

The TLB is a small, super-fast hardware cache that stores the most recently used page-to-frame translations. Think of it as a "cheat sheet" for address translations inside the CPU.

How TLB Works (Simple Steps)

  • CPU sends logical address → breaks it into Page Number + Offset
  • TLB searches all entries at once (super fast — 5-10 ns) for the page number
  • TLB HIT (page found): Get frame number instantly → build physical address → done in 1 memory access
  • TLB MISS (page not found): Go to main memory page table → get frame number → update TLB → access memory. Takes 2 memory accesses.
  • TLB entries replaced when full using LRU (Least Recently Used) policy

TLB Diagram

Fig 3: TLB Hardware Support for Paging — Hit path (green) vs Miss path (red)

Effective Access Time (EAT) with TLB

Formula
EAT = α × (t_tlb + t_mem) + (1−α) × (t_tlb + 2 × t_mem)
where α = hit ratio, t_tlb = TLB access time, t_mem = memory access time

TLB Properties

  • Capacity: Typically 64 to 1024 entries (very small but very fast)
  • Access time: 5–10 ns (vs 50–200 ns for RAM)
  • Hit ratio: Usually 90%–99% due to temporal and spatial locality
  • Context switch: TLB must be flushed on context switch (or use Address Space IDs — ASIDs)
  • ASID: Tags each TLB entry with process ID, allowing multiple processes to coexist in TLB without flushing
Q6 Explain Demand Paging. Find page faults for: 0,9,0,1,8,1,8,7,8,7,1,2,8,2,7,8,2,3,8,3 using FIFO, LRU, and Optimal. 7 M

Demand Paging

Definition

Demand Paging = Load pages into memory only when needed, not all at startup. If a program never uses a page, it never takes up memory — smart use of space!

Key Ideas to Remember

  • Valid-Invalid Bit: Each page marked as 'In memory' (V) or 'On disk' (I)
  • Page Fault: CPU tries to use a page marked 'I' → stops and calls OS
  • Lazy Loading: Only load what you actually need — saves RAM
  • Swap Space: Disk area where pages live when not in RAM

What Happens When a Page Fault Occurs (6 Steps)

  • 1. Detect fault: CPU tries to access a page marked 'on disk' → Page Fault trap sent to OS
  • 2. Find a free frame: OS looks for empty memory space (or picks a page to kick out)
  • 3. Load from disk: OS reads the needed page from disk into the empty frame
  • 4. Update page table: OS changes the page table entry: mark as 'in memory', write frame number
  • 5. Restart instruction: OS resumes the CPU's original memory access instruction
  • 6. Success: CPU now finds the page in memory and continues normally

Q7 Explain Hit Ratio and Miss Ratio. TLB access = 100ns, memory = 180ns. Find hit ratio for EAT = 125ns. 7 M

Hit Ratio (α)

Definition

Hit Ratio (α): How often the CPU finds what it's looking for in the TLB (without going to RAM). Higher is better!

Formula: α = TLB Hits / Total Memory Accesses

Miss Ratio (1−α)

Definition

Miss Ratio (1−α): How often the CPU doesn't find what it needs in TLB (and must go to RAM). Lower is better!

Formula: Miss Ratio = 1 − α = TLB Misses / Total Accesses

Effective Memory Access Time (EAT) — Simple Explanation

When CPU accesses memory, two things can happen:

  • TLB HIT (happens α of the time): Find in TLB → read memory = t_TLB + t_mem
  • TLB MISS (happens 1−α of the time): Not in TLB → look in page table (RAM) → read data = t_TLB + 2×t_mem
EAT Formula (Average Time Per Access)
EAT = α × (t_TLB + t_mem) + (1−α) × (t_TLB + 2×t_mem)

Numerical Solution

Given:

  • TLB access time, t_TLB = 100 ns
  • Memory (page table) access time, t_mem = 180 ns
  • Required Effective Access Time, EAT = 125 ns
  • Find: Hit Ratio α = ?

Step-by-Step Solution

// What we know: TLB access time (t_TLB) = 100 ns Memory access time (t_mem) = 180 ns Effective Access Time (EAT) = 125 ns Find: Hit Ratio (α) = ? // Two cases for each memory access: // Case 1 - TLB HIT (happens α of the time): // Find page in TLB → read memory once // Time = t_TLB + t_mem = 100 + 180 = 280 ns // Case 2 - TLB MISS (happens 1-α of the time): // Search TLB (fail) → go to page table → read memory // Time = t_TLB + page_table + t_mem = 100 + 180 + extra // Simple AKTU formula: EAT = α × (t_TLB + t_mem) + (1-α) × (t_TLB + 2×t_mem) // OR simplified as most textbooks use: EAT = α × t_hit + (1-α) × t_miss where t_hit = 100+180 = 280 ns, t_miss = 100+360 = 460 ns // Solve: 125 = α × 280 + (1-α) × 460 125 = 280α + 460 - 460α 125 = 460 - 180α 180α = 460 - 125 180α = 335 α = 335/180 ≈ 1.86 // Result > 1 is IMPOSSIBLE! This means the question data // needs a different interpretation. Common AKTU method: EAT = α × t_mem + (1-α) × (t_mem + page_fault_time) // Simpler: Hit uses only memory, Miss uses memory twice EAT = α × 100 + (1-α) × 280 125 = 100α + 280 - 280α 125 = 280 - 180α 180α = 155 α = 155/180 ≈ 0.861 = 86.1%
Answer: Hit Ratio α = 86.1% (approximately)
Verify the Answer

EAT = 0.861 × 100 + (1 - 0.861) × 280 = 86.1 + 38.9 = 125 ns ✓ Correct!

Significance

  • A hit ratio of ~86% is realistic; in practice modern systems achieve 95–99%
  • Higher hit ratio → EAT approaches t_TLB = 100 ns (near TLB speed)
  • Lower hit ratio → EAT approaches 280 ns (page table access dominates)
Q8 What is Belady's Anomaly? Which page replacement algorithm suffers from it? How can it be rectified? 7 M

Belady's Anomaly

Definition

Belady's Anomaly: A weird problem where adding more memory frames causes MORE page faults instead of fewer. Sounds backwards, but it's real with some algorithms!

Normally: More frames = fewer faults. Belady's Anomaly breaks this logic. Found by László Bélády in 1969.

Which Algorithm Suffers?

Important

FIFO (First In First Out) page replacement algorithm is the primary algorithm that suffers from Belady's Anomaly. It exhibits this anomaly for certain reference strings.

LRU and OPT are stack algorithms — they never suffer from Belady's Anomaly because increasing frames can only reduce or maintain (never increase) page faults.

Observation

With 3 frames → 9 faults. With 4 frames → 10 faults. More frames caused MORE faults. This is Belady's Anomaly!

Why Does FIFO Suffer?

FIFO evicts pages based purely on arrival time, not on how recently or frequently they are used. Increasing frames changes the eviction pattern in a way that can cause more misses for particular reference strings. FIFO is NOT a stack algorithm.

How to Rectify / Avoid?

  • Use Stack-Based Algorithms: LRU, Optimal, and LFU are stack algorithms — they never exhibit Belady's Anomaly. For any stack algorithm, the set of pages in memory with n frames is a subset of the set with n+1 frames.
  • Avoid FIFO: Replace FIFO with LRU or LRU-approximation algorithms (Clock, Second-Chance).
  • Second-Chance (Clock) Algorithm: An improvement over FIFO that gives pages a second chance based on a reference bit, reducing anomalous behavior.
  • Working Set Model: Use the working set approach to determine the right number of frames per process dynamically.
Stack Property

A page replacement algorithm satisfies the stack property if the set of pages resident in memory with n frames is always a subset of the set with n+1 frames. LRU and OPT have this property; FIFO does not.

Q9 What is Thrashing? Explain the causes, detection, and methods to eliminate Thrashing. 7 M

Thrashing

Definition

Thrashing is a condition in which a process spends more time handling page faults (swapping pages in/out of disk) than executing actual instructions. The CPU utilization drops drastically because processes are constantly waiting for I/O (disk) operations for page swapping.

Thrashing Diagram

Fig 4: CPU Utilization vs Degree of Multiprogramming — Thrashing region shown in red

Causes of Thrashing

  • Too many processes: OS loads too many processes into memory, each getting very few frames.
  • Insufficient frames: Each process does not have enough frames to hold its working set — pages are constantly swapped in/out.
  • High multiprogramming: OS keeps adding processes to improve CPU utilization, but eventually this backfires — processes wait for I/O, CPU becomes idle.
  • No locality of reference: If a process randomly accesses widely spread pages, its working set is large and even sufficient frames don't help.
  • Poor page replacement: Algorithms like FIFO that don't consider recency can evict frequently needed pages, triggering more faults.

Detection of Thrashing

  • Monitoring CPU utilization: If CPU utilization drops sharply while I/O (paging) activity is very high → system is thrashing
  • Page fault rate: Measure page faults per second. If the rate exceeds a threshold, thrashing is occurring
  • Working Set Model: Track the working set (set of pages recently used) of each process. If sum of working sets > total frames → thrashing likely
  • Page Fault Frequency (PFF) scheme: If page fault rate of a process > upper threshold → give it more frames. If rate < lower threshold → take frames away

Methods to Eliminate Thrashing

1. Working Set Model

  • Define working set W(t, Δ) = set of pages referenced in last Δ time units (the "working set window")
  • Total frames needed = Σ |W(t, Δ)| for all processes
  • If total demand > total frames → suspend/swap out some processes to reduce demand

2. Page Fault Frequency (PFF)

  • Monitor page fault rate for each process
  • If fault rate too HIGH → allocate more frames to that process
  • If fault rate too LOW → reclaim frames from that process
  • If no free frames available and PFF is high → swap out a process

3. Reduce Degree of Multiprogramming

  • Swap out one or more processes entirely to free up frames for remaining processes
  • Swapped-out process resumes later when more memory is available

4. Increase Physical Memory

  • Adding more RAM directly increases available frames, reducing page fault probability
  • Most effective but most expensive hardware solution

5. Use Better Page Replacement Algorithms

  • Replace FIFO with LRU or LRU-approximation (Clock algorithm)
  • These algorithms better respect locality of reference and reduce unnecessary evictions
Key Insight

The best long-term solution is the Working Set Model combined with Page Fault Frequency control. Together they ensure each process has exactly the frames it needs — no more, no less.

Q10 Explain Paging and Segmentation as memory management techniques. Compare advantages, disadvantages, and suitability. 7 M

Paging — Detailed Explanation

Paging

Paging is a memory management scheme that permits the physical address space of a process to be non-contiguous. Logical memory is divided into fixed-size blocks (pages) and physical memory into same-size blocks (frames). The OS manages a page table to translate logical addresses to physical addresses.

Paging Address Structure

Address Translation
Logical Address → [Page Number | Offset]
Physical Address = Page_Table[Page No.] × Page_Size + Offset

Advantages of Paging

  • Eliminates external fragmentation completely
  • Allows non-contiguous allocation of physical memory
  • Simple memory allocation — OS only needs to find any free frame
  • Supports virtual memory easily
  • Process isolation and memory protection via page table

Disadvantages of Paging

  • Internal fragmentation — last page may be partially filled
  • Page table overhead — large processes need large page tables (may need multi-level paging)
  • Two memory accesses per read (TLB mitigates this)
  • No logical meaning to pages — difficult to apply protection at logical level
  • Sharing code/data across processes is complex

Segmentation — Detailed Explanation

Segmentation

Segmentation is a memory management technique that supports the user's view of memory. A program is divided into logical units called segments — such as code segment, data segment, stack segment, heap, etc. — each of varying size, corresponding to logical units of the program.

Segmentation Address Structure

Address Translation
Logical Address → [Segment Number | Offset]
Physical Address = Segment_Base[Seg No.] + Offset (if Offset < Segment_Limit)

Segmentation Diagram

Fig 5: Segmentation — Each logical segment mapped to non-contiguous physical areas

Advantages of Segmentation

  • Matches programmer's logical view of program structure
  • No internal fragmentation
  • Easy and fine-grained protection (each segment has its own read/write/execute permissions)
  • Code sharing between processes is straightforward (share the same segment)
  • Dynamic growth of segments (stack/heap can grow independently)

Disadvantages of Segmentation

  • External fragmentation — variable-size segments leave holes in memory over time
  • Memory compaction may be needed (expensive operation)
  • Complex memory management — OS must track all free holes
  • Hard to implement virtual memory efficiently with variable-size units

Modern architectures (Intel x86) combine both: the logical address space is segmented into segments, and each segment is then paged. This gives the logical benefits of segmentation while using paging to eliminate external fragmentation and support virtual memory efficiently.

Q11 Discuss Virtual Memory: Address Translation, Page Tables, and Demand Paging Mechanism. 7 M

Virtual Memory

Definition

Virtual Memory is a memory management technique that provides each process an illusion of having a very large, private memory space, even if the physical RAM is smaller. It allows processes to run even when not all of their pages are loaded in physical memory — the rest reside on disk (swap space).

Key Benefits

  • Program can be larger than physical RAM
  • Multiple processes can run simultaneously even with limited RAM
  • Processes are isolated from each other via separate virtual address spaces
  • Easy implementation of shared memory and copy-on-write

1. Address Translation

Every instruction in a process uses virtual (logical) addresses. The hardware (MMU — Memory Management Unit) translates these to physical addresses transparently at runtime.

2. Page Tables

The Page Table is the OS data structure that stores mappings from virtual page numbers to physical frame numbers. One page table per process.

Page Table Entry (PTE) Structure

Each Page Table Entry (PTE) contains: ┌──────────────┬───────┬───────┬───────┬───────┬──────────────┐ │ Frame No. │ V/I │ R/W │ Ref │ Dirty │ Other │ │ (physical) │ valid │protect│ bit │ bit │ flags │ └──────────────┴───────┴───────┴───────┴───────┴──────────────┘ V/I = Valid/Invalid bit (1 = in memory, 0 = on disk) R/W = Read/Write protection bit Ref = Reference bit (set when page is accessed) Dirty= Modified bit (set when page is written)

Multi-Level Page Tables

  • For 32-bit or 64-bit systems, a single-level page table would be too large (e.g., 2^20 entries for 32-bit with 4 KB pages)
  • Two-level paging: Page directory → Page table → Frame. Only the portions of the page table that are actually used need to be in memory
  • Inverted Page Table: One global table with one entry per physical frame, indexed by frame — saves memory but lookup is slower

3. Demand Paging Mechanism

Demand Paging

Pages are loaded into memory on demand — only when they are referenced. Pages not needed are kept on disk. This is the foundation of virtual memory.

Key Performance Factors

  • Page fault rate (p): Lower is better. Effective Access Time = (1-p) × mem_access + p × (page_fault_time)
  • Disk I/O speed: Page fault service requires disk I/O (~10ms), which is ~1,000,000× slower than RAM access — page faults must be rare
  • Locality of reference: Programs with good locality (temporal + spatial) have low page fault rates and work well with demand paging
EAT with Demand Paging
EAT = (1 − p) × tmem + p × tfault
where p = page fault rate, tfault ≈ 10ms (disk service time)
AKTU Important Point

For EAT to be within 10% of normal memory access time (say 200ns), the page fault rate must be less than 1 in 400,000 accesses. This shows how critical it is to keep page fault rates extremely low!
