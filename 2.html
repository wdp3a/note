1a
Why is Java platform-independent?
2 marks

Java follows the Write Once, Run Anywhere (WORA) principle. The Java compiler converts source code (.java) into bytecode (.class), which is not tied to any specific operating system or processor.

The Java Virtual Machine (JVM), installed on every target platform (Windows, Linux, macOS), reads this same bytecode and translates it into platform-specific machine code at runtime. Because different JVMs exist for different platforms, the same bytecode executes everywhere without recompilation.

.java → javac (compiler) → .class (Bytecode — platform neutral) ↓ JVM on Windows / JVM on Linux / JVM on macOS ↓ Native Machine Code (platform-specific)
💡 Concept Booster

Think of bytecode as a universal recipe and the JVM as a local chef who adapts it to their own kitchen (OS). The recipe never changes, but every chef knows how to cook it. That's why Java is platform-independent — the recipe (bytecode) is universal; the cooking (execution) is local.

1b
What is the role of a constructor in a Java class?
2 marks

A constructor is a special block of code used to initialize an object when it is created using the new keyword. It has the same name as the class and has no return type (not even void).

  • Called automatically at object creation time.
  • Sets initial values for object fields.
  • Java provides a default (no-arg) constructor if none is defined.
  • Constructor overloading allows multiple constructors with different parameters.
class Student {
    String name; int age;
    Student(String n, int a) { name = n; age = a; } // parameterized constructor
    Student() { name = "Unknown"; }                   // default constructor
}
💡 Concept Booster

A constructor is like a factory setup procedure — the moment a new car comes off the assembly line (object created), the factory automatically installs the engine and sets the color (initializes fields). You don't call it manually; it fires the instant the object is born.

1c
What is the purpose of the finally block in Java exception handling?
2 marks

The finally block contains code that is always executed, regardless of whether an exception is thrown, caught, or not thrown at all.

  • Executes after try and catch complete.
  • Used for cleanup operations: closing files, releasing database connections, freeing resources.
  • Only skipped if System.exit() is called or the JVM crashes.
try { /* risky code */ }
catch (Exception e) { /* handle */ }
finally { System.out.println("Always runs — close resources here"); }
💡 Concept Booster

finally is like a security guard at an exit — whether the event (try block) went smoothly or someone caused trouble (exception), the guard always locks up when everyone leaves. It's your guarantee that cleanup code is never skipped no matter what happens.

What is a functional interface? Give an example.
2 marks

A functional interface is an interface with exactly one abstract method (SAM — Single Abstract Method). It may have any number of default or static methods.

  • Annotated with @FunctionalInterface (optional but compiler-enforced).
  • It is the target type for lambda expressions and method references.
  • Built-in examples: Runnable, Predicate<T>, Comparator<T>, Callable<V>.
@FunctionalInterface
interface Greet {
    void sayHello(String name); // only ONE abstract method
}
// Implemented via lambda
Greet g = name -> System.out.println("Hello, " + name);
g.sayHello("AKTU"); // Output: Hello, AKTU
💡 Concept Booster

A functional interface is like a single-button remote control — it does exactly one thing. Lambda expressions are the shorthand to program that button without writing an entire class. This is Java's gateway to functional programming style.

Explain the concept of multithreading. Write a program to implement two threads printing numbers alternatively.
7 marks

Multithreading in Java

Multithreading is the ability of a program to execute multiple threads concurrently. A thread is the smallest unit of execution within a process. All threads share the same memory (heap) but have their own stack.

Benefits

  • Better CPU utilization — multiple tasks run simultaneously.
  • Responsive applications — UI stays active while background tasks run.
  • Faster execution for parallelizable problems.

Thread Lifecycle

NEW → RUNNABLE → RUNNING → WAITING/BLOCKED → TERMINATED (created) (start()) (CPU allotted) (sleep/wait/join) (run() ends)

Ways to Create Threads

  1. Extend the Thread class and override run().
  2. Implement the Runnable interface and pass to Thread.

Program: Two Threads Printing Numbers Alternatively (1–10)

public class AlternateNumbers {
    static int current = 1;
    static final int MAX = 10;
    static final Object LOCK = new Object();

    public static void main(String[] args) {

        // Thread 1 — prints odd numbers
        Thread t1 = new Thread(() -> {
            while (current <= MAX) {
                synchronized (LOCK) {
                    while (current <= MAX && current % 2 == 0) {
                        try { LOCK.wait(); }
                        catch (InterruptedException e) { Thread.currentThread().interrupt(); }
                    }
                    if (current <= MAX)
                        System.out.println("Thread-1 (Odd) : " + current++);
                    LOCK.notify();
                }
            }
        });

        // Thread 2 — prints even numbers
        Thread t2 = new Thread(() -> {
            while (current <= MAX) {
                synchronized (LOCK) {
                    while (current <= MAX && current % 2 != 0) {
                        try { LOCK.wait(); }
                        catch (InterruptedException e) { Thread.currentThread().interrupt(); }
                    }
                    if (current <= MAX)
                        System.out.println("Thread-2 (Even): " + current++);
                    LOCK.notify();
                }
            }
        });

        t1.start();
        t2.start();
    }
}

Output

Thread-1 (Odd) : 1
Thread-2 (Even): 2
Thread-1 (Odd) : 3
Thread-2 (Even): 4
Thread-1 (Odd) : 5
Thread-2 (Even): 6   ... and so on up to 10

Key Concepts Used

  • synchronized — mutual exclusion; only one thread in the block at a time.
  • wait() — releases lock and suspends thread until notified.
  • notify() — wakes one waiting thread.
💡 Concept Booster

Multithreading is like two chefs sharing a single stove — one cooks while the other waits. synchronized is the kitchen rule (only one chef at the stove). wait() says "I'm done, you go" and notify() taps the other chef's shoulder to resume. This coordination is called inter-thread communication.

What is the Stream API in Java? How does it help in functional-style operations?
7 marks

Stream API in Java

Introduced in Java 8 (java.util.stream), the Stream API enables declarative, functional-style processing of collections and data sequences. A stream is not a data structure — it does not store data; it is a pipeline of operations on a source.

Key Characteristics

  • Lazy evaluation — intermediate operations execute only when a terminal operation is called.
  • Non-destructive — does not modify the original collection.
  • Pipeline-based — operations chained one after another.
  • Supports parallelism — parallelStream() for multi-core processing.

Stream Pipeline Structure

Data Source → Intermediate Operations (lazy) → Terminal Operation (List/Array) filter · map · sorted · distinct collect · forEach · count · reduce

Common Operations

TypeMethodDescription
Intermediatefilter(pred)Keep elements matching predicate
Intermediatemap(fn)Transform each element
Intermediatesorted()Sort elements
Intermediatedistinct()Remove duplicates
Intermediatelimit(n)Truncate to first n elements
Terminalcollect()Gather results into a collection
TerminalforEach()Perform action on each element
Terminalcount()Count matching elements
Terminalreduce()Combine all elements to one value

Example Program

import java.util.*;
import java.util.stream.*;

public class StreamDemo {
    public static void main(String[] args) {
        List<Integer> nums = Arrays.asList(1,2,3,4,5,6,7,8);

        // Filter even → square → collect
        List<Integer> result = nums.stream()
            .filter(n -> n % 2 == 0)      // [2,4,6,8]
            .map(n -> n * n)              // [4,16,36,64]
            .collect(Collectors.toList()); // terminal
        System.out.println(result);         // [4, 16, 36, 64]

        // Count elements > 5
        long c = nums.stream().filter(n -> n > 5).count();
        System.out.println("Count > 5: " + c); // 3

        // Sum using reduce
        int sum = nums.stream().reduce(0, Integer::sum);
        System.out.println("Sum: " + sum); // 36
    }
}
💡 Concept Booster

The Stream API is like an assembly line. Raw materials (your list) enter one end, pass through machines (filter, map, sort), and polished products come out the other end. You describe what to do, not how to loop — that's the essence of functional programming. Less code, more clarity, easier parallelism.

ArrayList vs LinkedList

Both implement the List interface but use different internal data structures.

Internal Structure

  • ArrayList — backed by a dynamic array. Elements stored in contiguous memory. Doubles capacity when full.
  • LinkedList — backed by a doubly linked list. Each node stores data + reference to previous and next node.
ArrayList: [ 10 | 20 | 30 | 40 | 50 ] ← contiguous memory block LinkedList: [10]↔[20]↔[30]↔[40]↔[50] ← nodes scattered in memory

Performance Comparison

OperationArrayListLinkedList
Access by index (get(i))O(1) — direct indexO(n) — must traverse from head
Search (contains())O(n)O(n)
Insert / Delete at endO(1) amortizedO(1)
Insert / Delete at beginningO(n) — shifts all elementsO(1)
Insert / Delete in middleO(n) — shift requiredO(n) traversal + O(1) pointer change
Memory overheadLow — stores only dataHigher — data + 2 pointers/node
Cache performanceGood (contiguous)Poor (scattered nodes)

Feature Comparison

FeatureArrayListLinkedList
ImplementsListList, Deque, Queue
Best forFrequent reads / random accessFrequent insert / delete
Can act as Queue/DequeNoYes (addFirst(), poll())

Code Example

ArrayList<Integer> al = new ArrayList<>();
al.add(10); al.add(20); al.add(30);
System.out.println(al.get(1)); // O(1) → 20

LinkedList<Integer> ll = new LinkedList<>();
ll.addFirst(5); ll.addLast(15); // both O(1)
ll.removeFirst();                 // O(1)

When to Use Which?

  • Use ArrayList when: frequent random access, mostly read-heavy, size known upfront.
  • Use LinkedList when: frequent insertions/deletions especially at ends, using as Queue/Deque.
💡 Concept Booster

ArrayList = a numbered locker system — you go directly to locker #5 instantly (O(1)), but inserting a new locker in the middle shifts everyone (O(n)). LinkedList = a treasure hunt chain — inserting a new clue is instant (just change pointers), but finding clue #50 means following all 49 before it. Choose based on your dominant operation: read → ArrayList, write → LinkedList.

Write a Java program to take user input and display the reverse of a string.
7 marks

String Reversal in Java

Strings in Java are immutable, so reversal creates a new string. Three methods are shown.

Method 1: Using StringBuilder (Recommended)

import java.util.Scanner;

public class ReverseString {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        System.out.print("Enter a string: ");
        String input = sc.nextLine();

        // Method 1: StringBuilder.reverse()
        String rev1 = new StringBuilder(input).reverse().toString();
        System.out.println("Reversed (StringBuilder): " + rev1);

        // Method 2: Loop from end to start
        StringBuilder sb = new StringBuilder();
        for (int i = input.length() - 1; i >= 0; i--)
            sb.append(input.charAt(i));
        System.out.println("Reversed (Loop)        : " + sb);

        // Method 3: Two-pointer swap on char array
        char[] chars = input.toCharArray();
        int left = 0, right = chars.length - 1;
        while (left < right) {
            char temp = chars[left];
            chars[left++] = chars[right];
            chars[right--] = temp;
        }
        System.out.println("Reversed (Char Array)  : " + new String(chars));

        sc.close();
    }
}

Sample Output

Enter a string: Hello AKTU
Reversed (StringBuilder): UTKA olleH
Reversed (Loop)        : UTKA olleH
Reversed (Char Array)  : UTKA olleH
💡 Concept Booster

Since strings are immutable in Java, reversal always produces a new string. StringBuilder is mutable and has a built-in reverse() — the easiest route. The two-pointer swap is the classic interview technique: move inward from both ends swapping characters, like zipping a bag from both sides simultaneously.

Explain the concept of Java Virtual Machine and Java Runtime Environment.
7 marks

Java Virtual Machine (JVM)

The JVM is an abstract computing engine that provides the runtime environment to execute Java bytecode. It is the key component that enables platform independence.

Responsibilities of JVM

  • Class Loading — loads .class bytecode files via the ClassLoader.
  • Bytecode Verification — checks for security violations before execution.
  • Execution — interprets bytecode line-by-line OR uses the JIT (Just-In-Time) compiler to convert hot code paths to native machine code for speed.
  • Memory Management — manages Heap, Stack, Method Area, and PC Register.
  • Garbage Collection — automatically frees unreferenced objects from heap memory.

JVM Architecture

Java Runtime Environment (JRE)

The JRE is a software package that provides everything needed to run Java applications. It is a superset of the JVM.

JRE Contains

  • JVM — for bytecode execution.
  • Java Class Libraries — pre-built API packages (java.lang, java.util, java.io, etc.).
  • Supporting files — property files, configuration data.

The JRE is for end users who only need to run Java apps, not develop them.

Write a Java program to handle multiple exceptions using try-catch-finally.
7 marks

Exception Handling with try-catch-finally

Exception handling prevents abnormal program termination due to runtime errors. Java uses a hierarchy of Exception classes.

Exception Hierarchy (Partial)

Throwable ├── Error (JVM errors — OutOfMemoryError, StackOverflowError) └── Exception ├── Checked (must be handled — IOException, SQLException) └── RuntimeException (unchecked) ├── ArithmeticException ├── NullPointerException ├── ArrayIndexOutOfBoundsException └── NumberFormatException

Complete Program

import java.util.Scanner;

public class MultiExceptionDemo {
    public static void main(String[] args) {
        Scanner sc = new Scanner(System.in);
        int[] arr = {10, 20, 30};

        try {
            // Scenario 1: ArrayIndexOutOfBoundsException
            System.out.print("Enter index (0-2): ");
            int idx = sc.nextInt();
            System.out.println("Element: " + arr[idx]);

            // Scenario 2: ArithmeticException
            System.out.print("Enter divisor: ");
            int div = sc.nextInt();
            System.out.println("100 / divisor = " + (100 / div));

            // Scenario 3: NumberFormatException
            String s = "xyz";
            int num = Integer.parseInt(s); // throws NFE
            System.out.println("Parsed: " + num);

        } catch (ArrayIndexOutOfBoundsException e) {
            System.out.println("[Caught] Array index out of bounds: " + e.getMessage());

        } catch (ArithmeticException e) {
            System.out.println("[Caught] Arithmetic error: " + e.getMessage());

        } catch (NumberFormatException e) {
            System.out.println("[Caught] Number format error: " + e.getMessage());

        } catch (Exception e) {
            // Generic fallback — MUST be LAST
            System.out.println("[Caught] Unexpected: " + e.getMessage());

        } finally {
            System.out.println("[Finally] Closing scanner — always runs.");
            sc.close();
        }
    }
}

Sample Outputs

Case 1 — index = 5:
[Caught] Array index out of bounds: Index 5 out of bounds for length 3
[Finally] Closing scanner — always runs.

Case 2 — divisor = 0:
[Caught] Arithmetic error: / by zero
[Finally] Closing scanner — always runs.

Rules for Multiple Catch Blocks

  • More specific exceptions must come before more general ones.
  • Exception (parent of all checked exceptions) must be the last catch.
  • Java 7+: Multiple exceptions in one catch: catch (AE | NFE e).
💡 Concept Booster

Exception handling is like safety nets under a tightrope walker. The try block is the walk; each catch is a net at a specific height (most specific first, generic last); finally is the cleanup crew who tidies up regardless. Java matches the thrown exception top-to-bottom — put Exception last or it shadows all specific catches above.

4b
Write a Java program that creates two threads — one to print even numbers and the other for odd numbers.
7 marks

Two Threads: Even and Odd Number Printing

public class EvenOddThreads {
    static volatile int N = 1;   // shared counter
    static final int MAX = 10;
    static final Object LOCK = new Object();

    // Thread to print ODD numbers
    static class OddThread extends Thread {
        @Override
        public void run() {
            while (N <= MAX) {
                synchronized (LOCK) {
                    // wait if current number is even
                    while (N <= MAX && N % 2 == 0) {
                        try { LOCK.wait(); }
                        catch (InterruptedException e) { return; }
                    }
                    if (N <= MAX) {
                        System.out.println("ODD  thread → " + N++);
                        LOCK.notify();
                    }
                }
            }
        }
    }

    // Thread to print EVEN numbers
    static class EvenThread extends Thread {
        @Override
        public void run() {
            while (N <= MAX) {
                synchronized (LOCK) {
                    // wait if current number is odd
                    while (N <= MAX && N % 2 != 0) {
                        try { LOCK.wait(); }
                        catch (InterruptedException e) { return; }
                    }
                    if (N <= MAX) {
                        System.out.println("EVEN thread → " + N++);
                        LOCK.notify();
                    }
                }
            }
        }
    }

    public static void main(String[] args) {
        new OddThread().start();
        new EvenThread().start();
    }
}

Output

ODD  thread → 1
EVEN thread → 2
ODD  thread → 3
EVEN thread → 4
ODD  thread → 5
EVEN thread → 6
ODD  thread → 7
EVEN thread → 8
ODD  thread → 9
EVEN thread → 10

Explanation

  • synchronized(LOCK) — only one thread enters the block at a time.
  • wait() — a thread releases the lock and suspends itself when it's not its turn.
  • notify() — after printing its number, a thread wakes the other one.
  • volatile — ensures the shared counter N is always read from main memory.
💡 Concept Booster

Two threads sharing one counter is like two musicians sharing a single microphone — one sings while the other waits, then they swap. synchronized is the "only one at the mic" rule; wait() is stepping back; notify() is tapping the other's shoulder. This pattern is called inter-thread communication.

import java.util.*;

public class LambdaDemo {
    public static void main(String[] args) {

        // 1. Custom functional interface with lambda
        @FunctionalInterface
        interface MathOp { int operate(int a, int b); }
        MathOp add  = (a, b) -> a + b;
        MathOp mul  = (a, b) -> a * b;
        System.out.println(add.operate(5,3)); // 8
        System.out.println(mul.operate(5,3)); // 15

        // 2. Predicate
        Predicate<Integer> isEven = n -> n % 2 == 0;
        System.out.println(isEven.test(4));  // true
        System.out.println(isEven.test(7));  // false

        // 3. Function
        Function<String, String> upper = s -> s.toUpperCase();
        System.out.println(upper.apply("aktu")); // AKTU

        // 4. Consumer
        Consumer<String> printer = msg -> System.out.println(">> " + msg);
        printer.accept("Hello World"); // >> Hello World

        // 5. Supplier
        Supplier<Double> pi = () -> 3.14159;
        System.out.println(pi.get()); // 3.14159

        // 6. With Collections — sort using lambda
        List<String> names = Arrays.asList("Charlie","Alice","Bob");
        names.sort((a, b) -> a.compareTo(b)); // alphabetical sort
        names.forEach(n -> System.out.println(n)); // Alice, Bob, Charlie
    }
}

Lambda vs Anonymous Class

// Anonymous class (old style)
Runnable r1 = new Runnable() {
    public void run() { System.out.println("Old"); }
};

// Lambda (concise)
Runnable r2 = () -> System.out.println("New");
💡 Concept Booster

Lambda expressions are like sticky notes for behaviour — instead of writing a whole class to do one thing, you jot it on one line and pass it around. Functional interfaces define the shape of the slot; lambdas fill that slot with actual behaviour. Together they unlock functional programming in Java — cleaner, shorter, and more expressive code.

Annotations in Java

Annotations are metadata tags prefixed with @, applied to code elements (classes, methods, fields, parameters, local variables). They do not change program logic directly but provide information to compilers, tools, and frameworks.

Roles of Annotations

  • Compiler instructions — @Override catches incorrect overrides at compile time; @SuppressWarnings suppresses compiler warnings.
  • Compile-time / build-time processing — used by tools like Lombok, MapStruct for code generation.
  • Runtime processing — Spring, Hibernate, JUnit read annotations via Reflection API to inject beans, map tables, run tests.
  • Documentation — @Deprecated marks outdated APIs in Javadoc.

Built-in Standard Annotations

AnnotationPurpose
@OverrideEnsures the method overrides a parent class method; compile error if it doesn't.
@DeprecatedMarks code as outdated — compiler generates a warning when used.
@SuppressWarnings("...")Tells compiler to suppress specified warnings.
@FunctionalInterfaceValidates that interface has exactly one abstract method.
@SafeVarargsSuppresses unchecked varargs heap pollution warnings.

Meta-Annotations (Annotations on Annotations)

Meta-AnnotationMeaning
@RetentionLifetime: SOURCE (discarded) / CLASS (in .class) / RUNTIME (available via reflection)
@TargetWhere it applies: METHOD, FIELD, TYPE, PARAMETER, LOCAL_VARIABLE, etc.
@DocumentedInclude annotation in Javadoc output.
@InheritedSubclasses automatically inherit the annotation.
@RepeatableAllows applying the same annotation multiple times.

Creating a Custom Annotation

import java.lang.annotation.*;

@Retention(RetentionPolicy.RUNTIME)
@Target(ElementType.METHOD)
public @interface LogExecutionTime {
    String value() default "method";
}

class Service {
    @LogExecutionTime(value = "fetchData")
    public void fetchData() { System.out.println("Fetching..."); }
}

Type Annotations (Java 8+)

Type annotations can be applied to any use of a type, not just declarations. They enable pluggable type-checking frameworks like the Checker Framework to verify @NonNull, @Readonly, etc. at compile time.

Where Type Annotations Can Appear

// Variable declaration
@NonNull String name = "AKTU";

// Generic type argument
List<@NonNull String> items;

// Method parameter

// Return type

// instanceof check
if (obj instanceof @ReadOnly List<?>) { }

// object creation
new @Interned MyObject()
💡 Concept Booster

Annotations are like labels on a parcel — "Fragile", "This side up". The parcel (code) doesn't change but the delivery system (compiler/framework) reads the label and acts accordingly. Type annotations make those labels even more precise — you can now tag exactly which type usage must be non-null or immutable, catching bugs before the program even runs.

HashMap in Java

HashMap<K,V> stores data as key-value pairs. It uses hashing to provide average O(1) time for get() and put(). It does not maintain insertion order and allows one null key.

Internal Working

key.hashCode() → bucket index → store Node(key, value) On collision (same bucket): chained LinkedList (Java 7) or TreeNode (Java 8+)

Complete Program

import java.util.*;

public class HashMapDemo {
    public static void main(String[] args) {

        HashMap<String, Integer> marks = new HashMap<>();
        marks.put("Alice",   85);
        marks.put("Bob",     92);
        marks.put("Charlie", 78);
        marks.put("Diana",   95);
        marks.put("Eve",     88);

        System.out.println("Size: " + marks.size());       // 5
        System.out.println("Alice's marks: " + marks.get("Alice")); // 85
        System.out.println("Has Bob: " + marks.containsKey("Bob")); // true

        // Method 1: entrySet() — best for key + value together
        System.out.println("\n=== entrySet() ===");
        for (Map.Entry<String, Integer> entry : marks.entrySet()) {
            System.out.printf("%-10s : %d%n", entry.getKey(), entry.getValue());
        }

        // Method 2: keySet() — iterate keys only
        System.out.println("\n=== keySet() ===");
        for (String key : marks.keySet())
            System.out.println("Key: " + key + ", Value: " + marks.get(key));

        // Method 3: values() — iterate values only
        System.out.println("\n=== values() ===");
        for (int v : marks.values()) System.out.print(v + " ");

        // Method 4: Java 8 forEach with lambda
        System.out.println("\n\n=== Lambda forEach() ===");
        marks.forEach((k, v) ->
            System.out.println(k + " scored " + v + " marks"));

        // Update and remove
        marks.put("Alice", 90);       // update
        marks.remove("Charlie");      // delete
        marks.putIfAbsent("Frank", 70); // add only if key absent
        System.out.println("\nAfter updates: " + marks);
    }
}

Key HashMap Methods Summary

MethodDescriptionTime Complexity
put(k, v)Insert or update key-value pairO(1) avg
get(k)Retrieve value by keyO(1) avg
remove(k)Delete entry by keyO(1) avg
containsKey(k)Check key existenceO(1) avg
keySet()Set of all keysO(n)
entrySet()Set of key-value Entry objectsO(n)
putIfAbsent(k, v)Insert only if key absentO(1) avg
💡 Concept Booster

HashMap is like a phone book with instant lookup — you go straight to "Alice" without scanning every page, because hashing converts the name into a page number (bucket index). Always use entrySet() for iteration when you need both key and value — it's more efficient than calling get() inside a keySet() loop (avoids a second lookup per key).

Java Collection Framework

The Java Collections Framework (JCF) provides a unified architecture (java.util package) for storing, retrieving, and manipulating groups of objects. It consists of interfaces, implementations, and algorithms.

Collection Framework Hierarchy

java.lang.Iterable └── java.util.Collection ├── List (ordered, duplicates allowed) │ ├── ArrayList │ ├── LinkedList │ └── Vector → Stack │ ├── Set (unique elements) │ ├── HashSet │ ├── LinkedHashSet │ └── TreeSet (sorted) │ └── Queue (FIFO ordering) ├── PriorityQueue └── Deque (interface) └── ArrayDeque / LinkedList Map (SEPARATE hierarchy — NOT extends Collection) ├── HashMap ├── LinkedHashMap (insertion order) ├── TreeMap (sorted by key) └── Hashtable (legacy, synchronized)

List vs Set vs Map — Comparison

FeatureListSetMap
OrderingMaintains insertion orderNo order (except LinkedHashSet, TreeSet)No order (except LinkedHashMap, TreeMap)
DuplicatesAllowedNot allowedKeys unique; values can repeat
Null elementsMultiple nullsOne null (HashSet)One null key (HashMap)
Access methodBy index: get(i)Iterator / stream onlyBy key: get(key)
InterfaceList<E>Set<E>Map<K,V>
ImplementationsArrayList, LinkedListHashSet, TreeSetHashMap, TreeMap
Use caseOrdered collection, duplicates OKUnique items, membership testKey-value lookups

Code Examples

// List — allows duplicates, preserves order
List<String> list = new ArrayList<>();
list.add("Java"); list.add("Java"); // [Java, Java]
System.out.println(list.get(0));     // Java

// Set — rejects duplicates automatically
Set<String> set = new HashSet<>();
set.add("Java"); set.add("Java");
System.out.println(set.size());   // 1 (duplicate ignored)

// Map — key-value pairs, keys unique
Map<String, Integer> map = new HashMap<>();
map.put("Alice", 90); map.put("Bob", 85);
System.out.println(map.get("Alice")); // 90
💡 Concept Booster

List = a notebook (write the same word twice, items in order). Set = a whiteboard (each unique word appears once, order not guaranteed). Map = a contact book (each unique name maps to one number). Rule of thumb: need order + duplicates → List; need uniqueness → Set; need key-based lookup → Map.

Dependency Injection (DI) in Spring

Dependency Injection is a design pattern where an object receives its dependencies from an external source (the Spring IoC container) rather than creating them itself. This promotes loose coupling, testability, and maintainability.

Types of Dependency Injection

TypeMechanismRecommended For
Constructor InjectionDependencies passed as constructor argumentsMandatory dependencies (preferred)
Setter InjectionDependencies set via setter methodsOptional dependencies
Field Injection@Autowired directly on the fieldSimple cases (not ideal for unit testing)
// Constructor Injection (Best Practice)
@Service
public class OrderService {
    private final OrderRepo repo;
    @Autowired
    public OrderService(OrderRepo repo) { this.repo = repo; }
}

private OrderRepo repo;
@Autowired public void setRepo(OrderRepo r) { this.repo = r; }

// Field Injection
@Autowired private OrderRepo repo;

1. Model

public class Student {
    private int id;
    private String name;
    private int marks;
    public Student(int id, String name, int marks) {
        this.id = id; this.name = name; this.marks = marks;
    }
    // getters and setters ...
    public int    getId()    { return id; }
    public String getName()  { return name; }

2. REST Controller

@RestController
@RequestMapping("/students")
public class StudentController {
    private final List<Student> db = new ArrayList<>();
    private int nextId = 1;

    // CREATE — POST /students
    @PostMapping
    public Student create(@RequestBody Student s) {
        Student ns = new Student(nextId++, s.getName(), s.getMarks());
        db.add(ns); return ns;
    }
    // READ ALL — GET /students
    @GetMapping
    public List<Student> getAll() { return db; }

    // READ ONE — GET /students/{id}
    @GetMapping("/{id}")
    public Student getById(@PathVariable int id) {
        return db.stream().filter(s -> s.getId() == id)
                 .findFirst().orElse(null);
    }
    // UPDATE — PUT /students/{id}
    @PutMapping("/{id}")
    public Student update(@PathVariable int id, @RequestBody Student upd) {
        for (Student s : db) {
            if (s.getId() == id) {
                s.setName(upd.getName()); s.setMarks(upd.getMarks());
                return s;
            }
        }
        return null;
    }
    // DELETE — DELETE /students/{id}
    @DeleteMapping("/{id}")
    public String delete(@PathVariable int id) {
        db.removeIf(s -> s.getId() == id);
        return "Deleted id: " + id;
    }
}
